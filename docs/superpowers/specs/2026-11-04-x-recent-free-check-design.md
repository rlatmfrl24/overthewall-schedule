# 무료 X 최근48시간 확인 설계 — 2026-11-04

상태: 사용자가 `최근48시간 무료 확인 + 공식12시간 대조` 방향과 아래 최대4페이지 확인의 완료 의미를 승인하고 구현·검증·운영 반영을 요청했다.

## 목적과 확인된 문제

무료 수집이 최근 글을 지속적으로 확보하고, 공식 X가 기존12시간 대조로 누락을 보완한다. 기존 예산·웹훅 Disabled·강제 유료 호출 보류·Play/AI 중지를 유지한다.

현재8개 cursor는 정기 실행마다 진행했다. 실제 다음 페이지8개를 무료 조회했으며 모두200·서로 다른 다음 cursor를 반환했다. 4계정은 수집 시작일 이전 구간이었다. 종료 후 다음 주기에 전체 이력을 다시 여는 코드와, 기존 tail을 이어 읽을 때 새 head의 후속 구간을 버리는 코드를 확인했다.

FxEmbed profile JSON은 기간을 제한하는 pagination 계약을 제공하지 않는다. `since`는 첫 페이지의204 판정이며, 빈 결과도 변환 실패/삭제 항목이 제거된 결과일 수 있다. 기간 조건 검색과 단순 계정 검색은 모두 실제404여서 대체 기본 경로로 채택하지 않는다.

## 제안한 완료 의미

**무료 수집의 작업 단위를 최근48시간을 대상으로 하는 최대4페이지 스냅샷 확인으로 정한다.** 한 번의 확인이 끝났다는 의미이며,48시간의 모든 글을 빠짐없이 읽었다는 증명은 아니다. 공식12시간 독립 대조가 누락 확인의 권위다. 예산·공급자 장애에 의한 복구 지연은 그대로 표시한다.

- 같은 실행 안에서 head→다음 페이지 순으로 최대4페이지를 정상 저장한다. 오래된 글 하나·같은 head·빈 결과만으로 조기에 완료하지 않는다.
- 첫 페이지를 정상 저장할 때 확인 범위의 종료 시각을 고정한다. 저장 대상은 `max(수집 시작 시각, 종료 시각-48시간)`부터 종료 시각까지다.
- 실제 다음 cursor가 없거나4페이지를 모두 저장하면 이번 스냅샷 확인을 완료한다. 4페이지 뒤 cursor가 남으면 `범위 제한`을 명시하고 공식 대조 상태와 함께 표시한다.
- HTTP/검증/저장/lease 실패는 실제 실패 또는 pending으로 보존한다. 성공하지 않은 페이지를 소비하지 않는다.
- 실패 후 재개는 같은 고정 범위·마지막 durable cursor·처리한 페이지 수를 사용한다. 별도 최신 head 확인을 포함해 실행당 타임라인4페이지 한도를 지킨다. 최신 head 확인으로 기존 pending을 덮지 않는다. 최초 계정 ID 확인 요청은 기존처럼 별도이며 현재8계정은 이미 확인된 ID가 있다.
- 완료된 확인의 이후 실행은 새로운 최근 범위를 확인한다. 이전 장기 cursor를 이어 읽지 않는다.48시간 겹침의 재수신은 기존 no-op 저장 판정을 사용한다.

이 기준은 기존 설계의 ‘공급자 전체 이력의 종단까지 탐색’ 의미를 교체한다.48시간 내 글이4페이지를 넘거나 공급자가 응답에서 글을 생략하면 무료 확인만으로 전량 발견하지 못할 수 있다. 이를 `전체 탐색 완료`로 표시하지 않는다.

## 진행 상태와 기존8개 cursor

`x_fx_sources`에 additive 진행 필드를 둔다: 현재 확인 범위 종료 시각, durable 페이지 수, 마지막 완료 범위 종료 시각, 마지막 상한 도달 여부, 은퇴한 기존 탐색 정보(JSON: 원래 cursor·이전 완료 시각·전환 시각·사유).

배포/migration은 기존 cursor·운영 설정을 변경하지 않는다. 새 수집기의 정상 실행에서 첫 페이지가 durable하게 저장될 때 이전 장기 탐색을 은퇴 정보로 보존하고 최근 확인으로 이관한다. 기존8개 cursor를 전체 이력 종단까지 소진했다고 보고하지 않는다. 이관 후의 실제 pending과 보존된 이전 cursor를 구분한다.

커서와 페이지 수·완료 정보는 기존 account lease/공개 정책 fence를 통과한 ACK로 함께 기록한다. 원래 본문·첨부·관계 권위/CAS·숨김/삭제/redaction·보관·허용 멤버·공식 cursor/clock은 유지한다. 새로운 D1 관측 쓰기·의존성·daemon·Queue·분산 semaphore를 추가하지 않는다.

## 관리자와 관측

관리자 상태/화면은 `최근48시간 무료 확인`, `최대4페이지`, `확인 완료 시각/범위`, `상한 도달`, `실제 재시도 대기`를 구분한다. 기존 `전체 탐색 완료` 문구를 새 확인에 사용하지 않는다. 무료 확인이 정상이어도 공식 API의 실패·예산 이월을 별도로 표시한다. 공개 게시물 DTO와 공개 요청의 D1 전용 조회는 유지한다.

공식 X12시간·기존 pending/fallback·공통 UTC 하루$1 목표·사이트 보호·자동충전·D1/Queue guard·웹훅 Disabled와 수동 재활성화 기능·RSS6시간은 변경하지 않는다. 강제 유료 호출이나 예산 증액으로 검증하지 않는다.

## 검증과 운영

필수 회귀: 기존 장기 cursor 이관/보존, 같은 head 이후에도 다음 페이지 발견, 비정렬/문맥/리포스트/48시간 경계,4페이지 뒤 정상 확인 완료와 범위 제한, 완료 후 다음 두 실행의 최근 확인, 저장 실패 후 cursor/페이지 수 유지, 최신 head와 pending의 분리, 공식 권위/clock·숨김 유지, RSS 전체 Queue50회 한도 유지.
