# SUL-41 X 수집 관리자 개선

사용자가 [SUL-41](https://linear.app/sulfurbottom/issue/SUL-41)을 구현하도록 요청했다. 웹훅 카드를 기존 관리자 카드와 맞추고, REST 누락 복구 예산·문제를 확인해 조치하며 실제 X 수집을 검증한다.

사용자가 예산 방식을 선택했다: **기존 양 사이트 UTC 하루 $1 공통 예산 유지, REST 실행 전 필요액·잔여액 표시.** 별도 $0.40 확보, 총액 인상, 공급자 자동충전 변경은 하지 않는다.

## 수용 조건

- 웹훅 카드는 기존 Card/CardHeader/CardContent·상태 Badge·고정폭 수치·8px/12px 여백을 재사용한다. 현재 상태/이전 응답/오류의 의미와 갱신 동작은 보존한다. 최근 수신 표본의 처리 제외·원문 미확보도 숨기지 않는다.
- REST 상태 카드에서 해당 사이트 전체 대상의 첫 페이지 예상 예약액, 페이지 크기·대상 수, 공통·사이트 보호 한도 중 실제로 사용 가능한 잔여액을 실행 전에 확인한다.
- 추정에는 실제 수집기의 최적화 여부에 따른 페이지 크기와 기존 비용 계산을 사용한다. 저장된 source identity와 사용자 캐시는 별개이므로 모든 대상의 캐시 갱신 상한을 포함하고, 유효 캐시는 실제 재조회하지 않음을 설명한다. 다음 페이지·인용 원문 보강·동시 사용은 별도다.
- 이미 이월 커서가 있는 계정의 첫 요청은 실제25개 continuation 정책을 포함하며, 신규 스캔5개와 혼동하지 않는다. 그 이후 추가 페이지 수는 예측하지 않는다.
- 공통 게이트의 미디어 추가 예약도 실제 실행과 같은 함수로 산정하고 사이트 기본 예약과 별도로 해당 잔여액에 비교한다. 사이트 snapshot/이력 읽기 실패는 빈 정상 목록이 아닌 조회 오류로 전달한다.
- 예산 산정은 기존 관리자 전용 `/api/x/activity`의 읽기와 고정 Service Binding을 재사용한다. 오래된 peer·장부 미준비·날짜 불일치·조회 실패는 확인 불가로 표시하고0이나 사용 가능으로 만들지 않는다.
- 실제 요청의 기존 사이트/공통 원자적 예약·정산·중지·숨김/권한·중복 방지는 그대로다. 예상액이 별도 배정·사전 결제·완료 비용을 뜻하지 않는다. 과거 REST 실패 원장은 보존한다.
- 추가 유료 테스트·강제 REST 실행·가짜 웹훅·구독 제어·장기 대기를 하지 않는다. 기존 자연 이벤트·저장 JSON·사진 표시·중복/실패/장부와 정상 관리자 흐름으로 검증한다.
