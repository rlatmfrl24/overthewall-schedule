# OTW Play 메타데이터·썸네일 우선 AI 초안 개편 계획

**상태: 미구현·프로젝트 이관 완료 후 재개**

확정일: 2026-10-14. 프로젝트의 범위가 큰 이관 작업을 우선하기 위해 이번 작업은 문서화만 수행한다. 기능 구현, 환경·API 키 설정, 마이그레이션 생성·적용, 실제 모델 호출, 운영 배포는 수행하지 않는다. 이관이 끝나더라도 자동으로 구현이나 검증을 시작하지 않으며, 사용자의 재개 요청 후 아래 선행 확인을 수행한다.

**목표:** 메타데이터·썸네일로 기본 초안을 만들고 필요한 판단·추출만 모델에 맡기며, 기존 플레이리스트 50개 검수 흐름을 유지한다.

**구조:** 기존 수집·작업 큐·AI 배치·검수 저장·비공개 등록 서비스를 재사용한다. 명확한 후보는 코드로 처리하고, 모호한 후보는 Decisions, 필수 정보 부족은 Gemini의 텍스트＋이미지 추출로 처리한다. 영상 AI 입력은 관리자 선택의 추가 확인으로 분리한다.

이 문서는 향후 변경 계획이다. 현재 동작과 과거 검증 기록은 [AI 검수 문서](../../otw-play-ai-review.md)를 따르며, 이 계획을 구현 완료나 현재 운영 계약으로 해석하지 않는다.

## 1. 현재 구현과 향후 변경

## 2. 확정한 제품 기준

- 기본 흐름은 플레이리스트 → 한 페이지 최대 50개 → 한 곡씩 검수 → 비공개 등록 → 관리자 선택으로 다음 묶음 준비다. 기존 [작업 큐](../../otw-play-playlist-work-queue.md)와 [가져오기·검수 개편](../../otw-play-import-review-redesign.md)의 활성 묶음 하나·관리자 완료 후 다음 페이지 원칙을 유지한다.
- 기본 초안은 메타데이터·썸네일·기존 카탈로그로 만든다. 영상 전체 분석을 초안 생성·검수 진입·비공개 등록의 기본 전제로 두지 않는다.
- 모호한 후보는 Decisions로 판단한다. 필수 정보 후보가 없거나 적합한 후보가 없다고 판단한 경우에만 Gemini를 자동 호출해 정보를 추출한다. 복수 후보 중 선택이 여전히 모호하면 관리자에게 넘긴다.
- 영상 분석은 관리자 선택으로만 실행한다. **별도로 요청하지 않은 가창 구간은 생성·자동 입력하지 않는다.** 저장된 구간이 있거나 구간 편집을 열었다는 사실은 AI 구간 요청으로 간주하지 않는다.
- 수동 검수값과 기존 곡 식별자를 보호한다. AI 판단만으로 제외·등록·게시하지 않는다. 검수 저장·비공개 등록·게시의 구분과 기존 데이터 검증을 유지한다.
- API 키 입력 후 새 흐름 50개를 실제 실행하고 기존 영상 분석 기록과 비교한다. 비교를 위한 추가 영상 AI 호출은 하지 않는다.

## 3. 초안 처리 흐름

1. **자료 확보:** 기존 수집 서비스로 제목·설명·태그·채널·썸네일을 확보한다. 기본 분석에는 영상 길이나 분석 구간을 필수로 요구하지 않는다. 수집 가능한 공개·일부 공개 메타데이터를 처리하며 접근 불가 항목의 보류·제외 경로는 유지한다.
2. **후보 구성:** 기존 제목·별칭·원곡 가수 연결 로직을 재사용한다. 제목·설명에서 추출한 신규 곡명·가창자 문자열도 후보로 포함한다. 기존 카탈로그에 없는 곡도 처리할 수 있어야 한다. 명확한 연결은 추가 모델 호출 없이 초안을 구성한다.
3. **Decisions 판단:** 모호한 후보와 필요한 분류만 텍스트＋썸네일로 판단한다. 선택지에 `적합한 후보 없음`과 `선택 모호`를 구분해 넣는다. 서버가 제공한 후보만 선택할 수 있게 검증하고 선택된 값·출처는 서버 후보 자료에서 구성한다. 확률은 검수 참고 정보로 표시하며 임의 임계값으로 등록·제외하지 않는다.
4. **Gemini 추출:** 곡명·원곡 가수·가창자 등 저장에 필요한 정보 후보가 부족할 때만 텍스트＋이미지로 추출한다. 충분한 추출 결과에 Decisions를 반복 호출하지 않는다. 정보가 여전히 부족하면 미확인으로 남겨 수동 입력·보류하도록 한다. 영상 분석으로 자동 우회하지 않는다.
5. **검수·등록:** 기존 한 곡씩 검수 화면에서 확인·저장·다음 이동을 수행한다. 기존 곡 ID 재사용과 신규 곡·인물 materialization, 비공개 등록 결과 확인을 유지한다. 성공한 저장·등록을 반복하지 않는다.

썸네일은 서버에서 허용된 YouTube 이미지 호스트만 내려받아 base64로 전송한다. 시간·크기·이미지 형식 제한과 리다이렉트 검증을 적용하고 원본 이미지 데이터는 D1에 저장하지 않는다. 썸네일 실패 시 확보한 텍스트로 계속 처리하고 이미지 미사용 사실을 표시한다.

### 필드별 근거

- 곡명·원곡 가수는 명시된 크레딧이나 확인된 카탈로그로 연결한다. 신규 문자열은 원문 후보 선택, 필요한 이미지 추출 또는 관리자 입력으로 확보한다.
- 가창자는 실제 크레딧으로 연결한다. 업로더·썸네일 캐릭터·원곡 가수만으로 실제 가창자를 확정하지 않으며 제작 크레딧을 듀엣 가창으로 오인하지 않는다.
- 장르는 확인된 카탈로그와 명시된 근거를 우선한다. 썸네일 분위기나 커버 언어만으로 곡 장르를 확정하지 않는다.
- 방송일·원본 방송 링크는 명시된 방송 자료와 기존 서버 출처 검증을 사용한다. 업로드일을 방송일로 바꾸거나 원곡 MV를 원본 방송으로 연결하지 않는다.
- 가창 구간·완곡 여부는 관찰 근거가 없으면 미확인으로 유지한다. 재생 기본 범위 `0~영상 끝`과 실제 가창 경계를 구별한다. 여러 곡·메들리는 확인된 후보를 각각 보여주며 썸네일만으로 전 곡을 찾았다고 표시하지 않는다.

## 4. API·저장·호출 제어 계획

이번 문서화에서는 아래 DTO·테이블·설정을 추가하지 않는다. 이관 후 현재 구조를 다시 확인한 다음 구현한다.

- 기존 AI 요청에 `mode: metadata | video`와 `includeSegment`를 추가한다. 기본값은 `metadata`, `false`다. 기본 요청에서 `range`를 생략하고 명시적인 영상·구간 요청에서만 허용한다. 최신 결과 조회와 멱등 키도 요청 범위를 구분한다.
- 메타데이터 프롬프트에는 영상 입력·분석 구간·구간 생성 지시를 넣지 않는다. 요청하지 않은 `segment`가 반환되더라도 서버 검증과 폼 적용 양쪽에서 제외한다.
- 결과에 썸네일·카탈로그 근거, 필드별 미확인 이유, 단계별 실행 정보를 추가한다. 정상 메타데이터 초안은 영상 분석 없이 `succeeded`가 될 수 있다. 실제 단계 실패는 구분하며 기존 `partial` 기록을 일괄 성공으로 변경하지 않는다.
- 기존 작업·배치 저장소를 재사용하고 모델 호출 기록을 추가한다. 제공자·모델·단계·사용량·시작/종료 시각·결과·가격 기준을 기록한다. 성공한 단계는 중단 후 재사용하며 원본 이미지·키를 저장하지 않는다.
- 동시 활성 분석은 기존처럼 하나로 제한한다. **UTC 일일 기본 500회는 실제 모델 호출 시도 합계**에 적용하며 재시도를 포함한다. 한 초안 작업의 모델 호출은 합산 최대 3회로 제한한다. 코드 처리·캐시 재사용은 모델 호출로 세지 않는다.
- 각 외부 호출 전에 한도를 원자적으로 확보하고 lease를 갱신한다. 같은 날의 기존 호출 기록도 한도에 반영한다. 저장 실패 복구와 등록 재시도는 성공한 모델 단계를 재호출하지 않는다. 외부 응답이 유실된 경우에는 사용량 미확인과 추가 시도 가능성을 숨기지 않는다.
- 캐시에 요청 방식·후보 버전·메타데이터·썸네일 해시·모델·프롬프트 버전을 반영한다. 기존 완료 결과와 수동 검수값은 보존한다. 이전 방식의 미실행 영상 작업은 자동 재개하지 않고 새 방식 재시도를 안내한다.
- 관리자 인증·`no-store`·후보 버전 검사와 기존 Queue를 유지한다. 마이그레이션은 데이터를 보존하는 추가 방식으로 생성·검증하며 다른 작업의 스키마·migration·미커밋 변경을 포함하거나 덮어쓰지 않는다.

확인 당시 구현 후보 모델은 Decisions의 `gpt-6-luna`와 기존 Gemini의 `gemini-3.8-flash`다. 이관 후 API 지원·가격·계정 접근을 다시 확인한다. 모델명 환경 변수만 교체하는 방식으로 구현하지 않는다.

## 5. 관리자 화면 계획

- 기본 버튼은 **초안 만들기**, 보조 버튼은 **영상으로 추가 확인**으로 구성한다. 메타데이터 확인·후보 판단·정보 추출의 현재 단계와 오류를 표시한다.
- 기본 화면에는 AI 분석 구간 입력을 노출하지 않는다. 영상 추가 확인을 선택한 뒤에만 **가창 구간도 분석** 옵션을 표시하며 기본은 꺼 둔다. 구간을 요청하지 않은 영상 분석에서는 완곡 여부 등 추가 확인만 제안한다.
- 저장된 구간이나 구간 편집 상태로 AI 구간 요청을 자동 활성화하지 않는다. 새 항목에서는 구간 요청 옵션을 초기화하고, 재로그인·새로고침에서는 해당 항목에 명시적으로 요청해 저장된 상태만 복원한다.
- 요청하지 않은 구간은 과거 AI 결과나 `AI 제안 일괄 적용`에서도 자동 적용하지 않는다. 기존 수동 구간값은 보존한다.
- 현재 50개 진행률·저장 후 다음 이동·보류·부분 등록 실패 복구를 유지한다. 조회·새로고침·재로그인은 모델 호출을 시작하지 않는다.
- 키가 없거나 제공자가 차단되면 필요한 설정과 영향을 표시한다. Decisions 장애를 이유로 모든 항목을 Gemini나 영상 분석으로 우회하지 않는다. 수동 검수는 계속 사용할 수 있게 한다.

## 6. API 키 설정과 재개 순서

현재 API 키를 요청·조회·설정하지 않는다. 사용자가 구현 재개 후 준비하는 순서는 다음과 같다.

1. 이관 완료 후 실제 OTW Worker·D1·Queue·관리자 UI의 경로와 소유 환경을 확인한다. 이관 문서의 환경 분리·데이터 경계를 우선한다.
2. Decisions의 모델·엔드포인트·이미지 입력 방식·계정 접근과 Gemini의 이미지/영상 입력·구조화 출력·모델 지원·가격을 공식 문서로 다시 확인한다. 공개 문서의 존재를 계정 권한 확인으로 간주하지 않는다.
3. 구현에서 Worker용 `OPENAI_API_KEY`와 기존 `GEMINI_API_KEY`를 연결한 뒤 사용자가 해당 Worker 환경에 키를 입력한다. 로컬 파일명과 운영 secret 대상은 이관 후 확정된 프로젝트 설정을 따른다. 클라이언트 `VITE_*` 변수나 Git 추적 파일에는 키를 넣지 않는다.
4. 활성화·일일 한도·Queue 연결을 확인하고 실제 관리자 진입에서 최소 대표 요청으로 제공자 접근을 검증한다. 설정 누락·인증 실패·한도 초과를 구별하고 키·원문 오류를 로그나 응답에 노출하지 않는다.
5. 아래 자동 검증과 실사용 검증을 수행한다. 키 입력만으로 완료 상태나 다음 묶음 준비를 자동 실행하지 않는다.

## 7. 검증·비용·속도 비교 계획

### 자동 검증

- 기본 요청·배치·프롬프트·결과·폼 적용 모두에서 영상 입력과 미요청 구간이 없는지 확인한다.
- 명확한 후보의 무호출 처리, Decisions 선택, 필수 정보 부족 시 Gemini 추출, 모호한 결과의 관리자 선택을 검증한다.
- 신규 곡·동명곡·별칭·듀엣·메들리·썸네일 실패·정보 부족·잘못된 후보·제공자 실패를 확인한다.
- 50개 경계·마지막 페이지·동시 요청·중복 전달·응답 유실·한도 초과·단계 저장 후 재개·수동 입력 보호를 실제 D1 테스트로 검증한다.
- 변경 관련 UI·API 테스트, 타입·린트·아키텍처 검사와 빌드를 수행한다. 마이그레이션은 기존 로컬 데이터를 초기화하지 않고 검증한다. 최종 PR/릴리스 검증은 당시 프로젝트 규칙을 따른다.

### API 키 입력 후 실사용 검증

- 실제 관리자 화면에서 대표 50개 묶음을 준비하고 초안 확인·검수 저장·비공개 등록·다음 묶음 준비까지 진행한다. 카탈로그와 D1을 다시 조회해 저장 결과와 곡 ID 재사용을 확인한다. 낮은 수준 API나 모의 응답으로 관리자 흐름을 대체하지 않는다.
- 기본 흐름의 영상 AI 호출 **0회**, 미요청 구간 생성·적용 **0건**을 확인한다. 선택적 영상 분석은 관리자 선택으로만 실제 화면에서 별도로 검증한다.
- 단계별 호출 수·캐시 재사용·Gemini 보완 비율·입출력 사용량·항목 및 묶음 처리 시간·관리자 수정량을 측정한다. 항목 처리의 p50/p95와 묶음 전체 대기 시간, 모델 호출 시간을 구분한다.
- 기존 영상 분석 기록과 비교한다. 모델·입력·시점·캐시·표본 차이를 명시하며, 같은 표본의 동일 조건 실험처럼 표현하지 않는다. 비교를 위해 기존 영상 방식을 새로 호출하지 않는다.
- 비용은 실제 사용량과 당시 제공자 가격을 근거로 한 **추정 비용**으로 표시한다. 생각 토큰 등 실제 과금 항목과 이미지·추출·재시도를 포함한다. 계정 청구액을 확인하지 않았다면 확정 청구액으로 표시하지 않는다. 사용량 누락은 0원으로 취급하지 않는다.
- 기존 기록이 부족하거나 비교 단위가 맞지 않으면 새 흐름의 실측만 보고하고 절감률을 임의 계산하지 않는다. 개선 여부는 측정 결과대로 보고한다.

완료 기준은 정상 초안을 **확인하고 다음 한 번으로 저장·이동**할 수 있고 실제 관리자 흐름과 저장 결과가 확인되는 것이다. 단가나 모의 테스트만으로 비용·속도·정확도 개선을 완료로 표시하지 않는다.
