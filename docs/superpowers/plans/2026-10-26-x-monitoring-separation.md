# 웹훅 현재 상태와 REST 복구 이력 분리

사용자가 과거 실패 보존, 현재 웹훅 상태/REST 누락 복구 이력의 분리, 상단 통합 새로고침과 오류 검증 후 운영 반영을 승인했다.
기존 예산·자동충전·수집/중지 설정, REST 커서, 실패 원장과 구독 상태는 바꾸지 않는다. 유료 테스트·강제 수집·장기 대기를 추가하지 않는다.

1. 기존 XAA 읽기 API/query key를 재사용해 X 수집 주 화면과 대시보드에 현재 구독·최근 수신/저장·오류/대기를 표시한다. 수신0건은 구독 정상/신규 수신 대기로 표시한다.
2. 기존 정기·수동 작업은 REST 누락 복구와 그 이력으로 명명한다. 원래 실패는 보존하고 REST 과거 실패를 웹훅 현재 장애로 설명하는 critical 경고를 분리한다.
3. 공통 읽기 query를 상단 새로고침에 연결한다. 조회 실패/오래된 응답에서 현재 정상으로 표시하지 않고 이전 값임을 명시한다. 제어 실패도 실제 상태를 재조회한다.
4. 회귀를 먼저 작성해 실패를 확인하고 최소 수정한다. 초기/재조회 오류, 캐시된 정상, 재조회 복구, 제어 실패, 부분/예산 중지, 통합 새로고침과 과거 실패 보존을 검증한다.
5. 변경 검토·기존 자동 CI 후 PR을 병합해 OTW 자동 배포, 같은 병합 소스의 정상 LuvDia 배포를 수행한다. 추가 스키마는 없다. 계정 D1 보호를 먼저 확인하고 정상 관리자 화면/서버 readback으로 완료한다.

도메인 간 화면 조합은 기존 app/admin 계층과 Dashboard의 슬롯 패턴을 사용한다. Operations API의 REST 이력은 그대로 제공하며 읽기 전용 경고의 이름·범위만 명확히 한다. 공개 중계나 유료 API 조회 경로를 새로 만들지 않는다.
