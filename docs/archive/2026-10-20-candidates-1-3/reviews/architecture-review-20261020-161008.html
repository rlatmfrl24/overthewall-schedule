문제. interface가 받는 Idempotency-Key는 실제 저장 implementation에 도달하지 않아, 같은 요청을 재전송해도 결과를 복구한다는 의미가 닫히지 않습니다.

방향. 기존 저장 module 내부에서 요청 의도와 결과의 책임을 연결하고, 이관 폐기 후 남은 shallow command 전달만 축소해 depth를 높입니다.

  • locality: 저장·재시도 판정 집중
  • leverage: 동일 interface로 재검증
  • seam: 실제 D1 adapter 유지

영향 조건: 저장 후 응답 유실·같은 입력 재시도. 발생 빈도는 미측정이며, 현행 CAS·구간 중복 검사는 보존돼 있습니다. 저장됐지만 실패로 보이는 상황이 가능한지는 실제 HTTP replay로 검증해야 합니다. 운영 중복 발생이나 데이터 손상은 이번에 관측하지 않았습니다.

문제. 하나의 DTO가 전체·페이지·lookup을 모두 표현해, 여러 UI caller가 결과의 완전성과 병합 규칙을 알아야 하는 interface가 됐습니다.

  • leverage: 여러 caller가 재사용

  • adapter: 현행 요청 제한 유지
