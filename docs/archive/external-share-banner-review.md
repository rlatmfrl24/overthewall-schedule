# SUL-5 외부 공유용 배너 필요성 검토 및 구현안

검토일: 2026-09-14 KST  
이슈: [SUL-5 — 외부 공유용 배너 기능 개발](https://linear.app/sulfurbottom/issue/SUL-5)  
상태: 검토 완료, 아래 구현안은 제안이며 구현 승인을 의미하지 않음

## 결론

**사이트를 소개하는 정적 배너는 유용하다. 우선 구현안은 홍보 이미지 1종, 이미지 저장·링크 복사 진입점, 기본 공유 미리보기 이미지의 조합을 권장한다.** 반복 공유에 쓸 자료를 제공하는 목적이며, 배너가 유입을 증가시킨다는 근거는 아직 없다. 공유 빈도나 유입 데이터도 이번에는 수집하지 않았다.

오늘 일정표를 전달하는 목적은 기존 이미지 다운로드·클립보드 복사 기능이 담당한다. 사이트 소개 배너에는 날짜나 실시간 방송 상태를 넣지 않아 오래된 게시글에서도 안내가 유효하도록 한다. 사용자별 배너 편집기, 동적 이미지 생성 API, 관리자 배너 관리 기능까지 만들 필요는 현재 요구사항에서 확인되지 않았다.

사용자가 확정한 이번 작업 범위는 **필요성·공유 방식 검토와 구현안 정리**다. 실제 배너 제작, 애플리케이션 코드 변경, 배포 및 외부 게시를 수행하지 않았다.

## 공유 방식 비교

| 방식 | 적합한 목적 | 한계와 비용 | 제안 |
| --- | --- | --- | --- |
| URL만 전달 | 빠른 사이트 방문 안내 | 소개 이미지가 없고 카드 모양은 플랫폼에 따라 달라짐 | 항상 함께 제공할 기본 수단 |
| 정적 PNG 첨부 + 본문 URL | 디시인사이드 등 커뮤니티에서 사이트 소개 | 작성자가 이미지를 올리고 URL도 붙여 넣어야 함 | 우선 지원 |
| Open Graph 대표 이미지 | 링크 미리보기를 지원하는 서비스에서 시각적 소개 | 모든 플랫폼이 이미지를 표시하는 것은 아니며 캐시 갱신이 지연될 수 있음 | 같은 이미지 재사용 |
| 기존 일정표 PNG | 특정 날짜의 방송 일정 전달 | 특정 시점 자료이므로 사이트 상시 소개와 목적이 다름 | 기존 흐름 유지 |
| HTML 링크형 배너 | HTML 편집을 허용하는 개인 사이트·블로그 | 대상 편집기의 HTML·외부 이미지 허용 여부에 의존 | 실제 요청이 있을 때 추가 |
| iframe·실시간 배너 | 외부 페이지에 현재 일정 표시 | 임베드 허용, 갱신, 보안 정책과 운영 비용까지 별도 설계 필요 | 이번 제안에서 제외 |

디시인사이드 공식 안내는 PC·모바일 웹에서 업로드한 이미지의 위치 조절을 설명하며, PC에서는 크기 조절도 안내한다. 따라서 이미지 파일을 받아 글에 첨부하는 방향에는 근거가 있다. 다만 이 안내만으로 외부 URL 자동 링크화, 클릭 가능한 이미지 링크, 임의 HTML·iframe 지원을 확정할 수는 없다. [디시인사이드 글쓰기 에디터 개선 안내, 2025-01-13](https://gall.dcinside.com/board/view/?id=know&no=416&page=1)

Open Graph는 대표 이미지 URL인 `og:image`와 이미지 크기·유형·대체 설명 필드를 정의한다. 이는 링크 미리보기용 메타데이터이며, 디시인사이드 본문 이미지 첨부를 대신하지 않는다. [Open Graph 공식 명세](https://ogp.me/)

## 제안하는 사용자 흐름

1. 방문자가 사이트 Footer의 **사이트 공유** 링크로 `/share`에 진입한다. 모바일과 데스크톱에서 로그인 없이 접근한다.
2. 소개 배너 미리보기와 짧은 소개 문구, 사이트 URL을 본다.
3. **배너 이미지 저장**으로 PNG를 받고 **링크 복사**로 홈 URL을 복사한다. 복사가 거부되면 화면에 표시된 URL을 직접 선택·복사할 수 있다.
4. 외부 글쓰기 화면에서 이미지를 첨부하고 본문에 URL을 넣는다. 안내 문구는 “배너 이미지를 첨부하고 아래 주소를 본문에 함께 넣어 주세요.”로 한다.
5. 독자가 본문의 링크로 홈에 진입하고 공개 일정 화면을 이용한다.

이미지 자체가 사이트로 이동한다고 안내하지 않는다. PNG에 적힌 주소는 클릭 가능한 링크가 아니므로 본문 URL이 방문 경로를 담당한다. 외부 편집기가 URL을 링크로 처리하는지는 구현 후 대상 환경에서 별도로 확인한다.

## 구현 범위와 변경 지점

아래 작업을 하나의 완결된 공유 흐름으로 구현하는 것을 제안한다. 중간 단계에서 파일만 추가하고 사용자 진입점을 빠뜨린 상태를 기능 완료로 처리하지 않는다.

| 영역 | 구현안 |
| --- | --- |
| 공개 자산 | 정적 PNG와 편집 가능한 원본을 버전 관리. 미리보기·다운로드·OG가 같은 PNG를 참조 |
| 기능 소유권 | `src/features/site-sharing/`에서 배너 경로, 소개 문구, 공유 UI 소유. 필요한 컴포넌트만 `index.ts`로 공개 |
| 페이지 | `src/routes/share.tsx`는 얇은 route adapter로 유지. `ContentPageShell`을 사용하고 공개 Footer에 진입점 추가. route tree는 정상 빌드로 생성 |
| 다운로드·복사 | 같은 출처의 정적 파일 다운로드를 기본으로 사용. 모바일에서 저장 대신 이미지가 열리는 경우 저장 안내 제공. URL은 `SITE_ORIGIN` 기준으로 만들고 복사 실패를 성공으로 표시하지 않음 |
| SEO 계약 | `/share` 고정 경로 및 기본 배너 이미지 정책 추가. 1차 기본 배너 적용 대상은 `/`, `/weekly`, `/notice`, `/vods`, `/multiview`, `/share`로 명시 |
| 최초 HTML | `generate-seo-assets.ts`가 이미지 태그를 생성·교체·제거하도록 보강. 초기 `index.html` 및 빌드 결과에 정확한 태그가 있어야 함 |
| 이동 후 HTML | `apply-site-seo.ts`와 Worker SEO도 같은 contract 정책 적용. 이미지 대체 설명·크기 등을 추가하면 기존 곡·멤버의 개별 이미지에 기본 배너 치수를 잘못 적용하지 않음 |
| 기존 SEO 보존 | 곡·멤버 상세의 고유 이미지와 canonical 유지. 관리자·비공개·404에 공유 배너를 전역 주입하지 않음. `twitter:card` 변경 시 최초 응답과 클라이언트 이동을 함께 처리하고 최신 플랫폼 명세 확인 |
| 디자인 문서 | 실제 채택한 공유 페이지·Footer 진입점·이미지 규격을 `Design.md`에 반영 |

권장안에는 신규 `/api` 엔드포인트, DB 테이블·쓰기, Queue, 이미지 생성 서버, 외부 게시 자동화가 필요하지 않다. 정적 파일은 기존 자산 배포를 사용한다. HTML 배너 코드는 대상 사용처가 확인되기 전에는 제공하지 않는다.

공유할 때마다 스냅샷을 렌더링하는 방식은 상시 홍보 이미지에 필요하지 않다. 정적 파일 제공은 기존 일정표 내보내기와 독립적으로 동작하도록 한다.

회귀 테스트는 이미지 메타데이터의 정적 HTML·클라이언트·Worker 일관성, 공유 URL 및 복사 오류 처리를 중심으로 추가한다. 구현 시 해당 테스트와 `architecture:check`, `typecheck:test`, `lint`, `build` 및 관련 회귀 범위를 실행한다. 테스트는 실제 다운로드·외부 공유 흐름 검증을 대신하지 않는다.

## 남은 결정과 검증 한계

- 필요성 판단은 현재 기능과 공유 목적을 비교한 제품 제안이다. 유입 개선 수치나 비용 대비 효과를 측정한 결과는 아니다. 운영자 1회 소개만 필요하면 같은 정적 이미지와 URL을 직접 사용하는 방식으로도 목적을 달성할 수 있으며, 반복해서 방문자에게 자료를 제공하려면 제안한 `/share`가 유용하다.
- 구현 착수 시 최종 배너 문구·시안과 우선 확인할 외부 환경을 정한다. 검토 자체를 위해 추가 정책 결정을 요구하지 않는다.
- 디시인사이드의 게시글 작성·등록, 실제 이미지 업로드, 모바일 앱 동작은 이번에 수행하지 않았다. 대상 환경에서 이미지나 URL 처리 차이가 있을 가능성은 미평가이며, 발생 시 해당 환경의 안내를 보완한다.
- 공유 서비스 캐시가 이전 이미지를 유지하면 노출 반영이 늦을 수 있다. 발생 가능성은 서비스별로 다르며, 버전이 있는 이미지 URL과 해당 서비스의 갱신 절차로 확인한다.
- 이번 산출물은 이 문서 한 개다. 코드 테스트나 빌드는 실행하지 않았고, 코드·공개 서비스·Linear 상태를 변경하지 않았다. 기능 완성 또는 배포 완료 판정이 아니다.
