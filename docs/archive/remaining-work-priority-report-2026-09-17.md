작성·갱신: 2026-09-17. 문서 통합 기준 커밋 `33779e25` 이후의 사용자 결정을 반영했다.
상태의 기준은 [개발·운영 상태표](../development-status.md)다. 중요도는 권고이며,
아래 사용자 확정 상태와 범위 결정을 우선한다. 이번에 운영 설정 변경이나 기능 테스트를 수행하지 않았다.

이전 조사 문서는 결정 이력으로 보존하며, 삭제한 기능을 복원하는 근거로 쓰지 않는다.

## 2. 남은 작업과 중요도

**남은 작업은 9개다: 높음 3개, 중간 2개, 낮음 2개, 보류 2개.**
현재 장애가 확인됐다는 뜻은 아니다. 높음은 기본 이용·데이터 정확도에 미치는 영향과
기능을 사용하기 전 확인 필요성을 기준으로 분류했다. AI는 테스트 예정이고 자동 수집은
기능 확인 대상으로 확정되었으며, 이번 보고서에서 실행을 시작하지 않는다.

| 중요도 | 작업 / ID | 쉬운 설명 | 현재 상태·다음 행동 |
| --- | --- | --- | --- |
| 높음 | 자동 수집 / OPS-PLAY-UPLOAD | 승인 채널의 새 영상이 자동으로 검수함에 들어오는지 확인 | 기능 확인 필요. 설정·예약 실행·전달·후보 저장의 실제 연결 확인 |

## 3. 우선 확인할 작업의 완료 기준

### 자동 수집 — 기능 확인 필요

수집 코드가 있다는 것만으로 예약부터 검수함까지 연결되었다고 판단하지 않는다.
먼저 현재 설정·승인 채널·중지 상태와 기존 증거를 확인하고 실제로 부족한 확인 범위를 정한다.
운영 재개가 필요한 확인은 그 실행 범위를 별도로 정하며, 상태 정리만으로 pause를 해제하지 않는다.

완료는 **새 영상 → 예약 작업 → 검수 후보 저장 → 관리자 검수·임시 등록 후 재조회**의
연결을 확인했을 때다. 중복·오류·중지 상태도 구분한다. 검수함에 도착한 것과 실제 공개는
다른 단계이며 자동 게시하지 않는다. [자동 수집 계약](../operations/channel-upload-polling.md)

### Play 실제 이용 — 관련 배포별 확인

일반 회원의 발견 → 검색 → 상세 → 실제 YouTube 재생, 개인 목록 저장 → 재방문 복원을 확인한다.
비로그인·회원·관리자 권한을 구분하고 관리자 전용 클립이 회원에게 노출되지 않는지 확인한다.
게시·철회·재생 불가 변경도 관련 화면에 반영되어야 한다.

이미 9/15 로컬 기록에는 실제 클립 게시 후 DB 상태 확인과 구간 재생·종료 확인이 있다.
이를 전부 미검증으로 되돌리지 않고 대상 배포와 부족한 역할별 흐름만 확인한다.
완료 기록에는 배포 버전·계정 역할·실제 동작·저장 후 조회 결과를 남긴다.
[기존 실사용 증거](../otw-play-ai-review.md)

### AI 검수 품질 — 테스트 예정

새 테스트를 이번에 실행하거나 완료로 간주하지 않는다. 예정된 테스트에서는 공식 영상·클립·
여러 곡 영상·모호한 곡 연결 등의 결과와 사람이 수정한 값의 보존을 확인하면 된다.
이전에는 영상 길이를 넘는 종료 시각 제안 사례와 이후 재분석 성공 사례가 모두 있었다.
전체 정확도·발생 빈도는 아직 그 기록만으로 판단하지 않는다.

완료 판단에는 원본·AI 제안·관리자 수정·저장 결과, 실패 유형과 확인하지 못한 범위를 남긴다.
몇 건의 성공만으로 모든 영상의 정확도를 보장하지 않는다. [AI 검수 계약](../otw-play-ai-review.md)

## 4. 나머지 작업을 결정하는 기준

- **계정 이전:** 분리 운영이 필요한 날짜가 정해지면 중요도가 올라간다. 현재 공유 계정 때문에
  실제 장애가 발생했다는 근거는 없다. 이전 시 데이터·인증·주소 전환과 되돌릴 방법을 준비한다.
- **가창 병합:** 같은 노래의 다른 날짜·영상·버전을 합치는 작업이 아니다. 실제 중복 가창만
  정리하고 소스·회원 제안·개인 목록·감사 이력의 참조를 보존해야 한다.
- **대표곡:** 기존 개인 플레이리스트 대표곡 선택과 멤버 대표 오리지널곡 지정은 별개다.
  폐기된 독립 멤버 노래책이나 삭제된 제작 참여 화면을 복원하지 않는다.
- **정정 요청:** 기존 가창 참여 정보 등 정확한 대상부터 정한다. 제작 참여 기능 삭제를
  이유로 이 항목까지 삭제하거나, 반대로 이를 통해 제작 참여 기능을 다시 도입하지 않는다.
- **보류 확장:** 개인 감상과 방송 단위 감상은 필요한 범위부터 선택한다. 작업량·완료일은
  아직 확정하지 않는다. 일정·라이브 확인이라는 제품의 최우선 가치보다 앞세우지 않는다.

## 5. 권장 진행 순서

1. 자동 수집의 기능 확인 범위와 기존 증거를 정리한다.
2. 예정된 AI 테스트 결과를 받아 문제와 미검증 범위를 기록한다.
3. 다음 Play 관련 배포에서 실제 회원·관리자 흐름의 부족한 검증을 마친다.
4. 계정 이전은 운영 일정에 맞추고, 가창 병합은 실제 중복이 확인될 때 구체화한다.
5. 대표곡·정정 요청과 보류 확장은 필요에 따라 선택한다.

X 비용 추적과 삭제·분리된 네 항목은 이 순서에 다시 넣지 않는다. 종료한 WebSub 제거,
백엔드 비용 7일 관측도 재개하지 않는다. 최신 상태 변경은 [단일 상태표](../development-status.md)에 남긴다.
