# 현재 작업과 2026-10-17 인계

갱신: 2026-10-16 KST. 현재 작업의 단일 진입점이다. 과거 계획의 체크박스나 과거 상태표를 새 실행 지시로 사용하지 않는다.

## 현재 중단 조건

사용자 요청으로 **D1 관련 작업을 전부 중단**했다. 원격·로컬 D1 SQL, 마이그레이션, doctor, DB 통합 테스트, 수집·백필, D1 읽기를 유발하는 사이트/API/관리자 화면 확인을 실행하지 않는다. preflight와 배포도 DB 검사에 이어질 수 있으므로 이번 문서 정리에서는 실행하지 않는다.

마지막 확인은 **2026-10-16 20:31 KST**, 계정 합산 읽기 **4,530,857 / 5,000,000행(90.6%)**, 잔여 469,143행이다. OTW 3,998,284행, LuvDia 532,573행이며 당시 쓰기 합계는 27,006행이다. 현재 수치로 다시 조회하지 않았다. UTC 일일 창의 다음 경계는 10월 17일 09:00 KST지만, 시간 경과나 초기화만으로 작업을 재개하지 않는다.

직전 문서 정리 작업에서는 운영 Cron·Queue·수집 플래그를 중지하거나 재개하지 않았다. 기존 자연 X 확인과 19일 관측 예약의 설정은 유지하되, 명시적 재개 요청 전에는 D1·D1 사용 웹/API 확인을 보류하도록 중단 조건을 추가했다. 이 제한은 과거 예약 본문보다 우선한다.

이후 사용자가 모든 미커밋 변경의 리뷰·문제 수정·PR 작성을 요청했고, **D1 중단 유지 및 PR 병합 대기**를 명시했다. 이번 PR도 master 병합 시 자동 배포의 원격 스키마 검사를 실행하므로 병합하지 않는다. D1을 호출하지 않는 로컬 문서 검사와 순수 단위 테스트만 실행한다. 첫 범위 대조 뒤 [추가 독립 리뷰](reports/sul-36/2026-10-16-uncommitted-deep-review.md)에서396개 코드·설정·스키마 항목의 변경 hunk·논리 변경을 검토하고 결함3종을 수정했다. 원본409개와 별도 X 작업 트리는 보존하며 실제 D1 회귀는 미실행이다.

## 내일 시작 순서

1. 이 문서와 아래 CHZZK 진단 기록을 읽는다. 기존 미커밋 작업과 작업 트리를 보존한다.
2. 사용자의 재개 요청을 확인한 뒤 Cloudflare **기존 계정 집계**로 여유를 확인한다. 여유·예상 비용·중단 기준을 기록하기 전에는 DB 검사나 수집을 실행하지 않는다.
3. PR162의 outbox 완료 확인·공유 채널·X 관계 정리 회귀26사례와 기존11/7행 기준을 필요한 로컬 D1 범위에서 먼저 확인한다. 아직 실행하지 않았고 병합·운영 반영되지 않았다. 전체 과거 검사·재이관으로 검증을 대체하지 않는다.
4. 테리 눈나 채널 오류를 작은 로컬 회귀 사례로 재현하고 담당 adapter/판정만 수정한다. 전체 수집·전수 DB 검증으로 재현하지 않는다.
5. 실패/미확인 상태, 휴방 오판 차단, 재시도, 공개 경계와 다른 채널 회귀를 검증한다. 실제 정상 진입과 저장 결과가 있어야 해결로 기록한다.
6. 필요한 검토·릴리스 절차를 거쳐 변경 범위만 반영한다. OTW 자동 배포와 중복 수동 배포를 만들지 않는다. 운영 결과가 없는 구현/테스트를 운영 해결로 올리지 않는다.
7. 기존 자연 X·19일 예약의 저장된 결과를 확인한다. 결과가 없으면 미확인으로 유지하고 중복 예약을 만들지 않는다.

## 테리 눈나 채널 오류: 확정된 진단

- 멤버: uid 2, terri_nunna, 채널 0a2020b09b8cc7f2285b7ae5de2ce4d3.
- 실패 실행: f1195a83-a4ab-4efd-8590-23f771a72d9c, 10월 16일 16:03~16:08 KST. scan item은 c38ceec2-768a-4331-b13f-73d62059aa44, 3회 시도 후 실제 partial이다. 성공으로 수정하지 않았다.
- Cloudflare의 당시 Queue 로그 6개에서 **라이브 polling 응답 HTTP 500 / code 9004 / 해외 시청 불가능한 콘텐츠**를 확인했다. 원본 Worker 버전은 0e140a70-3574-4af4-8b4f-261477ed766a다. 현재 코드의 일반 500 재시도와 겹친다.

- 공개 채널 메타데이터에서 openLive=false를 별도로 확인했지만, 이를 사용하는 수정은 아직 구현하지 않았다. 공개 메타데이터 사용 가능성을 검증하되 인증/지역 제한 우회, 재생 URL 획득, 방송 시작 시각 추정, 미확인 값을 휴방으로 바꾸는 처리는 금지한다.

저장된 로컬 증거는 릴리스 작업 트리의 .tmp/schedule-channel-repair-20261016/에 있다. failed-run.json, cache-probe.json, vod-evidence.json, vod-http.json, log-probe.json을 재사용하며 같은 운영 요청을 반복하지 않는다. 로그 검색 통계의 rows_read는 Observability 저장소 값이며 D1 사용량에 합산하지 않는다. 진단 중 직접 D1 조회는 읽기 29행·쓰기 0행이었다. 정상 공개 VOD 조회의 캐시 동작과 직접 SQL 비용을 혼동하지 않는다.

## 계속 보류할 범위

LuvDia 재이관·재복사·대량 백필, 원격 전수 doctor·재귀 음악 정합성·전체 스캔은 실행하지 않는다. 기존 이관 완료를 미완료 작업으로 되살리지 않는다. 데이터 공백이 필요하면 필요성·차이·비용을 먼저 확인한 선택 복구로 한정한다.

의도적으로 중지된 양 사이트 Play 자동화와 LuvDia AI=false를 유지한다. 유료 AI 품질 검증, 대량 업로드 감시 재개, 계정 이전, 전면 아키텍처 개편은 현재 작업에 포함하지 않는다. 기존 R2 업로드 사고의 영향/이전 상태가 모두 해소됐다고 판정하지 않으며 [사고 기록](reports/sul-36/operational-upload-incident.md)은 보존한다.

대표곡 pin, 참여 정보 정정·가창 병합, 라이브러리·방송 setlist, 전용 멀티뷰 확장, AI 메타데이터 초안과 전체 품질 검증은 요구사항만 보존한 후순위다. 기존 개인 playlist와 역할·보관 정책을 변경하지 않는다. player 원곡 가수 확장·제작 참여 확장·공유 배너·VOD AI 별도 프로젝트와 종료된 X 비용 추적 의무는 복원하지 않는다.

## 안전한 재개 위치

새 clone이나 다른 작업 트리에서도 이 저장소의 README → docs/current-work.md를 진입점으로 사용한다. 특정 개인 디렉터리가 있어야 작업을 시작할 수 있는 구조가 아니다. 병합 대기 PR의 문서를 읽을 때는 해당 PR HEAD와 운영 기준 HEAD를 구분한다.

C:/Develop/overthewall-schedule의 기존 409개 미커밋 파일과 별도 X 작업 트리는 수정하지 않는다. 릴리스 작업 트리의 기존 미커밋 보고서 3개도 바이트 그대로 보존한다. 해당 보고서의 과거 현재/미완료 표기보다 이 문서의 최신 중단·작업 상태가 우선한다. 다음 코드 작업은 최신 검토 소스에서 범위를 분리하고, 이미 섞여 있는 변경을 초기화하지 않는다.

로컬 보존 위치는 당시 작업 증거다. 원본 WIP는 C:/Develop/overthewall-schedule, 리뷰·문서 작업은 별도 otw-publication-release 작업 트리, X 원본은 otw-x-scan-recovery 작업 트리에 남아 있다. 원본 프로젝트의 새 인계 포인터는 저장소 웹 문서로 연결하고, 이 로컬 경로에 접근할 수 없는 독자는 PR의 인계 본문을 그대로 사용한다. 원본409개 변경의 포함 여부와 폐기된 이관 코드의 보존 여부는 리뷰 기록에서 대조한다.

필요한 기능의 계약만 [참조 문서](reference.md)에서 선택한다. 과거 실행·실패·계획은 [아카이브](archive/README.md)에서 증거가 필요할 때만 읽는다.
