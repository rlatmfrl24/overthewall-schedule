1. **D1 파일 접근 비용:** 경로 인덱스→소유 행 PK 조회로 수정했다. 실제 로컬 D1에서 무관한 공지10개→1,000개로 늘려도 요청당 수십 행을 유지한다. 공개·보관·공유 파일 회귀는 통과했으며 운영 감소는 배포 후 제한된 표본으로 별도 확인한다.
2. **Play 비회원 재생:** 사용자는 직접 연 일반 Chrome에서 정상 재생을 확인했다. IAB 비회원도 실제 재생 시간이 진행됐다. 자동화 Chrome의0:00 정지는 운영 장애로 확정하지 않는다. 실제 앱 검증을 통과하지 못한 실험 패치는 별도 보존 후 복원했으며 이번 PR에는 Play 코드 변경을 포함하지 않는다.
3. **문서·Git 정리:** 완료 관측 보고서를 검토해 현재 문서와 아카이브에서 연결했다. PR164의 병합·포함 관계와 사용 상태를 증명한 유휴 Play 브랜치/작업 트리만 정리했다. ignored 원본과 Windows 긴 경로 오류 후 남은 파일은 별도 보존했다. 원본과 별도 X 작업 트리는 보존 스냅샷의 내용·HEAD·diff 해시와 동일하다.
4. **PR165 계약 수정·릴리스:** 정확한 기준 `006d835b`에서도 재현된51개 실패를 수정했다. nullable 소유자 때문에 공용 공지·카페가 잘못 제외되는 실제 결함도 바로잡고 최종 시각·선택 멤버 차단을 유지했다. 전체2,923개 사례의 합성 gate와 독립 리뷰 후 merge `93e3d323`을 양 사이트에 반영했다. 운영 최소 표본에서 별도 JOIN 재정렬 문제가 드러나 후속 수정으로 후보→owner PK 순서를 고정했다. 로컬10→1,000행·ANALYZE 전후 읽기 비용과 기존 파일 보호20개 회귀가 통과했다. 최종 gate·운영 판정은 위 PR ledger와 연결된 후속 PR을, 변경 근거는 [계약 수정·컨텍스트 검토](reports/sul-36/2026-10-19-pr165-contract-release.md)를 따른다.

진행 근거는 [10/19 D1·Play 점검 및 정리](reports/sul-36/2026-10-19-d1-playback-closeout.md)를 따른다. 기존 보고서의 예정·미완료 표기보다 이 문서의 상태가 우선한다.

## 별도 확인이 남은 한계

- 공개 결과는 확인했으나 정각 전후와 계속 열려 있던 countdown 탭은 실시간 관측하지 못했다. 이미 지난 정각 검증을 새 예약으로 복원하지 않는다.
- 관측 창의 계정 D1 증가227,431행·쓰기35행은 UI/API·자연 Cron·집계 지연이 섞여 개별 귀속이 확정되지 않았다. SQL14행만으로 화면 전체 비용을 설명하지 않는다. 로그 검색의 `statistics.rows_read`도 D1 비용이 아니다.
- 관리자 보관 화면의 ‘일반 공개 일정’ 문구는 저장 상태를 표시해 시간 정책으로 숨긴 일정에 혼동을 줄 수 있다. 일반 API 차단은 확인했으며 데이터 상태를 강제로 바꾸지 않는다.
- 별도 일반 회원 계정의 실제 관리자 우회 차단과 과거 R2 사고의 전체 영향·복구 판정은 완료로 올리지 않는다. [업로드 사고 기록](reports/sul-36/operational-upload-incident.md)을 보존한다. 프로필의 현재 표시 시간·모바일 검증은 이번 기록을 따르며 측정이 없던 PR167 이전의 개선 배수를 추정하지 않는다.

## 다음 작업에 유지할 컨텍스트

- **미커밋 변경 보존:** 다른 작업의 변경을 잃지 않기 위한 기본 작업 규칙이다. 원본 작업 공간과 별도 X 작업 트리의 포함 관계를 검토하기 전에는 삭제·일괄 배포하지 않는다. 상세 파일 수·해시·경로는 보고서에 두며 매 요청에 복사하지 않는다.
- **X 최적화:** 운영 반영된 기능을 다시 구현할 일이 아니다. 빈 작업11행·미래 재시도7행의 회귀 계약만 유지한다. 별도 미커밋 X 작업 트리는 위 일반 보존 규칙을 따르며 영구 보관 의무나 종료된30일 추적을 새로 만들지 않는다.
- **대량 작업:** 계정 한도 사고와 작업별 비용 미산정 때문에 계속 보류한다. 공개·이번 수정에 필요한 최소 schema/인덱스 표본과 전수 이관·백필은 구분한다. 다시 필요해지면 범위·예상 비용·중단 기준·승인을 먼저 정한다. 이관 완료를 재이관 의무로 바꾸지 않는다.
- **Play·AI 자동화:** 사용자의 명시적 중지 결정을 유지한다. 자동 수집은 외부 호출·D1 쓰기·복구/적체를, AI는 유료 호출·결과 적용을 수반한다. 기능 전체가 고장 났다는 뜻은 아니다. OTW AI 기능 binding은 true, LuvDia는 false이며 수동 기능 설정과 자동 실행 중지는 구분한다. 이번 배포에서 새 실행·재개·과거 기간 소급을 하지 않는다. 재개 요청이 생길 때 품질·예산·작업 범위와 중지 기간 처리를 별도로 확인한다.

지금 컨텍스트에는 이 네 항목의 짧은 규칙만 유지하면 된다. 공개 전 countdown·완료 관측 예약·이관 실행부 제거·원본 파일 수 등 완료 이력은 증거가 필요할 때 보고서를 참조한다. 과거 D1 전면 중단이나 PR165 병합 대기 문구를 현재 승인보다 우선하지 않는다.

## 계속 보류할 작업과 참조

LuvDia 재이관·재복사·대량 검증·백필, 전면 아키텍처 개편, 유료 AI 품질 검증, Play/AI 자동화 재개는 보류한다. 대표곡 pin·참여 정보 정정/가창 병합·setlist·전용 멀티뷰 확장 등 후순위 요구는 [참조 문서](reference.md)에 유지한다. 이관 완료나 종료된 X 비용 추적 의무를 미완료로 되살리지 않는다.

새 작업은 README→이 문서→필요한 담당 기능 문서 순서로 시작한다. 과거 실행·실패·계획은 [아카이브](archive/README.md)에서 증거가 필요할 때만 읽는다. 원본 작업 공간·X 작업 트리·기존 보호 보고서는 정리 대상이 아니다.
