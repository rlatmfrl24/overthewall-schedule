## 이번 작업 결과와 반영 대기

1. **D1 파일 접근 비용:** 경로 인덱스→소유 행 PK 조회로 수정했다. 실제 로컬 D1에서 무관한 공지10개→1,000개로 늘려도 요청당16~27행을 유지한다. 공개·보관·공유 파일 회귀는 통과했으며 운영 감소는 배포 후 제한된 표본으로 별도 확인한다.
2. **Play 비회원 재생:** 사용자는 직접 연 일반 Chrome에서 정상 재생을 확인했다. IAB 비회원도 실제 재생 시간이 진행됐다. 자동화 Chrome의0:00 정지는 운영 장애로 확정하지 않는다. 실제 앱 검증을 통과하지 못한 실험 패치는 별도 보존 후 복원했으며 이번 PR에는 Play 코드 변경을 포함하지 않는다.
3. **문서·Git 정리:** 완료 관측 보고서4개를 검토해 현재 문서와 아카이브에서 연결했다. PR164의 병합·포함 관계와 사용 상태를 증명한 유휴 Play 브랜치/작업 트리만 정리했다. ignored 원본과 Windows 긴 경로 오류 후 남은 파일은 별도 보존했다. 원본412개 상태 항목과 X16개 항목은 내용·HEAD·diff 해시가 모두 동일하다.
4. **릴리스 검증 실패 해결 후 반영:** 전체 preflight는 테스트51개 실패로 중단됐다. 정확한 기준 소스 `006d835b`에서도 동일한51개 실패 이름이 재현돼 이번 수정의 신규 실패와 구분했다. 기존 fixture·공개 시점 기대를 담당 기능별로 수정하고 전체 gate를 통과하기 전에는 새 PR을 병합·배포하지 않는다.

진행 근거는 [10/19 D1·Play 점검 및 정리](reports/sul-36/2026-10-19-d1-playback-closeout.md)를 따른다. 기존 보고서의 예정·미완료 표기보다 이 문서의 상태가 우선한다.

## 별도 확인이 남은 한계

- 공개 결과는 확인했으나 정각 전후와 계속 열려 있던 countdown 탭은 실시간 관측하지 못했다. 이미 지난 정각 검증을 새 예약으로 복원하지 않는다.
- 관측 창의 계정 D1 증가227,431행·쓰기35행은 UI/API·자연 Cron·집계 지연이 섞여 개별 귀속이 확정되지 않았다. SQL14행만으로 화면 전체 비용을 설명하지 않는다. 로그 검색의 `statistics.rows_read`도 D1 비용이 아니다.
- 관리자 보관 화면의 ‘일반 공개 일정’ 문구는 저장 상태를 표시해 시간 정책으로 숨긴 일정에 혼동을 줄 수 있다. 일반 API 차단은 확인했으며 데이터 상태를 강제로 바꾸지 않는다.
- 별도 일반 회원 계정의 실제 관리자 우회 차단, 프로필 속도의 변경 전후 실측, 과거 R2 사고의 전체 영향·복구 판정은 완료로 올리지 않는다. [업로드 사고 기록](reports/sul-36/operational-upload-incident.md)을 보존한다.
- 기준 소스의 기존51개 실패에는 공개일 경계·고정 revision 기대와 CHZZK allowlist fixture 불일치가 포함된다. 전부 날짜 문제로 묶지 않는다. 최종 저장 시각 보호 조건을 완화하거나 테스트를 제외해 숨기지 않는다. 변경 범위 회귀와 구분해 기록한다.
