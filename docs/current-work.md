## 추가 기능 구현 — 빙하유 응원 펫

사용자의 실제 화면 확인 후 PR #173의 주간표 개선 구성을 되돌리고 **헤더 높이 6rem 고정만 유지**하도록 변경한다. 기준은 PR #173 직전 `770d9e4d`의 주간표이며 폰트·카드·열 너비·기념일 인라인 표시·스크롤 구성을 복원한다. 일간 응원 펫과 접기/펼치기 초점 수정은 그대로 유지한다. 이번 수정에 DB·migration 변경은 없고 운영 D1 작업이나 자동화 재개는 필요하지 않다.

사용자가 두 변경의 통합을 승인했다. 주간표 고정 헤더·접근성 개선과 아래 펫 변경을 기존 [PR #173](https://github.com/rlatmfrl24/overthewall-schedule/pull/173)에서 함께 검토하고 게시한다. 주간표 단독 검증을 통합 소스의 통과로 간주하지 않으며, 최종 통합 HEAD의 공식 preflight·양 사이트 빌드·실제 화면과 GitHub 판정은 해당 PR 검증 댓글이 소유한다. 이번 승인은 PR 준비까지이며 운영 D1 조회·변경·원격 migration·병합·배포와 자동화 재개는 포함하지 않는다.

`codex/luvdia-recovery-pet` 작업 트리에 LuvDia 일간 일정표의 플로팅 펫을 구현했다. 일반 방문자는 한국 현재 날짜 기준 2026-11-16부터 표시하고 11-15 이후 D+일수를 계산한다. 서버에서 확인된 관리자는 날짜 전에도 `관리자 미리보기`로 표시한다. 승인한 6종·각 5컷·3초 반복, 접기·펼치기, 기존 모션 설정 연동을 적용했다. 후속 요청에 따라 개별 일시정지를 제거하고 닫기 버튼을 하단 카드 오른쪽 끝에 맞췄다. 최종 코드 검토에서 잔여 중대한 지적이 없으며 34개 테스트·타입·린트·구조 검사·양 사이트 빌드와 실제 개발 관리자 화면을 재확인했다. 사용자 요청에 따라 이 변경만 인계 커밋으로 분리하고 **주간 스케줄 헤더 높이 고정** 세션의 기존 [PR #173](https://github.com/rlatmfrl24/overthewall-schedule/pull/173)과 함께 반영할 수 있도록 전달한다. 통합 후 최종 preflight와 PR 판정은 담당 세션에서 확인하며 운영 배포와 master 병합은 수행하지 않았다. ## 현재 승인과 제한

현재 추가 승인은 **`codex/d1-efficiency`의 PR 게시와 병합 전 점검**이다. 계정 합산 UTC 하루5,000,000행 기준을 유지하며 최종 검토 소스의 공식 preflight와 GitHub PR 상태를 확인한다. 점검 근거와 판정은 해당 PR 댓글에 기록한다. **운영 D1 조회·원격 migration·병합·배포는 승인되지 않았다.** 이 지시가 아래의 과거 로컬 전용·운영 승인 기록보다 우선한다.

직전 구현 작업은 **D1 조회 최적화의 격리 로컬 구현·검증**이었다. 계정 합산 UTC 하루5,000,000행을 기준으로9개 작업과 독립 리뷰 보완을 완료했다. [구현·비용·검증 보고서](reports/sul-36/2026-10-19-d1-efficiency.md)와 [실행 계획](superpowers/plans/2026-10-19-d1-efficiency.md)을 따른다. 당시 원격 SQL·업무 API·migration·수집·push·배포는 수행하지 않았으며, 운영 반영과 실제 하루 한도 준수는 미확인이다. Play 자동화 중지·LuvDia AI=false·공개/권한 정책과 기존 미커밋은 유지한다.

10/20 요청한 `codex/d1-efficiency` 최종 검토에서 프로필 접근 경합·검색 상태 무효화·선택기 페이지/기존 곡 판정·전체 게시 준비 오류를 수정했다. 수정 커밋 `c58d1f3`, 관련220개 사례 조합 PASS·양 사이트 빌드 PASS, 독립 재검토 잔여 지적0건이다. [최종 검토·수정 기록](reports/sul-36/2026-10-20-d1-efficiency-final-review.md)을 따른다. 실제 인증 관리자 흐름과 운영 하루 한도는 미확인이다. **운영 D1 조회·원격 migration·병합·배포는 아직 금지**이며 이전 운영 승인으로 재개하지 않는다.

직전 운영 요청은 **PR171 최종 검토 후 master 병합과 기존 미커밋의 유효 잔여 반영**이다. 빙하유 일정은 선택 날짜 기준 2026-11-15까지 정상 운영하며, 11-16 이후에는 저장된 일정이 있는 날짜만 공개하고 관리자만 변경할 수 있다. 기존 미래 일정과 대기 후보는 보존한다. 자동 수집·후보·휴방 제안·라이브 입력·재시도는 이후 날짜의 일정을 쓰지 않는다. 커버곡·게시글·프로필·영상·D-day와 OTW 정책은 유지한다. - 작업 범위 밖 미커밋 변경과 기존 보고서·데이터·마이그레이션 이력을 덮어쓰지 않는다. 이번 검토한 변경만 커밋하고 양 사이트의 리소스·보호 경계·자동화 중지 상태를 유지해 반영한다. OTW는 기존 병합 자동 배포, LuvDia는 동일 병합 소스의 검증 산출물을 사용한다. Play 공개와 자동화 재개는 별개다.

1. **D1 파일 접근 비용:** 경로 인덱스→소유 행 PK 조회로 수정했다. 실제 로컬 D1에서 무관한 공지10개→1,000개로 늘려도 요청당 수십 행을 유지한다. 공개·보관·공유 파일 회귀는 통과했으며 운영 감소는 배포 후 제한된 표본으로 별도 확인한다.

## 별도 확인이 남은 한계

- 공개 결과는 확인했으나 정각 전후와 계속 열려 있던 countdown 탭은 실시간 관측하지 못했다. 이미 지난 정각 검증을 새 예약으로 복원하지 않는다.
- 관측 창의 계정 D1 증가227,431행·쓰기35행은 UI/API·자연 Cron·집계 지연이 섞여 개별 귀속이 확정되지 않았다. SQL14행만으로 화면 전체 비용을 설명하지 않는다. 로그 검색의 `statistics.rows_read`도 D1 비용이 아니다.
- 관리자 보관 화면의 ‘일반 공개 일정’ 문구는 저장 상태를 표시해 시간 정책으로 숨긴 일정에 혼동을 줄 수 있다. 일반 API 차단은 확인했으며 데이터 상태를 강제로 바꾸지 않는다.
- 별도 일반 회원 계정의 실제 관리자 우회 차단과 과거 R2 사고의 전체 영향·복구 판정은 완료로 올리지 않는다. [업로드 사고 기록](reports/sul-36/operational-upload-incident.md)을 보존한다. 프로필의 현재 표시 시간·모바일 검증은 이번 기록을 따르며 측정이 없던 PR167 이전의 개선 배수를 추정하지 않는다.

## 다음 작업에 유지할 컨텍스트

- **미커밋 변경 보존:** 다른 작업의 변경을 잃지 않기 위한 기본 작업 규칙이다. 원본 작업 공간과 별도 X 작업 트리의 포함 관계를 검토하기 전에는 삭제·일괄 배포하지 않는다. 상세 파일 수·해시·경로는 보고서에 두며 매 요청에 복사하지 않는다.
- **X 최적화:** 운영 반영된 기능을 다시 구현할 일이 아니다. 빈 작업11행·미래 재시도7행의 회귀 계약만 유지한다. 별도 미커밋 X 작업 트리는 위 일반 보존 규칙을 따르며 영구 보관 의무나 종료된30일 추적을 새로 만들지 않는다.
- **대량 작업:** 계정 한도 사고와 작업별 비용 미산정 때문에 계속 보류한다. 공개·이번 수정에 필요한 최소 schema/인덱스 표본과 전수 이관·백필은 구분한다. 다시 필요해지면 범위·예상 비용·중단 기준·승인을 먼저 정한다. 이관 완료를 재이관 의무로 바꾸지 않는다.
- **Play·AI 자동화:** 사용자의 명시적 중지 결정을 유지한다. 자동 수집은 외부 호출·D1 쓰기·복구/적체를, AI는 유료 호출·결과 적용을 수반한다. 기능 전체가 고장 났다는 뜻은 아니다. OTW AI 기능 binding은 true, LuvDia는 false이며 수동 기능 설정과 자동 실행 중지는 구분한다. 이번 배포에서 새 실행·재개·과거 기간 소급을 하지 않는다. 재개 요청이 생길 때 품질·예산·작업 범위와 중지 기간 처리를 별도로 확인한다.

지금 컨텍스트에는 이 네 항목의 짧은 규칙만 유지하면 된다. 공개 전 countdown·완료 관측 예약·이관 실행부 제거·원본 파일 수 등 완료 이력은 증거가 필요할 때 보고서를 참조한다. 과거 D1 전면 중단이나 PR165 병합 대기 문구를 현재 승인보다 우선하지 않는다.

## 계속 보류할 작업과 참조

LuvDia 재이관·재복사·대량 검증·백필, 전면 아키텍처 개편, 유료 AI 품질 검증, Play/AI 자동화 재개는 보류한다. 대표곡 pin·참여 정보 정정/가창 병합·setlist·전용 멀티뷰 확장 등 후순위 요구는 [참조 문서](reference.md)에 유지한다. 이관 완료나 종료된 X 비용 추적 의무를 미완료로 되살리지 않는다.

새 작업은 README→이 문서→필요한 담당 기능 문서 순서로 시작한다. 과거 실행·실패·계획은 [아카이브](archive/README.md)에서 증거가 필요할 때만 읽는다. 원본 작업 공간·X 작업 트리·기존 보호 보고서는 정리 대상이 아니다.
