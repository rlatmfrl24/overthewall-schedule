# OTW Play 가져오기·검수 재개편

## 작업 흐름

가져오기/검수의 기본 화면은 플레이리스트 작업이다. 기존 범위 지정 가져오기, 자동 수집 후보와 사용자 제안은 기타 검수·관리에서 연다.

1. 플레이리스트 추가 대화상자에서 여러 URL을 저장한다. 이 단계는 요약 정보만 조회한다.
2. 50개 초안 준비 또는 이어서 검수로 현재 묶음을 연다. 준비가 끝나면 원래 순서의 첫 미처리 항목으로 이동한다.
3. 영상과 곡·원곡 가수·가창자·구간·방송일 요약을 확인한다. 정상 초안은 확인하고 다음 한 번으로 검수를 저장한다.
4. 곡 검색·참여자·구간 수정, AI 근거·재분석, 메모와 게시 미리보기는 필요할 때 펼친다. 필수 누락·모호한 AI 결과는 바로 표시한다.
5. 보류하고 다음 또는 제외 사유를 명시적으로 선택한다. 추가 메모는 기타 사유일 때만 필수다.
6. 묶음 결과에서 비공개 등록하고 다음 50개 또는 비공개 등록하고 쉬기를 선택한다. 이 화면이 최종 확인이며 중복 확인창은 없다.

중간에 나중에 이어하기로 나가도 저장된 검수와 현재 묶음은 유지된다. 저장하지 않은 입력은 기존 이탈 경고와 마운트된 검수 폼으로 보호한다. 재로그인 후에는 서버에서 현재 묶음의 첫 미처리 항목을 복원한다.

검수 저장은 Ready 및 곡·참여자 식별자 저장이다. 묶음 등록은 가창과 source의 비공개 draft 생성이다. 공개는 카탈로그에서 별도로 실행한다. 사용자 제안의 승인·게시는 독립된 의미를 유지한다.

## 진행률 계약

- 전체 처리율: 현재 확인 회차의 등록·제외된 목록 항목 / 회차 시작 때 확인한 목록 항목 수.
- 이번 묶음 진행률: 검수 저장·등록·제외·명시적 보류된 항목 / 현재 페이지 항목 수.
- 목록 확인: 현재 회차에서 발견한 playlist item ID의 수. 같은 항목을 재전달해도 누적하지 않는다.
- 같은 영상의 여러 playlist item은 각각 진행률 한 칸을 가지며, 후보·AI·검수 결과는 공유한다.
- Ready와 보류는 전체 처리 완료에 포함하지 않는다. 마지막 페이지 도달도 전체 처리 완료를 의미하지 않는다.
- 회차 진행률과 별도로 `deferredCount`는 이전 회차까지 남은 보류 검수의 수다. 보류 목록과 동일한 중복 제거 기준으로 계산한다.
- 영상 ID가 없는 식별 가능한 목록 항목은 후보 없이 보존하고 관리자가 보류·제외한다. 모델에는 전달하지 않는다.
- 목록 수 변경·비정상 응답·과거 기록 불완전은 진행률 확인 필요로 표시한다. 임의로 100%를 만들지 않는다.

새 항목 확인은 새 회차로 시작하고 기존 검수·등록·보류 기록을 재사용한다. 과거 회차의 읽은 수를 새 회차에 합산하지 않는다. 30일이 지난 요약 정보는 만료 처리한다.

## 구조와 복구

기존 수집 Queue와 AI Queue, 검수 폼·저장·비공개 등록 서비스를 재사용한다. 한 번에 전역 활성 묶음 하나와 YouTube 한 페이지 최대 50개를 유지한다. 일반 검수의 필터 전체 AI 실행은 작업 큐 소속 후보를 제외하고 해당 작업 화면으로 연결한다.

작업 URL은 큐·묶음·목록 항목·선택 후보를 보존한다. 채널 설정 또는 연결 제안을 다녀와도 같은 항목으로 돌아온다. 보류 조회는 선택한 플레이리스트에 한정하고 이전 묶음의 저장 결과를 다시 연다.

서버는 버전과 멱등 키를 검사한다. 응답 유실 후에도 같은 완료 명령을 복구하고, 서버의 다음 묶음 연결을 읽어 이동한다. 부분 등록 성공은 보존하며 등록 재시도는 모델을 다시 호출하지 않는다. 조회·새로고침은 분석을 시작하지 않는다.

0100 마이그레이션은 후보 없는 작업 항목과 위치·회차 필드를 추가한다. 0101은 기존 항목·위치·검수·보류를 유지하면서 과거 순회를 구분한다. 이전 전체 목록 스냅샷을 확증할 수 없으므로 이전 기록의 퍼센트는 확정하지 않는다.

### 실제 관리자 흐름

로그인된 `localhost:5173/admin/otw-play`에서 일반 검수함으로 이동하지 않고 아래 흐름을 수행했다. 로컬 데이터만 변경했으며 게시하지 않았다.

- URL 일괄 추가: 동일 URL 중복을 합치고, 잘못된 입력은 행별 오류로 표시했다. 형식상 ID인 접근 불가 입력은 정보 조회 실패를 큐 행에 표시했다. 해당 검증용 기록은 보관했다.
- 두 번째 묶음의 첫 초안 `334JRDlhitc`를 기존 마리골드 곡에 연결해 확인하고 다음으로 저장했다. Ready와 메모를 D1에서 읽고, 다음 곡 및 `1/50` 표시를 확인했다.
- 실제 구간 재생이 시작 20초 및 종료 276초를 사용했다. 음악 내용 전체를 검증한 것으로 처리하지 않고 가창 범위를 미확인으로 저장했다.
- 새로고침 후 이어서 검수로 첫 미처리 곡을 복원했다. 나머지 49개는 관리자 추가 검수 대기 사유를 명시적으로 선택해 보류했다.
- 같은 화면의 `등록 예정 1 · 보류 49` 결과에서 비공개 등록하고 다음 50개를 실행했다. 중복 확인창 없이 등록 후 마지막 29개 페이지로 이동했다.
- 등록 가창 `28c78680-5a60-495a-a241-d84b0227d0ac`를 D1에서 `draft`로 재조회했다. 곡 ID `3d900554-b345-45e5-b0d3-576c366841bb`를 재사용했다. 실제 카탈로그에도 기존 두 가창과 함께 임시 저장 3개로 표시됐다.
- D1의 세 페이지는 위치 `0–49`, `50–99`, `100–128`, 항목 수 `50/50/29`였다. 마지막 페이지의 기존 등록·저장된 검수 결과 6개를 재사용하고 23개만 AI 대상으로 지정했다. 최종 AI 결과는 저장됨 22개·선택 필요 1개다.
- 완료된 첫 묶음의 보류 검수를 열고 채널 화면 왕복 후 같은 항목·작성 중 메모를 복원했다. 외부 관리 화면으로 이동할 때 이탈 경고, 보류 대화상자의 Esc 종료 후 원래 버튼 초점을 확인했다.
- 현재 패널 880px와 좁은 390px에서 가로 넘침을 확인했다. 영상과 요약이 겹치던 폭을 수정했다. 390px 고정 버튼 높이 121px를 콘텐츠 여백으로 확보했다.

화면 증거는 로컬 `.wrangler/play-redesign-summary.jpg`, `play-redesign-final-screen.jpg`, `play-redesign-narrow.jpg`, `play-redesign-catalog.jpg`에 저장했다. 권위 데이터는 `play-redesign-catalog-final-readback.json`과 `play-redesign-state-final-readback.json`이다.

### 자동 검증과 검토

- 관련 유닛·소비자 12파일 189건 PASS. 이후 변경된 검수 폼 19건, 작업 패널 9건, 빈 자동 검수함 1건을 해당 경로별로 재실행해 PASS했다. 전체 유닛 명령의 재실행으로 표현하지 않는다.
- 실제 Worker D1 통합 3파일 49건 PASS. 최종 수집 사유 보존 변경 후 작업·수집 2파일 37건을 다시 실행해 PASS했다. 부분 등록 실패·동시 관리자·멱등 완료·재전달·재확인·정보 만료·후보 없는 항목을 포함한다.
- 앱·Worker·테스트·Node 타입, 변경 코드 lint, 아키텍처 검사, agent 동기화 검사, 빌드·SEO 생성 PASS. 빌드의 관리자 청크 500kB 초과 경고는 남아 있다.
- 등록 후 최종 D1 doctor PASS: 가창 20개·정렬 키 20개, 검색 인덱스 불일치 0건. `foreign_key_check` 결과 0건이며 활성 묶음은 하나다.
- 독립 코드 검토에서 과거 보류의 완료 후 자동 이동(P1)과 공유 후보의 과거 행을 통한 등록 잠금 우회(P2)를 확인했다. 실패 테스트를 먼저 재현하고 수정해 통과시켰다. 저장 완료 후 이미 떠난 화면으로 이동하는 경로도 차단했다.
- 반복 작업에서 비활성 폼은 입력 상태를 유지하고 DOM만 제거한다. 실제 36개 폼의 DOM 약 9,266개가 현재 폼 1개·약 638개로 감소했다. 입력 복원 회귀 테스트를 유지한다.
- 기존 회차 스냅샷의 근거가 부족한 기록은 진행률 확인 필요 상태를 유지한다. 새 회차에서는 이전 읽은 항목을 누적하지 않는다. 영상 ID가 없는 항목의 기존 보류·제외 사유도 재확인 시 보존한다.

네트워크 응답 유실·동시 관리자·부분 등록 실패는 자동 회귀 및 실제 D1 테스트로 검증했다. 실제 브라우저에서 별도 관리자 세션과 네트워크 장애를 강제로 만들지는 않았다. 재로그인 자체는 반복하지 않았으며 기존 로그인 세션의 새로고침 및 서버 상태 복원을 확인했다. 접근성 전체 인증과 전체 플레이리스트의 음악적 검수는 수행하지 않았다. 실제 AI 초안에서 연도 추정 오류가 보였으며 해당 항목은 보류로 남겼다.

운영 D1 적용·배포·커밋·푸시는 별도 릴리스 작업이다. AI 추정 사실은 관리자 확인이 필요하며 전체 접근성 준수를 이 문서로 보증하지 않는다.
