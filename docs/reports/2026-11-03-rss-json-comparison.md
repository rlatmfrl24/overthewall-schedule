# 멤버 8명 RSS·현재 JSON 실제 비교

- 측정일: 2026-11-03 KST. 코드 기준 `a6b9463111eba8c8a40a27856da55d2a74fce69e`.
- 사용자 범위: 실제 공개 응답 비교와 설계 검토. **구현·통합·배포·공식 유료 호출·DB/설정/구독 변경·commit/push는 보류한다.** 기존 브랜치와 로컬 검증 데이터를 보존한다.
- 사용자 확정 조건: 무료 수집 우선, 공식 API로 누락 보완, 허용 복구 지연 24시간 이내. 웹훅 기능은 남기고 기본 Disabled이며 필요시 관리자가 활성화한다.
- 이 문서는 실측 보고서다. 아래 설계 제약은 최종 설계 승인이나 기존 운영 주기 변경이 아니다.

## 결론

**이번 표본에서는 JSON을 기본 수집으로 유지하는 쪽이 유리하다.** RSS는 목록 HTTP 요청을 4분의 1로 줄였지만, 공개 피드 기준 160건 중 JSON과 똑같은 153건을 발견하고 같은 7건을 놓쳤다. 최근 24시간 창에서 JSON보다 추가로 발견한 RSS 글은 0건이었다. 전체 기간에서는 RSS에만 있는 유효 글 13건이 있으므로 RSS의 보완 가치가 항상 0이라고 결론 내리지는 않는다.

두 번째 RSS는 하루의 대상 글이 58→20건으로 줄었는데도 HTTP 200이었다. JSON은 두 관측에서 같은 79건을 유지했다. RSS만으로 전체 탐색 완료를 판단하거나 독립 공식 대조를 없애는 근거가 되지 않는다. 약 4분의 비교이므로 장기 가용률·월 비용 절감률을 입증한 것은 아니다.

## 실제 비교 방법

1. 두 운영 사이트의 공개 `/api/members`에서 현재 정상 공개·비활성화되지 않은 X 멤버를 확인했다. OTW 5명, LuvDia 3명이다.
2. 각 멤버의 공개 `/api/x/posts?handles={handle}&maxResults=20`를 한 번씩 읽어 20건×8명=160건의 기준 응답을 고정했다. 공개 조회는 기존 D1 읽기 경로다. 이 기준은 **서비스가 이미 알고 있는 글**이며 현재 X 전체의 정답 집합이 아니다. 8개 응답은 짧은 순차 조회로 확보했으며 하나의 원자적 DB snapshot은 아니다.
3. RSS는 `https://fxtwitter.com/{handle}/feed.xml?count=100&with_replies=true`를 계정당 한 번 요청했다. JSON은 현 [요청·파서](../../worker/features/x-posts/infrastructure/fx-api.ts)의 `count=20&with_replies=true`, 작성자 numeric ID·handle·공개 여부·리포스트 제외·날짜/미디어 검증을 그대로 사용해 계정당 최대 4페이지를 읽었다.
4. 비교를 위해 JSON은 **두 관측 모두 cursor=null에서 시작하는 제한 탐색**이다. 실제 [수집기](../../worker/features/x-posts/infrastructure/fx-collection.ts)를 실행하지 않았고, DB의 pending cursor·활성화 이후 필터·저장·공식 진행 상태는 변경하지 않았다. 아래 발견 수는 일반 백필을 승인하거나 신규 저장 수를 뜻하지 않는다. 현재 수집기의 모든 상태를 재현한 실행 성능 시험도 아니다.
5. RSS는 XML을 실제 파싱하고 GUID의 글 ID·대상 handle·날짜를 검증했다. 다른 작성자 문맥을 제외하고 ID를 중복 제거했다. RSS에 numeric 작성자 ID·리포스트 표시가 없으므로 JSON과 겹치는 ID 및 별도 공개 개별 조회로 대상 작성자와 비리포스트 여부를 확인했다. RSS 단독 13건은 모두 이 검증을 통과했다.
6. 1차는 RSS→JSON, 2차는 JSON→RSS 순서다. 같은 계정 RSS의 두 요청 간격은 162–178초로, 응답의 `max-age=120`을 넘었다. 최대 동시 HTTP 요청은 2개이며 재시도·캐시 우회 query·로그인·개인 쿠키·공식 X API 키를 사용하지 않았다. 캐시 TTL 경과가 upstream 갱신을 증명하지는 않는다.

기준 응답 확보는 UTC `09:22:32–09:22:43`, 두 수집 비교는 `09:22:43–09:26:24`(KST 18:22–18:26)에 수행했다. 최근 24시간 창은 기준 고정 시각 `2026-11-03T09:22:43.904Z`에서 24시간 전까지로 고정했다. 알려진 ID 진단은 뒤이어 UTC `09:26:38–09:27:34`경에 별도로 수행했다.

## 8명별 발견·미발견

`RSS 1→2`와 `JSON 1→2`는 대상 작성자의 고유 글 수다. 두 열의 목록 기간은 같지 않다. RSS의 총 100항목 상한과 JSON의 4페이지 상한이라는 실제 설정 차이를 포함한다. `기준 재발견`은 각 방식·각 관측이 모두 같은 값을 보였다.

1차 두 방식의 공통 글은 433건, 합집합은 511건이다. 2차 JSON 단독은 103건으로 늘었다. 이는 RSS 발견 범위가 줄어든 영향이며 X의 실제 삭제·원인을 확정한 것이 아니다. JSON 고유 ID 집합은 두 관측에서 같았다.

RSS 단독 13건은 나츠키 10월 19일 1건, 하네 9월 12일 2건, 메이 3월의 10건이다. 모두 최근 24시간 밖이다. 백필을 추가할 근거로 사용하지 않는다. RSS에는 1차 원시 800항목 중 다른 작성자 문맥 354개, 2차 735항목 중 327개가 있었다. JSON은 각 관측 원시 913항목, 대상 글의 페이지 간 중복 16개를 중복 제거해 498건이 됐다.

### 최근 24시간과 성공 응답의 범위 축소

| 관측 | RSS 대상 글 | JSON 대상 글 | RSS가 JSON에 더한 글 | JSON이 RSS에 더한 글 |
| --- | ---: | ---: | ---: | ---: |
| 1차 | 76 | 76 | 0 | 0 |
| 2차 | 52 | 76 | 0 | 24 |

전체 기준 160건 중 최근 24시간 글은 54건이고, 그중 같은 5건이 양쪽에서 미발견이었다. 76건을 전체 X의 최근 24시간 게시물 수로 해석하지 않는다. 공개 기준은 계정당 20건으로 제한돼 있으므로 이 수치의 분모와 다르다.

하루 RSS는 원시 100→35항목, 대상 글 58→20건으로 축소됐다. 두 응답 모두 유효 XML·HTTP 200·`Cache-Control: public, max-age=120`이었고, ETag/Last-Modified/Link 헤더는 없었다. 외부 next cursor나 전체 탐색 완료 표시는 없었다. JSON은 같은 계정의 최근 24시간 글 44건을 계속 반환했고, RSS는 44→20건이었다. 내부 페이지 실패·공급자 결과 변동·캐시 중 어느 원인인지는 공개 응답만으로 판정하지 않는다.

## 요청 횟수·응답 크기

| 항목 | 1차 | 2차 | 합계 |
| --- | ---: | ---: | ---: |
| RSS 목록 | 8 | 8 | **16** |
| JSON 목록 | 32 | 32 | **64** |
| 기준 확인 | 멤버 목록 2 + 공개 글 8 | 재사용 | 10 |
| 뒤이은 개별 진단 | RSS 단독 13 + 양쪽 미발견 7 | 중복 없이 한 번 | 20 |

본 실험 기록은 총 110 HTTP 요청이다. 별도 사전 공개 형식 확인 3회를 포함하면 이 작업의 데이터 요청은 113회다. 문서·원본 소스 열람은 수집 요청 비교에 포함하지 않는다. 공식 유료 X 호출은 **0회**다. 목록 80회는 모두 HTTP 200, 진단 20회는 200 19회/404 1회였다. 200 비율을 장기 정상 수집률로 해석하지 않는다.

RSS는 목록 클라이언트 요청이 JSON 대비 **75% 적었다**. 그러나 RSS 원본은 한 번의 HTTP 안에서 같은 공급자의 타임라인을 최대 10페이지 합칠 수 있다. 내부 실제 호출 수·캐시 hit·프로필 등 부수 호출·운영 비용은 측정하지 않았다. 클라이언트 요청 감소를 X 청구 감소나 upstream 부하 75% 감소로 옮겨 쓰지 않는다. [동일 공급자·내부 페이지 상한](https://github.com/FxEmbed/FxEmbed/blob/f6a2ca986cfdc3728fe826abe124a107ebd82c46/packages/atmosphere/src/providers/twitter/userStatuses.ts#L223-L320)

| 관측값, 두 회 합계 | RSS 16요청 | JSON 64요청 |
| --- | ---: | ---: |
| 압축 해제 후 UTF-8 본문 | 922,764 bytes | 5,038,635 bytes |
| 개별 요청 중앙값 | 5,092 ms | 1,431 ms |
| 개별 요청 최소–최대 | 2,178–9,911 ms | 823–12,419 ms |

본문 크기는 wire 전송량이 아니다. JSON은 더 많은 구조·글을 제공하며 RSS를 본문·첨부·관계 DTO로 검증·보강하는 비용을 포함하지 않았으므로 동일 데이터 압축률·완성된 카드당 비용 비교가 아니다. 중앙값도 서로 다른 작업량의 짧은 요청 표본이다.

## 설계에 반영해야 할 제약

- **RSS와 JSON의 역할:** JSON은 작성자 numeric ID·첨부·관계·cursor 재개를 제공한다. RSS는 보조 발견 후보로 활용하되 HTTP 200·최신 게시 시각만으로 전체 성공/완료를 판단하지 않는다. 이번에 관측한 RSS 단독 글의 가치는 전체 13건/최근 24시간 0건으로 구분한다. RSS 기본 전환과 매주기 동시 실행은 이 실측만으로 최적이라고 판단하지 않는다. [공식 RSS 안내](https://docs.fxembed.com/guide/advanced/rss-atom-feeds/), [JSON 타임라인](https://docs.fxembed.com/api/twitter/operations/2profilehandlestatuses/)
- **누락 복구:** RSS/JSON이 알려 준 새 ID·불완전 항목은 먼저 무료 JSON으로 검증/보강한다. 무료 양쪽이 모르는 ID는 공식 독립 타임라인으로 발견해야 한다. 무료 최신 ID를 공식 완료 cursor로 복사하지 않고, 예산·저장 실패·미완료 페이지를 보존한다. 무료 재생으로 공식 확인 필드·숨김·삭제를 되돌리지 않는다.
- **24시간 요구:** 사용자 조건은 24시간 이내 복구다. 공식 24시간 주기는 실행·오류 여유가 없어 같은 보장이 아니다. 공식 12시간 대조는 여유를 두는 미승인 제안이며 실측 최적값은 아니다. 고정 공통 UTC $1 목표와 사이트/D1/Queue 보호, backoff·pending이 있으면 24시간 상한이 불가능할 수 있으므로 위반 상태를 명시해야 한다. 조용한 계정을 실패로 처리하거나 자동 예산 증액으로 요구를 맞추지 않는다.
- **절감 가능 범위:** 무료 확보 글을 공식이 반환하면 과금될 수 있다. 현재 공개 Post Read 단가 $0.005를 적용한 100글/일은 Post Read만 월 30일 $15, 200글/일은 $30인 조건부 예시다. User/확장 자원·이벤트·재조회·계정 실제 청구를 포함한 견적이 아니다. $1로 Post Read만 최대 200건이라는 산술이 현재 보수적 선예약·정산을 완화할 근거가 되지 않는다. [공식 자원별 요금](https://docs.x.com/x-api/getting-started/pricing#read-operations)
- **웹훅:** 기본 Disabled·원격 소유 유료 구독 없음 확인을 유지하면서 endpoint·CRC·인증·이력은 보존한다. 관리자의 명시적 활성화와 기본 수집원은 별개 제어로 설계해야 한다. 현재 Fx 기본 모드의 start/resume 409는 최신 요구와 다르므로 후속 설계에서 수정 대상으로 다룬다. 이번에는 원격 구독·코드를 변경하지 않았다. [공식 복구·과금 조사](../research/2026-11-03-x-free-first-recovery-options.md)

JSON 기본+저빈도 RSS와 RSS 기본+JSON 검증/보강이라는 두 대안을 사용자에게 제시했고, 후속 답변에서 사용자가 **JSON 기본+저빈도 RSS**를 선택했다. [상세 설계서](../superpowers/specs/2026-11-03-x-free-first-collection-design.md)를 작성했으며 권고 주기인 JSON 30분·RSS 6시간·공식 12시간은 여전히 설계 승인 대상 제안이다. 기존 구현·운영 설정을 덮어쓰지 않으며 구현·통합·배포 보류는 설계 선택만으로 해제되지 않는다.
