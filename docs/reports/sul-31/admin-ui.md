# 관리자 UI 통합·분리 구현 및 검증

2026-09-23. 사용자 지정 SUL-31 브랜치의 작업 트리. 기준 HEAD `4e8daa61492a6ea42e82da3d7ca7885038314e1d`; 이 보고서는 배포된 산출물에 대한 검증이 아니다.

## 변경 결과

관리자 7개 업무 경계를 유지했다. 기존 21개 하위 화면 중 사용자 곡 요청을 가져오기/검수의 사용자 제안 출처로 통합해 **20개 하위 화면 + 대시보드**가 된다. 후보의 Ready→임시 등록→게시와 제안의 확인→승인·게시를 별도로 유지한다. 완료 제안은 처리 시각·사유를 읽기 전용으로 확인한다.

- 관리자 전용 따뜻한 백색/차콜 토큰, 시스템/Pretendard 글꼴, Phosphor Bold 아이콘, 얇은 테두리, 모바일 터치 영역. 대화상자·메뉴 포털에도 테마 적용. 공개 화면과 스냅샷 출력은 유지.
- 모바일 업무명과 하위 화면 선택기. 공통 제목/설명/주 작업/조회 시각. 기본 플레이리스트와 스냅샷에도 페이지 제목 추가.
- 대시보드 동일 원인의 경고 묶음, 대상별 근거 펼치기, 사람 검토/자동 처리 구분, 중복 Queue 수치 제거, 출처·상태가 지정된 처리 링크.
- 일정 검수의 반복 통계·수집 실행을 줄이고 수집 설정으로 연결. 회원 곡 제안 한도와 Play 전체 자동화 제어는 Play 운영으로 이동.
- X/카페의 중복 새로고침 제거, 설정 다음 최근 결과 배치, 소스 필터를 지정한 실행 이력 링크. YouTube 신규 피드와 요청 시 캐시 갱신 작업 영역 분리.
- 목록 행의 삭제는 보조 메뉴에서 기존 확인창으로 연결. 폼의 임시 행 제거와 이미지 정리 화면의 주 작업은 바로 표시.
- 제안은 명시적으로 선택할 때만 상세 조회. 목록 왕복에서 입력 유지, 서버 버전 충돌 시 입력 유지, 최신 데이터 재시작은 확인 후 수행.
- 사용자 제안 출처에서는 후보용 일괄 등록 안내를 숨기고 제안 전용 승인 절차를 안내. 연결된 후보/제안은 기존 대표 행과 처리 경로 유지.
- 기존 제안 주소는 `tab=import&source=user&view=inbox` 또는 선택 ID의 `view=proposal`로 연결. 완료된 옛 제안 주소도 읽기 전용 상세로 연결.

UI 변경을 위한 서버 API나 DB migration은 추가하지 않았다. SUL-31의 기존 migration/API/예산 정책/Ready catalogChanges/첫 페이지 커서 재구성은 유지한다. 완료 제안 상세는 기존 제안 조회 API를 명시적 선택 시 사용하며, 대기 목록에는 전체 이력을 선조회하지 않는다.

## 자동 검증 및 한계

- 변경 영역 14개 파일 133개 테스트와 Ready 캐시·커서 회귀 3개: 최종 관련 재실행 포함 통과. 제안 명시적 선택/왕복 입력 유지/완료 상세, 거절·승인 실패, URL 호환, 다음 후보의 권위 ID 재사용, 부분 실패, 커서 초기화, 플레이리스트 충돌/입력 유지 포함.
- 긴 기존 등록 시나리오는 5초 기본 제한에서 시간 초과했다. 개별 재실행에서 6.47초 정상 완료를 확인하고, 변경 범위 실행에 `--testTimeout=20000 --maxWorkers=2`를 사용했다. 제품 동작/검증 조건은 완화하지 않았다.
- TypeScript 프로젝트, test/Worker/Node 타입, 변경 파일 ESLint, Vite 빌드, architecture, agent sync 검사 수행.
- 실제 두 후보의 동일 ID 재사용은 위 연속 UI 저장과 D1 readback으로 확인했다. 새 곡·주체 생성 응답이 전체 카탈로그 재조회 없이 즉시 캐시에 반영되는 것은 Ready 캐시 회귀 및 이전 [SUL-31 실흐름·D1 검증](README.md)도 함께 근거로 사용한다.
- 삭제 확인창은 기존 회귀 테스트로 검증했으며, 실제 로컬 데이터 영구 삭제는 수행하지 않았다. 실제 동시 관리자 충돌/부분 실패는 회귀 테스트 범위다.
- 로컬 Analytics 설정 부재에 따른 경고 후 진행은 확인했다. 실제 계정 UTC 예산 차단/자정 회복, 운영 Insights 절감 효과는 운영 적용 후 검증 대상이다.
- 운영 배포/인덱스 적용/계정 설정은 수행하지 않았다. SUL-31 운영 적용은 기존 보고서대로 인덱스 migration 후 호환 코드 배포 순서를 유지한다.


## 브라우저 피드백 6건 반영 (2026-09-23)

- 대시보드 경고의 영향·조치·대상별 근거·진단 코드를 기본 노출하고 행 간격을 줄였다.
