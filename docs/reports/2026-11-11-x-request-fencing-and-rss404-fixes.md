# 요청 확정·이전 회차 차단 수정과 RSS 404 조사

2026-11-11. 기준 HEAD `236fd3495c367364ef53959e3c576375c77d72e4` 위의 기존 미커밋 변경을 보완했다. [직전 리뷰](2026-11-11-x-sequence-generation-review.md)에서 재현한 3건을 수정하고, 사용자가 확인한 **X 수집 실행 기록의 간헐적 404**를 조사했다.

운영 설정·배포·원격 DB 변경·신규 공식 X 유료 호출·커밋·push·PR·병합은 수행하지 않았다. 운영 진단은 기존 기록의 SELECT와 공개 무료 RSS의 제한된 조회로 진행했다. 12시간 주기·정상 즉시 Queue 재개·저장 글 재조회 방지·실행당 D1 50회 정책을 유지했다.

## 재현한 3건의 수정

| 문제 | 수정 | 확인 결과 |
| --- | --- | --- |
| 구간 조회 후 요청 기록 확정 직전 Fx 저장 | 요청 checkpoint UPDATE가 예상 저장 순번을 같은 SQL에서 비교한다. 달라졌으면 같은 UPDATE로 재분할 상태를 저장한다. | fresh/token 요청 모두 이미 저장된 110의 신규 공식 조회 0회. 즉시 재개 후 누락 105 복구 및 확인 지점 완료. |
| 이전 제어 메시지가 새 재시도를 실패 처리 | 제어 메시지에도 회차를 전달한다. 실행 요약의 내부 회차를 수동 재시도마다 올리고, 실패·제한·skip·계획 INSERT·계획 요약 쓰기에 예상 회차를 확인한다. | 계획 전의 빈 실행과 이미 계획된 실행을 모두 보존한다. 이전 계획·이전 예산 판단이 늦게 끝나도 새 실행을 변경하지 않는다. |
| 이전 outbox의 예산 거절이 새 실행 전체를 제한 | 예산 거절 쓰기를 해당 outbox ID·임대 토큰·임대 유효기간·항목 회차에 묶는다. | 유효한 현재 거절은 기존 제한 처리를 유지하고, 새 회차 또는 다른 임대의 전송에는 쓰지 않는다. |

요청 순번 불일치는 정상적인 경합으로 처리해 즉시 후속 Queue를 만든다. lease 유실·DB 저장 오류는 실제 실패로 남으며 새 유료 요청이나 공식 확인 지점 전진이 없다. 기존 정산 응답은 같은 요청으로 재생한다.

제어 회차는 기존 `summary_json.controlGeneration`에 보관해 추가 스키마 변경이 없다. `updateRunSummary`는 이 값을 보존하고, 운영 화면에 반환하는 요약에서는 내부 회차를 제외한다. 회차가 없는 기존 제어 메시지는 0으로 해석한다. 새로운 재시도는 증가한 회차를 전달한다.

기존 3건의 영구 회귀를 먼저 실패시킨 뒤 수정했다. 계획 중 회차가 바뀌는 추가 경합도 SQL 조건으로 보호했다. 독립 재검토에서 이전 제어 DLQ·이전 전송 거절·usage 조회 뒤 경합·빈 계획 skip·오래된 대상 INSERT 등 실제 로컬 D1 6개 회귀가 통과했다.

## 운영 404에서 확인한 사실

보존된 실행 기록의 RSS 404는 OTW 17건, LuvDia 7건이었다. 이 시점의 JSON 타임라인 404는 11/4의 과거 기록이었다. 최근 404는 `fxembed:rss_candidates:*`의 RSS 첫 요청에서 발생했으며 후보 조회 전 상태였다. 이후 정상 수집 이력도 확인했다.

실패 경로는 `https://fxtwitter.com/{handle}/feed.xml?count=100&with_replies=true`다. 같은 오류 계정 3개의 기존 주소를 조회했을 때 모두 200이었고, 실제 RSS 응답을 기존 파서로 읽은 결과는 다음과 같다.

| 계정 | RSS 전체 항목 | 본인 후보 |
| --- | ---: | ---: |
| terri_nunna | 100 | 53 |
| kurenai_natsuki | 100 | 23 |
| yangmei1126 | 100 | 43 |

과거 실패의 응답 본문이 보존되지 않았고, 공식 RSS 처리도 실패 본문을 비우므로 공급자 내부의 handle 해석 실패인지 타임라인 응답 부재인지 확정할 수 없다. **확인한 원인은 무료 RSS 공급자가 일시적으로 404를 반환하는 경로이며, 앱이 첫 404에서 바로 해당 실행을 중단했다는 점**이다. 공급자 내부 장애를 해결했다고 주장하지 않는다.

공식 [RSS 처리 소스](https://github.com/FxEmbed/FxEmbed/blob/main/src/realms/twitter/routes/feed.ts#L167-L179)는 비정상 응답에 `Cache-Control: no-store`를, 정상 RSS에만 캐시를 지정한다. [외부 RSS 라우터](https://github.com/FxEmbed/FxEmbed/blob/main/src/realms/twitter/router.ts#L109-L115)는 `id:`의 콜론을 허용하지 않는다. 내부 파서의 지원만 보고 ID RSS 경로로 바꾸면 안 된다. 실제 ID 주소 3개도 302였으므로 사용하지 않았다. 공급자의 현재 배포가 공개 main 소스와 같은지는 확인하지 않았다.

## RSS 404 보완

RSS의 실제 HTTP 404에 한해 **동일 HTTPS URL을 한 번만 다시 요청**한다. 첫 응답의 스트림은 정리한다. 리디렉션 차단, 계정 확인, XML 검증, 원문 저장 및 checkpoint 보호는 유지한다. 두 번째도 404이면 `fx_http_404`와 재시도 대기를 보존한다. 302·401·429·500·잘못된 XML·저장 오류는 이 재시도 대상이 아니다. 공식 API로 자동 전환하는 기능을 추가하지 않았다.

실제 캡처한 RSS 3개를 `404 → 캡처한 200`으로 현재 어댑터에 재생했고, 모두 같은 URL 2회에서 정상 파싱 결과와 일치했다. 이 재생 단계의 추가 외부 요청은 0회다. 재생한 어댑터 SHA256은 `e385be0137f88c34d0348917120febb4c06f17c58fa1ab09e4e477d9e4f5392c`다. 이는 운영에서 실제 404 직후 재시도로 회복하는 모습을 관측한 증거는 아니다.

## 로컬 검증

Node 24.20.0, 실제 로컬 D1, 정상 Worker Queue handler와 전송 완료 기록까지 계측했다. 공식 X 및 Cloudflare 예산 응답은 검증 환경에서 모의 응답이며 실제 유료 호출은 0회다.

| 사례 | 결과 |
| --- | --- |
| 기존 공식 보완 ID | 4/4 복구 및 확인 지점 완료 |
| fresh/token 요청 확정 직전 Fx 저장 | 중복 공식 조회 없이 즉시 재분할·재개 |
| 재분할 직후 중단·추가 동시 저장 | 양쪽 누락 복구, 확인 지점 완료, 다음 확인 +12시간 |
| 요청 확정 직전 lease 유실·DB 오류 | 실패 유지, 새 유료 조회 0회·확인 지점 보존 |
| 원문 캐시 만료·작성자 적중/미적중 혼합 20건 | Queue 16회, D1 최대 49회 |
| 같은 혼합 20건에서 첫 ACK 실패 1회 | Queue 16회, D1 최대 50회 |
| 같은 혼합 20건에서 마지막 ACK 실패 후 재전달 | Queue 17회, D1 최대 49회 |
| 일시 RSS 404 → 200의 전체 Queue | RSS 요청 2회, 글 5건 저장, D1 29회, 공식 호출 0회 |
| 지속 RSS 404 → 404의 전체 Queue | RSS 요청 2회 후 대기·오류 보존, D1 12회, 공식 호출 0회 |

위 D1 제한 검증은 모두 한도 거절 0회였다. 인용 20건의 기존 Queue 33회/D1 최대 46회도 유지한다. RSS 재시도는 D1 호출을 추가하지 않으며, 성공적인 무료 본문 처리량 5건을 유지한다.

전체 영향 **51파일 950건을 합성 검증해 통과**했다. 첫 전체 실행은 944건 통과와 테스트 호출 인자의 기대 6건 실패였다. 해당 테스트가 새 회차 인자 전달까지 검증하도록 확장한 뒤 영향 7파일 263건을 다시 실행해 모두 통과했다. 제품 코드는 이 기대 인자 정리 전후 동일하다. 최종 전체 명령을 한 번 더 통과했다고 보고하지 않는다. 독립 검토의 추가 동시성 프로브와 실제 캡처 응답 재생은 이 950건에 합산하지 않았다.

`typecheck:test`, 변경 코드 lint, `architecture:check`, `git diff --check`를 확인했다. 기존 생성 마이그레이션 `0170`의 스키마·SQL은 이번 수정에서 변경하지 않았다. 앞서 통과한 전체 체인·격리 D1 스키마 검사 증거를 재사용한다. 최종 PR/배포용 preflight와 원격 마이그레이션은 수행하지 않았다.

## 검증 한계와 보류

운영은 아직 이전 코드를 실행한다. 공급자 내부의 과거 404 세부 원인과 새 재시도의 운영 개선 효과는 미확인이다. 지속 404를 성공으로 강제하거나 미완료 상태를 삭제하지 않았다. 운영 설정·원격 DB 변경·배포·신규 유료 호출·Git 게시 보류를 유지한다.
