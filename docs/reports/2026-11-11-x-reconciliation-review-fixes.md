# X 12시간 대조 재리뷰와 로컬 수정

검토 기준은 `236fd3495c367364ef53959e3c576375c77d72e4` 이후의 미커밋 X 수집 변경이다. 운영 반영된 코드와 구분한다. 사용자 요구인 12시간 주기, 정상 구간의 즉시 Queue 재개, 저장 글의 공식 재조회 방지, 실행당 D1 binding 호출 50회 한도를 유지했다.

## Standards

최종 독립 재검토의 추가 필수 지적은 0건이다. 기존 지적은 다음과 같이 수정했다.

- 이전 회차의 RSS DLQ 묶음과 늦게 실패한 실행이 새 회차를 정산하지 못하도록 입구에서 검사한다.
- 정산 실패 기록, Queue 재시도 예산 예약, ACK, ACK 이후 실행 상태 갱신에도 같은 항목의 진행 기록을 SQL 조건으로 확인한다. 읽기 직후 수동 재시도가 발생해도 새 실행에 쓰지 않는다.
- 수동 재시도는 유지되는 성공 항목까지 이전 회차 메시지를 무효화한다. 성공 결과는 보존한다.
- 기존 원자적 완료 결과를 재사용해 완료 후 별도 재조회와 다른 회차의 결과를 읽을 가능성을 줄였다.

## Spec

최종 독립 재검토의 추가 수정 지적은 0건이다. 다음 문제를 재현하고 수정했다.

| 재현 상황 | 수정 및 확인 결과 |
| --- | --- |
| 수동 재시도 후 이전 메시지 도착 | 새 회차를 부여하고 이전 실행의 실패·정산·ACK를 차단한다. |
| 같은 시각에 임대 복구를 두 번 수행 | 복구별 임시 식별자로 이번 복구의 outbox만 갱신한다. 이미 전송한 메시지를 다시 열지 않는다. |
| 인용 조회의 정산 응답보다 복구 표시가 오래 유지 | 인용 응답을 UTC 날짜 기준 31일 보존해 30일 복구 표시를 포함한다. 일반 완료 응답은 기존 2일 기준, 실행 중 요청은 정리 대상에서 제외한다. |
| 작성자 캐시 적중 2건을 골랐으나 실행 도중 만료 | 즉시 다시 선택하는 Queue 후속 실행을 만든다. 작업을 남긴 채 종료하지 않는다. |
| 공식 응답 대기 중 Fx 저장, 또는 토큰 만료 후 Fx 저장 | 다음 요청 전에 최신 저장 ID로 구간을 다시 나눈다. 이미 정산된 요청은 같은 요청 ID로 재생한다. |
| 수집 시각이 과거인 Fx 저장이 늦게 완료 | 원문과 같은 트랜잭션에서 증가하는 계정별 저장 순번을 사용한다. 시간 비교에 의존하지 않는다. |
| 공식 원문 저장에 CAS 충돌 발생 | 후속 저장 시도 전에 D1 여유분을 확인하고, 부족하면 내구성 있는 정산 응답에서 재개한다. |

저장 순번은 `x_posts.insert_revision`과 `x_post_sources.insert_revision`에 기록한다. 새 원문 INSERT와 카운터 증가가 같은 D1 batch에서 커밋되고 충돌 시 함께 롤백된다. 경계 검사는 이전 요청의 순번 이후 저장된 ID를 확인하며, 자신이 저장한 마지막 응답의 ID는 제외한다. 경계 검사와 현재 순번 읽기는 같은 SELECT다. 이전 형식의 페이지 기록은 저장 ID로 보수적으로 재분할한다.

## 구조 및 비용 최적화

- 작성자별 원문 ID를 한 번 묶어 조회 권한 확인, 요청 표시, 캐시 저장에서 재사용한다. 반복되는 전체 목록 검색을 제거했다.
- 경계 검사에는 `(handle, insert_revision)` 인덱스를 명시한다. 저장 글 4,000건의 검사에서 `rowsRead`가 4,001에서 2로 줄었다. 조회 1회, 쓰기 0행이다.
- 정산 응답 정리는 만료일 식 인덱스로 최대 100건씩 처리한다. 보존 응답 5,000건을 포함한 회귀에서 조회 1회, 읽기 9행, 삭제 2행이었다.
- 저장 순번 갱신은 신규 원문당 소스 1행 쓰기와 인덱스 쓰기를 추가한다. 별도 D1 binding 호출은 추가하지 않는다. 실제 운영 청구액은 측정하지 않았다.
- 추가 계층이나 일반화된 실행 프레임워크는 도입하지 않았다.

## 로컬 검증

Node 24.20.0에서 실제 로컬 D1과 Worker Queue 진입점을 사용했다. 외부 X 응답은 모의 응답이며 실제 유료 호출은 0회다. Queue 계측은 후속 메시지의 전송 완료 기록까지 포함하고 실행당 50회에서 거절하도록 설정했다.

| 사례 | 결과 |
| --- | --- |
| 전체 영향 검사 | 51개 파일, 931건 통과 |
| 기존 공식 보완 ID | 4/4 저장 및 확인 지점 완료 |
| 정상 33개 공식 구간 | 서로 다른 공식 요청 33개, 후속 Queue 16회, D1 최대 46회 |
| 인용 대기 20건, 작성자 보강 | Queue 33회, D1 최대 46회 |
| 원문 캐시 만료 + 작성자 캐시 적중·미적중 혼합 20건 | Queue 16회, D1 최대 49회, 작성자 조회 10회 |
| 공식 저장 충돌 후 재개 | D1 최대 45회, 같은 공식 경로의 추가 유료 요청 없이 완료 |
| 회차 변경 후 이전 정산 실패·예산 예약·ACK | 새 실행·항목·outbox·예산 쓰기 0행 |
| 수집 정책 회귀 | 46/46 통과 |

실행한 영향 범위는 X 기능 전체, scheduled operations, scheduled jobs, 관련 Queue·게이트웨이·XAA·회원 글 조회·보존 콘텐츠·모니터링 UI 테스트다. native Cron → Workflow → Queue → 로컬 D1 흐름과 다른 수집기의 수동 재시도도 포함했다. 회차를 버리던 테스트 전달 도우미는 실제 전송 메시지를 보존하도록 고쳤으며, 모의 X 응답도 요청 구간에 맞게 반환하도록 수정했다.

`pnpm typecheck:test`, 변경 코드 lint, `architecture:check`, `git diff --check`가 통과했다. 신규 `0170_talented_franklin_richards.sql`은 Drizzle로 생성한 컬럼·인덱스 추가만 포함한다. `d1:reset:local -- --validate-only`로 전체 170개 마이그레이션을 임시 D1에 적용했고, 별도 격리 DB `.wrangler/x-review-20261111-final`에서 `d1:doctor --schema-only`도 통과했다. 기존 앱 DB를 초기화하지 않았다.

## 유지하는 보류와 검증 한계

운영 설정·원격 D1·배포·신규 유료 호출·커밋·push·PR·병합은 수행하지 않았다. 릴리스용 전체 preflight와 운영 성능·실제 과금 효과는 검증하지 않았다. 후속 운영 반영 시에는 생성한 마이그레이션과 코드의 적용 순서를 별도 릴리스 검증에서 확인해야 한다.

native Workflow 테스트 종료 시 RPC stub 정리 경고가 1회 출력됐으나 테스트 실패는 없었다. 이 검토에서 운영 RPC 자원 누수로 재현한 것은 아니다.
