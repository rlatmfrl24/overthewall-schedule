## 확인한 원인과 변경

- 양 사이트 운영 `/api/play/config`는 이미 public/navigation 모두 true였다. 그러나 공통 접근 정책이 OTW 외 사이트를 회원제로 분류해 LuvDia의 익명 catalog 요청을401로 차단했다. 알려진 OTW·LuvDia만 공개로 바꾸고 unknown/undefined 사이트는 기존 차단을 유지한다. DB 설정 변경이나 마이그레이션은 필요하지 않다.
- 공통 메뉴는 config 로딩 중 숨겨졌다가 로그인 사용자에게 제안 페이지, 이후 catalog로 바뀌었다. 항상 공개 `/play`로 연결하고 메뉴를 위한 config 요청을 제거했다. 실제 콘텐츠의 public_read_enabled·read-model revision·관리자 preview 검사는 유지한다. navigation_visible은 프로필 연결·검색 노출에 계속 적용되므로 관리자 설명도 실제 책임에 맞췄다.
- 개인 목록은 Clerk pending을 비회원으로 처리했다. 인증이 확정되기 전에는 skeleton을 표시하고 실제 로그인 소유자가 확인된 경우에만 개인 쿼리를 실행한다. 계정 전환·로그아웃 취소와 캐시 제거, 제안/개인 소유권/관리자 클립 보호는 유지한다. 프로필의 Play 연결도 config pending에는 로딩 자리를 표시한다.
- LuvDia 현재 소속은 공통 표시 함수에서 러브다이아로 바꿨다. 일정·프로필·스냅샷이 같은 표시를 사용하며 저장된 과거 소속이나 가창 credit은 변경하지 않는다.
- 일반 비회원 프로필 URL은 이미 바로 요청하고 있었다. 로그인 프로필은 보이지 않는 모바일 배경까지 인증 요청하고 desktop optimized와 원본을 동시에 불러왔으며 모든 배경이 높은 우선순위였다. 모바일은 보이는 사진만, desktop은 optimized 실패 후 해당 원본을 요청하며 첫 배경/주 사진만 우선한다. 불필요한 최초 preload 취소·재시작도 제거했다.
- 일정 초상과 모바일 사진에 동일 크기 skeleton을 적용했다. 캐시 완료·실패·src/세션 변경을 구분하고, 실패는 빈칸이나 깨진 이미지 대신 고정 placeholder를 유지한다. 기존 crop/object-fit·origin·required bearer·no-store·취소·참조 수·Blob URL 해제 경계를 보존한다.
