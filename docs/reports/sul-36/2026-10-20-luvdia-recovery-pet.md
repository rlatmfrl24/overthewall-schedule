# LuvDia 일간 일정표 빙하유 응원 펫

## 구현 범위와 상태

- 기준: `origin/master`의 `770d9e4d39ff0c4619c9a9707fcc62f3258c06ee`.
- 기존에 연결된 깨끗한 작업 트리를 재사용해 `codex/luvdia-recovery-pet`에서 구현했다. 원본 작업 공간의 미커밋 변경은 건드리지 않았다.
- 일반 방문자는 한국 시간의 실제 현재 날짜가 2026-11-16부터일 때 LuvDia 일간 일정표에 표시한다. 서버에서 확인된 관리자는 날짜 전에도 미리 볼 수 있다. 선택한 일정 날짜와 독립적으로 기존 `SCHEDULE_MEMBER_END.lastDate`인 2026-11-15 이후의 경과 일수를 계산한다. 11-16은 D+1, 11-17은 D+2다.
- `빙하유는 건강 회복 중!` 문구와 D+일수를 표시하며 한국 자정과 탭 복귀에 갱신한다. 새 API·DB·설정·예약 작업은 추가하지 않았다.
- 승인한 v3 6종의 서로 다른 5컷·3초 반복을 유지한다. 15초마다 장면을 바꾸며 접기·펼치기를 제공한다. 후속 요청으로 개별 일시정지를 제거했다. 사이트 애니메이션 끄기와 OS 동작 줄이기에서는 F00 정지 컷으로 표시한다.
- 높이 100px의 실루엣과 문구를 일간 일정표 우측 하단에 배치했다. 스크롤 영역과 분리하고 푸터 위에 고정하며, 펼쳐진 동안에는 마지막 카드를 위로 스크롤할 여백을 둔다. 닫기·펼치기 버튼 외에는 아래 일정의 클릭을 막지 않는다. 닫기 버튼과 하단 카드의 오른쪽 끝은 같은 그리드 열로 맞췄다.
- 주간 일정표와 별도 스냅샷 경로에는 마운트하지 않으며 OTW에서는 렌더링과 타이머가 없다.

## 에셋

`public/images/luvdia/bing-hayu-pet-v3/`에 288×288 무손실 투명 Animated WebP 6개와 F00 WebP 6개를 포함했다. 12개 합계는 2,586,832바이트다. 최초 장면만 로드하고 이후 해당 장면을 요청한다.

기존 승인 PNG를 FFmpeg로 크기만 변환하고 Pillow로 애니메이션을 인코딩했다. 모든 디코딩 프레임의 보이는 RGB·알파·유지 시간·무한 반복을 대조했다. 각 5컷과 3000ms를 확인했으며 `assets.json`에 원본 PNG/출력 해시와 기준 표시 좌표를 기록했다. 폐기한 동행 간식 장면은 포함하지 않았다. 원본 v3 묶음은 보존했다.

## 실제 화면 확인

정상 LuvDia 개발 서버의 일간 진입·기존 Clerk·기존 로컬 Worker/D1 조회를 사용했다. 운영 D1·원격 migration·운영 수집·배포는 수행하지 않았다. 현재 날짜의 기본 화면에서 미표시를 확인했다.

미래 경계는 ignored `.tmp`의 로컬 Vite 설정에서 **펫 컴포넌트의 시계만** 바꿔 확인했다. API·인증·일정 데이터와 앱의 선택 날짜는 교체하지 않았다. 이 로컬 설정의 시계 분기와 `__petClock` 문자열이 양 사이트 production JS에 없음을 별도 검사했다. 기존 개발 서버를 보존하기 위해 검증 서버는 localhost:5184를 사용했고, 충돌하는 검사 포트는 로컬 검증 설정에서만 껐다.

확인한 흐름:

- 11-15 자정 직전에는 미표시, 같은 탭에서 자정 경과 후 D+1 표시.
- 11-17 시계에서는 D+2 표시.
- 과거 날짜·시간순 보기로 바꿔도 현재 시계 기준 D+1 유지.
- 접기·펼치기와 기존 사이트 애니메이션 끄기 연동. 개별 일시정지는 후속 요청으로 제거했다.
- 라이트·다크 화면, 390px iframe, 모바일 스크롤 시 마지막 카드와 하단 안내를 가리지 않는 배치.
- 미래 시계 조건의 주간 화면에 펫이 없음.
- 일간 화면에서 실제 288px WebP 로드 완료. 5,070ms 연속 캡처에서 낮잠의 서로 다른 화면 상태 5개 확인.
- 날짜 이동 버튼으로 11-16 일정표에 진입해 D+1과 기존 관리자 예외 일정을 함께 확인. 해당 일정은 이전 정책 검증에서 저장된 로컬 데이터이며 이번 작업에서 쓰지 않았다.
- 마지막 브라우저 오류 로그 없음. PNG 증거와 파일 검사 결과는 작업 트리의 `.tmp/recovery-pet-evidence/`에 보존했다.

## 최초 구현 검증

Node.js 24.20.0을 사용했다. 시스템 기본 Node 25에서 기존 애니메이션 테스트의 localStorage 충돌이 있었으므로, 프로젝트가 고정한 24.20.0으로 기준 테스트를 재실행해 11개 통과를 확인한 뒤 진행했다. 제품 코드를 완화해 맞추지 않았다.

- `vitest run`: daily-schedule, chronological-schedule-list, recovery-pet 모델/UI, animation-provider의 5개 파일 **30개 PASS**.
- 변경한 TS/TSX ESLint PASS, `architecture-check.mjs` PASS, `git diff --check` PASS.
- `tsc -p tsconfig.app.json --noEmit`, `tsc -p tsconfig.test.json --noEmit` PASS.
- 정식 `build-site.mjs --site=luvdia`, `--site=otw` PASS. 각 빌드의 타입 검사와 사이트 산출물 검증 포함.
- 양 사이트 빌드에 복사된 12개 파일의 해시가 원본 웹 에셋과 일치. 펼침 상태의 스크롤 여백 CSS 포함, 검증용 시계 분기 미포함.
- `code-review-otw` 기준의 변경 범위 자체 검토에서 남은 중대한 지적 없음. 실제 화면에서 발견한 푸터 겹침과 마지막 카드 가림을 수정하고 같은 흐름을 다시 확인했다.

## 후속 요청 — 일시정지 제거와 정렬

개별 일시정지 버튼·재생 버튼·paused 상태를 삭제했다. 사이트/OS 모션 설정과 접기·펼치기는 유지한다.
하단 문구 카드와 닫기 버튼을 같은 그리드 열에 배치하고 오른쪽 끝을 맞췄다. 문구는 기존 한 줄 폭을 유지하며 카드 크기를 늘리지 않았다.

펫 모델/UI 12개 테스트 PASS, 변경 TSX ESLint와 `git diff --check` PASS다. 실제 일간 화면에서 개별 재생 제어가 없고 닫기·펼치기가 동작하는 것을 확인했다.
카드 폭 약120px·높이 약50px와 닫기 버튼의 오른쪽 좌표가 0.001px 이내로 일치하는 것을 브라우저에서 확인했다. 390px 화면에서도 한 줄 문구와 정렬을 확인했다. 정렬 증거는 `.tmp/recovery-pet-evidence/close-alignment.json`, `pet-close-aligned-no-pause.png`, `close-aligned-mobile-390.png`다.
최초 양 사이트 빌드 이후의 이 UI 수정에는 변경 범위 검증을 적용했으며 전체 빌드·preflight를 반복하지 않았다.

## 후속 요청 — 관리자 즉시 표시

일반 회원·비회원의 공개 시점이 한국 시간 2026-11-16 00:00부터임을 기존 경계 테스트로 재확인했다.
`/`의 기존 `useAdminStatus` → DailySchedule의 `isAdmin` → RecoveryPet으로 서버 판정을 전달한다. 로그인 여부만으로 관리자라고 간주하지 않으며, 권한 미확인·일반 회원은 날짜 전에는 숨긴다. OTW 관리자는 표시하지 않는다.
날짜 전의 관리자 화면에는 경과 일수 대신 `관리자 미리보기`를 표시하고 접힌 버튼에는 `미리보기`를 표시한다. 자정에 일반 D+1로 전환한다.

변경 검증은 모델/UI·일간 소비자·인증 API 호출의 4개 파일 **21개 PASS**, 변경 TSX ESLint·app/test TypeScript·diff 공백 검사 PASS다.
권한 확인 전/확인 후/해제, OTW 관리자 제외, 관리자 미리보기의 자정 전환을 포함한다. 테스트용 관리자 플래그나 신규 인증 경로를 제품에 추가하지 않았다.

실제 검증용 주소 localhost:5184가 개발 Clerk authorized parties의 localhost:5174와 달라 인증이 확인되지 않는 환경 차이를 발견했다.
기존 개발 서버와 운영 설정은 보존하고, 이번 검증 세션의 `LUVDIA_CLERK_AUTHORIZED_PARTIES`만 localhost:5184로 맞춰 재시작했다. 관리자 ID·서버 인증 코드는 바꾸지 않았다.
그 후 `http://localhost:5184/`의 2026-10-20 화면에서 정상 관리자 내비게이션과 펫의 `관리자 미리보기` 표시를 함께 확인했다. 최종 검증은 날짜 보정 플러그인이 없는 로컬 설정으로 서버를 재시작한 뒤 수행했으며 현재 시각과 실제 서버 관리자 판정만 사용했다. 이전 로컬 날짜 보정 매개변수는 현재 서버에서 작동하지 않는다. 증거는 `.tmp/recovery-pet-evidence/admin-preview-current-date.png`다.
이 후속 변경에 전체 빌드·preflight를 반복하지 않았으며 운영 배포·master 병합은 미실시다.

## 최종 코드 검토와 주간표 작업 인계

사용자의 후속 요청에 따라 `code-review-otw` 절차로 최종 변경을 검토했다. 기준은 최신 `origin/master`와 일치하는 `770d9e4d39ff0c4619c9a9707fcc62f3258c06ee`이며, 펫 변경만 `codex/luvdia-recovery-pet`의 인계 커밋으로 분리한다. 원본 작업 공간과 다른 작업 트리의 미커밋은 포함하지 않는다.

일간 진입 → 기존 서버 관리자 판정 전달 → 한국 현재 날짜 판단 → 화면 표시와 D+갱신, 사이트/OS 모션 설정, 접기·펼치기, 타이머 정리, 스크롤/푸터/스냅샷 경계를 추적했다. 남은 중대한 지적은 없으며, 이번 검토에서 제품 코드 수정은 필요하지 않았다. 테스트나 로컬 시계 설정이 제품의 권한·날짜 정책을 대신하는 경로도 없다.

최종 제품 소스에서 Node.js 24.20.0으로 다시 실행한 결과:

- 펫 모델/UI·일간·시간순 보기·애니메이션 제공자·인증 API의 6개 파일 **34개 PASS**.
- 변경 TS/TSX ESLint, app/test TypeScript, 구조 검사와 diff 공백 검사 PASS.
- 정식 양 사이트 빌드 PASS. 각 산출물의 12개 에셋 해시 일치, 펼침 여백 CSS 포함, 로컬 날짜 보정 문자열 미포함을 재확인했다.
- 실제 WebP의 6종 무한 반복·각 3000ms와 프레임 수, 12개 파일의 크기·SHA-256 및 합계 2,586,832바이트 일치 PASS.
- 날짜 보정 없는 `http://localhost:5184/`의 실제 개발 관리자 로그인에서 `관리자 미리보기`와 접기·펼치기를 재확인했다. 닫기 버튼과 카드의 오른쪽 좌표는 모두 792.84375px였다. 증거는 `.tmp/recovery-pet-evidence/review-admin-preview.png`다.

참조한 **주간 스케줄 헤더 높이 고정** 세션은 이미 [PR #173](https://github.com/rlatmfrl24/overthewall-schedule/pull/173)을 생성했다. 확인한 주간표 HEAD는 `728ae04e94b049732c692e07b1c2bb3eebd8498b`다. 중복 PR은 여기서 생성하지 않으며, 담당 세션에 인계 커밋과 이 기록을 전달해 주간표 변경과 함께 PR에 반영하도록 한다. 통합 후에는 최종 diff와 실제 양쪽 화면을 재검토하고 최종 소스의 공식 `pnpm preflight` 및 GitHub 판정을 해당 PR ledger에 기록해야 한다. 이 기록은 통합 소스의 preflight 성공이나 운영 반영을 뜻하지 않는다.

## 남은 범위

이후 사용자가 주간표 개선과의 통합을 승인했다. 인계 커밋 `ae88ee0630b93e0bfdad55cb2f8d909bca3d1baa`를 주간표 작업 브랜치에 포함하며 별도 PR을 만들지 않는다. 아래는 펫 단독 인계 시점의 한계이고, 최종 통합 소스의 검증·게시 상태는 [PR #173 검증 ledger](https://github.com/rlatmfrl24/overthewall-schedule/pull/173)의 정확한 HEAD와 판정을 따른다. 운영 D1과 병합·배포 제한은 유지한다.

펫 브랜치 push·PR 게시·master 병합·운영 배포는 여기서 수행하지 않았다. PR 병합 준비 단계의 최종 preflight는 인계받는 세션의 통합 후 검증으로 남긴다. API·권한·D1 계약을 바꾸지 않았으므로 Worker/D1 통합 전체 테스트는 이번 변경 범위에 포함하지 않았다. 운영 D1 조회·쓰기와 Play/AI 자동화 재개는 수행하지 않았다.

휴대전화 실기기, 이미지 다운로드의 신규 실측, 실제 2026-11-16 이후의 자연 실행은 미확인이다. 스냅샷에는 펫을 마운트하지 않는 소스 경계만 확인했다. 미래 동작의 화면 확인은 위의 로컬 시계 검증이며, 자연 날짜 관측이나 운영 배포 증거를 뜻하지 않는다. 테스트나 검증 설정이 실제 제품의 시간 정책을 소유하지 않으며 제품에는 현재 Date.now 기반 경로만 남겼다.
