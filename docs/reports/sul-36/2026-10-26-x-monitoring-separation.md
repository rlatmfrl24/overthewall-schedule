# 웹훅 상태와 REST 누락 복구 이력 분리 — 2026-10-26

## 의도와 변경

현재 웹훅 구독 상태와 과거 REST 실행 결과를 별도 표시한다. 최신 REST 실행2852/2853의 `failed/shared_budget_unavailable` 원본은 보존한다. 당시 API 호출·저장·비용은0이며 현재 웹훅 전체 장애로 설명하면 안 된다.

- 대시보드와 X 수집 주 화면에 기존 `/api/x/activity` 읽기 결과를 표시한다. 구독 정상·수신0건은 ‘구독 정상 · 신규 수신 대기’다. 최근 수신 시각과 최근 표본의 저장/대기/실패 건수, 양 사이트 합산 UTC 예산을 구분한다.
- 정기/수동 수집은 ‘REST 누락 복구’와 실행 이력으로 표시한다. Operations의 과거 REST 실패/지연 경고 이름·설명만 REST 범위로 바꾸며 저장 결과나 실패 이력을 정규화하지 않는다.
- 두 진입점 상단 새로고침이 같은 웹훅 query를 갱신한다. 초기 조회 실패·정상 캐시 후 재조회 실패는 ‘최신 상태 확인 불가’이며 캐시는 이전 정보로 명시한다. 상태가 불명확할 때 제어를 막고, 제어 요청 실패 후 재조회하되 변경 요청 자체를 재시도하지 않는다.
- app/admin 조합 계층이 웹훅 카드/경고를 Operations 화면에 주입한다. 새 엔드포인트·스키마·주기 조회·유료 API 경로는 추가하지 않는다.

## 로컬 검증

Node24.20.0, pnpm11.7. 회귀를 먼저 작성한 RED에서5건이 실제 실패했다. 구현 후 최종 관련7개 파일64건이 통과했다. 정상 캐시 후 조회 실패/복구, 초기 오류, 구성 불가, 공급자 오류, 부분/예산 중지, 제어 실패 후 실제 상태 재조회, 상단 갱신, REST 실패 원본 보존과 경고 범위를 검증했다.

`pnpm typecheck:test`, 변경 코드 ESLint, `pnpm architecture:check`가 통과했다. 테스트는 실제 운영 흐름의 대체가 아니며 릴리스 후 정상 관리자 진입점·읽기 결과를 추가 확인한다. 운영에 가짜 장애나 유료 수집을 발생시키지 않는다.

## 릴리스와 운영 확인

사용자 승인에 따라 PR 검토·기존 Cloudflare 자동 CI를 재사용한다. OTW는 병합 자동 배포만 수행하며 LuvDia는 같은 병합 소스를 정상 빌드·배포한다. 계정 D1 보호를 먼저 확인하고 정상 관리자 두 화면·상단 새로고침·원본 REST 실패 보존·구독과 공통 예산을 읽어 확인한다. 최종 버전과 실제 판정은 owning PR의 증거 댓글에 기록한다.

기존 자동충전5→10달러·주기30달러·공통 UTC 하루1달러 목표, 사이트별 조회 보호와 중지 설정은 변경하지 않는다. 하루1달러는 전달 중 비용 때문에 엄격한 상한이 아니다. 자연 사진/영상의 신규 표본이 없으면 처리 품질은 미확정으로 남긴다.
