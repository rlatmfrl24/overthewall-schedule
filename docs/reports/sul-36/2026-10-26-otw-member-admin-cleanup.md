# OTW 관리자 카페·프로필 잔여 항목 정리

사용자가 러브다이아로 이관된 빙하유·양메이·유리리를 OTW 카페 수집 조회와 관리자 프로필 목록에서 제외하도록 요청했다.
추가 설명에서 대상은 `콘텐츠 → 일정 보관`의 프로필 버튼이며 기존 주소 자동 이동은 요청하지 않았다.
러브다이아의 현재 프로필·카페와 OTW 과거 일정·멤버·사진·이력은 보존한다. X 수집·예산·자동충전과 다른 자동화는 이번 변경 대상이 아니다.

## 카페 실제 반영

- 정상 OTW 관리자 `수집·소스 → 네이버 카페 → 수집·공개 설정 및 게시판 관리`에서 세 소스를 제외했다.
- 서버의 기존 삭제 동작은 소스 행의 `enabled=0`, `archived_at/deactivated_at` 기록과 다음 점검 해제다. 게시글·멤버·사진 삭제나 러브다이아 재복사를 하지 않는다.
- 대상은 OTW cafe31352147의 소스3/4/5, 게시판12/13/14다. 기존 수집기에서는 이미 소속 정책으로 제외했으나 관리자 설정에는 활성 상태로 남아 있었다.
- 새로고침한 실제 관리자 화면은 활성5/5·주의0·오류0·지연0·정상으로 표시했다.
- 14:50 KST 원격 readback에서 세 소스 비활성/보관 시각과 나머지5개 활성, 러브다이아 cafe30854204 게시판30/32/34의 기존 활성·오류 없음이 확인됐다.
- 계정 D1 읽기1,507,675(<배경4M)을 먼저 읽고 좁은 SELECT를 실행했다. 관측 SQL 쓰기는0이며 실제 변이는 위 관리자 흐름에서만 발생했다.

## 프로필 원인과 수정

`ScheduleArchiveManager`가 보관 일정의 소유자 식별용 전체 멤버 목록을 프로필 버튼에도 그대로 사용했다.
OTW 관리자에서 세 프로필 버튼이 실제로 남아 있는 것을 재현했다. 원본 행은 `content_access=normal`이어도 사이트 공개 전환 정책에서 제외되므로 단순 보관 플래그 필터로 해결할 수 없다.

프로필 버튼·열린 프로필에만 기존 `getHiddenMemberCodes(site.id, Date.now())` 정책을 적용한다.
보관 일정의 조회·과거 소유자 이름, 다른 보관 멤버의 프로필과 러브다이아의 세 프로필 동작은 유지한다.
API·인증·스키마·파일·멤버 행은 변경하지 않는다.

기존 러브다이아의 세 프로필을 실제 화면에서 열어 현재 소속·사진·카페 링크를 확인했다.
세 사진은 모두 실제 로드 완료·1280×720, 사인은3790×3790이었다. 양 DB의 멤버 identity와 사진 행 각1개는 전후 동일했다.

## 검증·릴리스 상태

- 회귀 테스트에서 OTW의 빙하유 버튼이 남는 실제 결함으로1 FAIL·LuvDia1 PASS를 확인한 뒤 수정했다.
- 수정 후 두 사례 PASS: OTW 세 버튼 제외/보관 일정 소유자·다른 보관 프로필 보존, LuvDia 세 버튼·선택 프로필 표시 보존.
- 최종 CI·배포와 실제 관리자 새로고침 결과는 소유 PR의 evidence 댓글과 이 문서 후속 기록을 따른다. 로컬 수정만으로 운영 프로필 정리 완료를 주장하지 않는다.
