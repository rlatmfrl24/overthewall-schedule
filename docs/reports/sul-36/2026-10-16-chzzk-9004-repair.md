# 2026-10-16 CHZZK 9004 자동 일정 수집 수정

## 결론과 상태

저장된 로그의 권역 제한 응답을 일반 HTTP500 장애로 재시도하면서, VOD 조회와 별개인 라이브 근거 확인이 실패했다. 수집용 catalog에서만 공개 채널 메타데이터의 확인된 상태를 사용할 수 있도록 수정했다. **PR162에 반영하며 D1 중단·Draft·병합 및 배포 대기를 유지한다.** 운영의 실제 수집·저장 성공은 아직 확인하지 않았다.

기준 HEAD는 `403f368dee3122f8db74b56e7eac58c691e38d43`, 마지막 확인된 운영 소스는 `462779cf1db6b7e06fadc46d0dc3f878762e241b`다. 제출 HEAD와 원격 검사는 PR ledger에서 대조한다.

## 원인과 기존 증거

- 대상은 테리 눈나(uid2, `terri_nunna`), 채널 `0a2020b09b8cc7f2285b7ae5de2ce4d3`다. 실패 run `f1195a83-a4ab-4efd-8590-23f771a72d9c`와 scan item `c38ceec2-768a-4331-b13f-73d62059aa44`의 기존 partial은 변경하지 않는다.
- 저장된 Queue 로그6건 모두 같은 라이브 polling 오류다: `HTTP500 / {"code":9004,"message":"해외 시청 불가능한 컨텐츠 입니다."}`. 저장된 첫 VOD 응답은200이다. 후속 VOD 전체 성공까지 뜻하지 않으며, 로컬 ECONNRESET을 운영 원인으로 바꾸지 않는다.
- `fetchChzzkLiveStatusWithDebug`는 이 응답을 일반 `http_error`로 분류하고 같은 polling을 재시도했다. `recordHolidayAssessments`는 오류/오래된/없는 라이브 근거를 failed로 처리한다. 그 coverage가 scheduled scan의 재시도와 최종 실패/partial로 이어졌다.
- 후보는 권역 제한 오분류, 라이브 캐시, VOD 페이지 실패였다. 저장된 로그와 실제 catalog→assessment 함수 재생에서 첫 원인을 확인했다. 캐시 경로는 회귀로 검증했고 VOD 후속 실패를 이번 원인으로 확정하지 않았다.
- 원본 증거는 로컬 `.tmp/schedule-channel-repair-20261016/`의 log-probe.json, failed-run.json, vod-http.json, cache-probe.json, vod-evidence.json이다. 이번에는 읽기만 했고 운영/CHZZK 요청을 반복하지 않았다. 공개 메타데이터의 현재 실제 응답은 재확인하지 않았다.

## 변경과 유지 조건

1. polling의 JSON `code=9004`를 `region_restricted`로 구분하고 동일 제한 응답의 즉시 재요청을 멈춘다. 일반500/502/503/504와 네트워크 오류의 기존 재시도는 유지한다. 일반403을 채널 상태로 해석하지 않는다.
2. 수집 catalog가 `fetchChzzkLiveStatusForScan`을 사용한다. 라이브 근거는 기존 메모리 캐시를 우회하며, 9004일 때만 인증/Cookie/재생 정보가 없는 공개 `/service/v1/channels/{id}` 메타데이터를 한 번 요청한다.
3. HTTP 성공·응답 code200·동일 channelId·boolean openLive를 모두 만족해야 확인된 상태로 사용한다. false는 CLOSE이고 true는 OPEN이다. 시작 시각은 `null`이며 제목·시각을 추정하지 않는다. 메타데이터를 일반 라이브 캐시에 넣거나 완전한 공개 라이브 DTO로 위장하지 않는다.
4. OPEN에 시작 시각이 없으면 기존 assessment가 incomplete로 남긴다. 메타데이터 실패·잘못된 응답·다른 채널·미확인 값은 실패를 유지하고 오래된 CLOSE를 대신 쓰지 않는다. VOD coverage의 failed/incomplete를 성공으로 올리지 않는다. 휴방은 여전히 관측 범위가 완전할 때 제안하는 가설이며 일정에 직접 확정하지 않는다.
5. 일반 공개 라이브 화면·관리자 자동 입력은 기존 polling 경로를 유지한다. 수집·일반 저장·최종 `commitPublicationBatch`의 공개 경계, 사이트/멤버 권한, 감사·원자성·중복 방지·기존 재시도/Queue 설정은 변경하지 않는다. 정각을 넘는 수집 응답의 최종 저장 차단도 같은 writer 경로다. 이 DB 동작은 이번에 실행하지 않았다.
6. 기존 테스트 캐시 초기화 함수가 누락하던 LIVE_STATUS_CACHE도 지우도록 보완했다. 테스트 간 캐시 오염을 제거한 뒤 RED를 다시 확인했으며, 운영 캐시 TTL/설정은 변경하지 않았다.

## 검증과 한계

Node24.20.0, `vitest.config.ts`로 실제 catalog와 assessment의 코드 경로를 검사했다. 외부 경계는 기록된 HTTP 응답과 경계 사례로 대체했으며 SQL parser·SQLite·D1/Miniflare runtime을 실행하지 않았다. assessment 시험은 준비된 쓰기 의도만 메모리에서 캡처하므로 실제 저장/휴방 생성의 증거가 아니다.

- 수정 전 단독 재현1사례 FAIL: 기대 CLOSE 대신 `content:null / http_error`. 캐시 초기화 보완 뒤 확장 사례는7 FAIL/19 PASS였고, 수정 및 공개 polling 경계 사례 보강 후 신규27사례 모두 PASS다.
- 관련7파일/88사례 PASS: 신규 live-status·holiday assessment, 기존 CHZZK cache·공개 HTTP/관리자 권한, VOD scan·live schedule 판정, 예약 실행 결과. 기존 cache 시험의 D1 인터페이스는 메모리 대역이며 SQL 실행이 아니다. 오류·stale 회귀의 의도된 stderr 로그가 있었고 테스트 실패는0이다.
- 변경4개 코드/시험 파일 ESLint, `tsc -p tsconfig.test.json --noEmit`, architecture, diff 검사 PASS. 이전 X/outbox/공유 정책 검증을 이번 전체 통합 PASS로 확대하지 않는다.
- 원격/로컬 D1·SQLite SQL, doctor·마이그레이션, 전체 preflight·build, 실제 사이트/API/provider, 수집 강제 실행·백필·배포는 미실행이다. 원본 WIP409개·별도 X10개·기존 보고서3개·이전 PR 코드 수정은 해시/차이로 보존 확인한다. 자연 X·19일 관측 예약은 변경하지 않는다.

후속은 명시적 D1 재개와 예산 확인 뒤, 작은 대상의 실제 자연 수집·최종 저장·완료/미완료 상태를 확인하는 일이다. 메타데이터도 제한되거나 라이브 시작 시각을 확인하지 못하면 실패/미완료가 계속 남는 것이 정상이며, 이를 숨기기 위해 성공 처리하거나 권역 제한을 우회하지 않는다.
