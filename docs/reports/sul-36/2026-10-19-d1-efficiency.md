기준은 **계정 전체 UTC 하루5,000,000행 읽기**다. 임시 유료 플랜을 근거로 목표를 높이지 않았다. 배포 전 로컬 결과이며 운영 하루 한도 달성을 증명하지 않는다.

**캐시와 정책**

공개 catalog/facets/detail/member/playlist의 요청 간 데이터 cache는 계속 우회한다. config cache는 기존 동작만 유지했다. member/link/shared-owner 변경과 기본 목록 설정 version을 모두 포함하는 무효화가 입증되지 않았기 때문이다. cache hit 절감량은 주장하지 않는다. 요청 내 공유는 적용했다. 한 글자 부분 문자열 검색은 gram 색인이 없으므로 기존의 완전한 검색을 유지한다. 전체 게시 버튼은 전체 대상 목록을 별도로 읽은 뒤 대상 수를 확인하고 실행한다.25개 페이지를 전체로 취급하지 않는다.

Play 자동화 중지·LuvDia AI=false, 익명/로그인/관리자 경계, 양 사이트 공개/보관/공유 소유자 정책, 빙하유 일정 날짜 제한, 실제 partial/실패/재시도는 유지한다.

**Migration과 추가 쓰기 비용**

Drizzle schema에서 생성한142~147은15개 CREATE INDEX만 포함한다. 삭제/테이블 재작성은 없다. 쉼표 표현식의 생성기 문제는 COALESCE 정렬과 동등한 CASE로 schema를 바꾸고 다시 생성했다. 임시 D1의147개 전체 체인을 `pnpm d1:reset:local -- --validate-only`로 실제 적용·검증했다. 기존 로컬 DB는 교체하지 않았다.

향후 승인된 릴리스에서 계정 읽기·쓰기 여유와 양 DB 적용 이력을 확인한 뒤142→147을 순서대로 적용하고, 인덱스를 요구하는 Worker를 반영해야 한다. 원격 적용은 이번에 실행하지 않았다.

**독립 리뷰와 보완**

독립 리뷰 기준은 `c3433543fa2cce6a609046632f4130f78ff1fdad`이다. 전체 변경을 새 컨텍스트에서 검토한 결과 관리자 회귀3건을 발견했다. 페이지 밖 기존 가창 참여자 검색을 활성화하고 기존 identity ID가 저장 명령에 전달되는지 확인했다. 빈 서버 검색 결과에서도 전체 게시를 열어 전체 대상 확인·실행이 가능하게 했다. SQLite의 ASCII `lower()` 대신 기존 정규화 저장값으로 후보를 좁히고, 소비자별 Unicode/NFKC/공백/구두점 의미를 페이지 제한 전에 판정한다. 외부 참조 검색과 유니코드 검색을 위해 전체 카탈로그 관계를 다시 불러오지는 않는다. 부분 문자열 후보 탐색은 여전히 O(N)일 수 있다.

세 회귀는 수정 전 실패를 확인했다. 수정 후 관리자 UI2개와 실제 D1 카탈로그26개가 통과했다. 과거 멤버 identity30개가 외부 참여자 검색25개를 소진하는 추가 회귀도 재현해, 기존 선택기처럼 멤버는 활성 멤버 조회에서 표시하고 외부 identity는 페이지 제한 전에 멤버 항목을 제외하도록 보완했다. 비용 fixture의 일반25곡 페이지는13SQL/659읽기/쓰기0을 유지했다. 보류한 사소한 리뷰 지적은 없다.

리뷰가 별도로 판단을 남긴 기존 수동 Play 수집/큐 처리는 관리자 요청으로 수락된 작업의 계약을 유지한다. 공통 fail-closed 예산 검사는 새 자동 Workflow 생성·계획 조회 앞에서 수행한다. 사용자가 명시적으로 수락한 수동 작업/다음 묶음은 자동화 재개로 간주하지 않는다. 집계가 불가능한 동안 수동 수락 작업이 읽기를 소비할 수 있으므로 운영자가 계정 예산을 지켜야 한다.
