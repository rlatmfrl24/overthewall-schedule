# 2026-10-19 공개 전환 관측

**현재 LuvDia 공개·OTW 이관 대상 숨김은 정상이다.** 익명 HTTP와 실제 Chrome 사용자 흐름에서 확인했다. 관리자 원본 조회와 파일은 보존돼 있다. 다만 정각 순간의 실시간 관측은 하지 못했고, 점검 중 계정 D1 읽기 증가가 계획한 관측 예산을 넘어 추가 D1 확인을 종료했다. 모든 경계·비용 검증이 완료됐다는 뜻은 아니다.

## 시각과 실제 배포

예정 관측은 10/19 00:01 KST(`2026-10-18T15:01:00Z`)였고 직전 예약 readback도 이 시각과 일치했다. 이번 heartbeat 실제 발화는 05:09:39 KST(`20:09:39Z`), 최초 익명 publication-status 실측은 05:12 KST였다. 지연 원인은 확인하지 않았으며 00:00 당시를 관측했다고 보고하지 않는다. 서버 정책의 공개 시각은 기존 `2026-10-18T15:00:00Z` 그대로이며 예약이 공개를 실행하지 않는다.

control-plane의 양쪽 100% 버전은 직전 관측과 같다. 다른 정상 배포를 이전 버전으로 덮어쓰지 않았다.

## 공개 정책과 실제 사용자 흐름: 확인한 범위 PASS

- 양 사이트 익명 `GET /api/publication-status`는 200/phase=open/canPreview=false, `private, no-store`다. LuvDia의 공개 전 countdown/403 상태에서 공개 후 상태로 바뀌었다.
- 익명 OTW members는 비대상 5명만 반환한다. LuvDia members는 `bing_hayu`, `yang_mei`, `u_lili` 3명만 반환한다.
- OTW의 위 3명 프로필 API는 각각 404다. 비대상 `kurenai_natsuki` 프로필 API는 200이다. 10/17 과거 일정 API도 member_uid 3·4·5를 제외하고 비대상 일정 6개를 정상 반환했다.
- OTW D-day API는 200이며 명시 대상 ID **4·9·10·11**이 모두 제외됐다. 제목으로 대상을 추정하지 않았다.
- 익명 OTW 대상 프로필 파일 HEAD 3개와 인코딩 경로 `%62ing_hayu.webp`는 **401/private no-store/body 0**이다. LuvDia의 같은 파일·인코딩 경로와 OTW 비대상 파일은 200/body 0이다. 인증이 없는 보호 파일의 401은 현재 계약이며 500 장애나 원본 유실로 해석하지 않는다.
- 익명 archive=1의 멤버 목록·대상 상세는 모두 401이다. 인증 토큰 복사나 권한 우회를 하지 않았다.
- Chrome의 LuvDia 실제 메인에 오늘 일정과 멤버 3명·멀티뷰 메뉴가 표시됐다. 메인의 프로필 버튼으로 빙하유→양메이→유리리 각각의 프로필에 진입해 실제 이름·소개·연결 채널을 확인했다. 이 UI는 기존 로그인 세션이었으며 익명 HTTP 검증과 구분한다.
- 메인 아바타 3명 모두 실제 이미지 decode 완료를 확인했다. 빙하유 480×479, 양메이 820×813, 유리리 600×600이다. 초기 화면 캡처가 로드 전 상태여서 같은 입력의 새 진입에서 DOM complete/naturalWidth와 로드 후 화면을 추가 확인했다. 이를 정량 성능 측정으로 확대하지 않는다.
- OTW는 로그인 전 게스트 메인에서도 비대상 5명만 보였다. 일반 직접 `/profile/bing_hayu`는 실제 '페이지를 찾을 수 없습니다' 화면이다.
- 정상 사용자 메뉴→Clerk 로그인→기존 Google 운영 계정→관리자 메뉴→콘텐츠→일정 보관→빙하유 프로필 경로를 통과했다. 보관 조회에는 숨긴 멤버와 일정이 남아 있고 원본 프로필·배경·사인이 로드됐다. 프로필 480×479, 배경 1280×720, 사인 3790×3790의 decode 완료를 확인했다. 관리자 세션·토큰을 추출해 하위 API로 대체하지 않았다.
- 별도 PK 최소 조회에서 OTW members uid 3·4·5와 D-day id 4·9·10·11이 모두 기존 content_access=normal로 남아 있었다. 삭제·상태 강제 변경 없이 시간 정책이 일반 노출을 차단한 것이다. 이 보조 SQL은 실제 관리자 진입 검증을 대신하지 않는다.

사이트별 D1/R2/Queue/Workflow 연결, Cron, Queue 각 6개의 consumer/retry/retention/paused 설정은 기존과 같다. 적체는 전부 0이다. LuvDia AI=false를 metadata로 재확인했다. Play 자동화를 재개하지 않았으며 OTW 정상 관리자 화면에도 의도적인 중지 안내가 유지된다. Queue가 비었다는 사실을 수집 전체 성공 판정에 대신 사용하지 않았다.

## 비용과 확인 중단

D1 사용 전에 기존 계정 집계를 읽었다. 05:10 KST 읽기 1,374,782행/500만행(**27.50%**), 쓰기 21,587행/10만행(21.59%)이었다. 05:13 중간 집계는 읽기 1,374,827행이었다.

05:19 최종 집계는 읽기 **1,602,213행(32.04%)**, 쓰기 **21,622행(21.62%)**이다. 관측 창 계정 증가 **227,431행 읽기·35행 쓰기**는 계획한 2만행보다 크다. 계정 집계는 자연 운영·다른 사용자·집계 지연과 이번 UI/API 확인이 섞여 있어 모두 이번 점검 비용이라고 단정하지 않는다. 그래도 이번 UI/API 비용이 예산 안에 들었다고 증명할 수 없으므로 **예산 준수 PASS로 보고하지 않으며 추가 D1 SQL·사이트/API 확인을 종료했다.** 해당 시점에는 검증용 브라우저 탭도 모두 닫았다. 계정 80% 중단 기준에는 도달하지 않았다.

직접 REST SQL은 명시 PK 7개의 보존 확인 2문장뿐이며 **14행 읽기·0행 쓰기**다. 이 수치가 화면/API 전체 비용은 아니다. 전체 count/scan·doctor·재귀 음악 검사·백필·강제 수집·메시지 소비/purge·유료 AI·데이터/설정 변경·배포·rollback은 하지 않았다. 후속 운영 화면·파일 권한 조회의 비용은 기존 로그와 로컬 쿼리 계획으로 분리할 필요가 있으며 원격 대량 재검사로 원인을 찾지 않는다.

## 최초 FAIL과 관측 도구 보정

초기 관측 assert는 보호 파일의 익명 HEAD를 403/404로만 가정해 실제 401에서 FAIL했다. 원래 실행 파일과 응답을 보존했다. assets handler의 requireAdminUser 호출과 auth의 `Login required` 401 계약을 확인한 뒤, **이미 저장한 응답**을 올바른 401 기대값으로 재검증해 공개 경계 assert를 통과했다. 제품 보호 조건이나 운영 코드를 바꾸지 않았고 전체 네트워크 확인도 반복하지 않았다. `verification-history.json`에 최초 FAIL과 근거를 남겼다.

IAB 화면 연결은 타임아웃으로 실패해 Chrome의 실제 정상 UI로 검증했다. 이는 서비스 공개 오류와 구분한다. 기존 WIP·X 작업 트리·보호 보고서·마이그레이션 이력은 수정하지 않았다.

## 관측 한계와 종료

- 정각 직전/직후와 계속 열려 있던 countdown 탭의 자동 전환은 이번 실제 관측에서 확인하지 못했다. 과거 로컬 경계 테스트와 현재 공개 결과를 구분한다.
- 별도 일반 회원 계정의 관리자 우회 차단은 실제 계정으로 재검증하지 않았다. 익명 차단·정상 관리자 접근은 확인했고 기존 권한 회귀 근거는 보존한다. 역할 변경이나 계정 생성으로 검증하지 않았다.
- 정각을 넘긴 수집 응답의 최종 저장 차단과 모든 공유 자료의 보존은 이전 로컬 D1 회귀 근거이며 이번 원격 전수 검증은 하지 않았다. 과거 R2 사고 전체 해결 판정도 하지 않는다.
- 관리자 보관 화면의 '일반 공개 일정' 문구는 저장된 content_access를 표시해 시간 정책으로 숨긴 일정에도 붙는다. 일반 API의 실제 차단은 확인됐다. 운영자에게 혼동을 줄 수 있는 표시 문제로 남기며 데이터 상태를 강제로 바꾸지 않는다.

현재 공개 전환의 실제 결과와 관리자 보존을 관측했으므로 이 일회성 관측 예약을 도구로 삭제했다. `deleteStatus=deleted`와 read-only 로컬 예약 저장소에서 otw-luvdia-19/automation-4 행이 모두 없는 것을 확인했다. otw-9-d1은 PAUSED를 유지하며 `automation-readback.json`에 남겼다. 대량 이관·백필·전수 검증·Play/AI 재개는 계속 보류한다.
