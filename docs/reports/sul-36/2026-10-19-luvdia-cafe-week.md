## 실행 경로와 실제 저장

이전 작업에서 정상 관리자 UI로 세 소스의 카페 ID·게시판·URL을 바꿨다. 기존 수집기는 최초 실행 시 현재 글을 기준점으로만 저장하므로, 이번에는 먼저 관리자 ‘지금 점검’으로 실제 초기화를 완료했다. 초기 실행 `474573ad-fd9d-461c-8074-1c57d3e96a05`은 성공했으며 세 게시판 모두 외부 요청을 수행했다.

최근 일주일 소급을 위해 세 소스의 수집 시작 시각과 재조회 커서만 일회성으로 조정했다. 실제 초기화 완료 시각·게시판·멤버 연결·활성/공개 상태는 유지했다. 운영 D1의 원자적 조건부 UPDATE는 확인한 세 행이 모두 그대로이고 실행 중인 카페 작업이 없을 때만 적용했다. 로컬 SQLite에서 실행 중 작업 차단, 한 행 변경 시 전체 중단, 초기화 이력 보존, 재실행 차단을 검증했다. 제어 상태 변경은 3행 쓰기였다. 게시물 행을 SQL로 직접 생성·수정하지 않았다.

이후 정상 관리자 ‘지금 점검’ → 작업 접수 → Outbox → Queue → 기존 수집기 → 저장 경로로 실행했다. 실행 `0d4d4887-58f0-4858-bb2a-67af37736897`은 10:30:39 KST 완료, 실제 item은 1회 시도로 succeeded였다. 내부 결과는 세 source 모두 `ok`, 글 수 1·1·0, 오류 없음이다. 두 게시물의 authoritative 저장 행도 제목·카페 ID·게시판·멤버 UID·시각·원문 URL이 일치했다. 정상 watermark를 다시 기록했고 미완료 페이지/실패 상태는 남지 않았다. Execute outbox는 dispatched, reconcile receipt는 기록되어 이번 실행의 미해결 전송·재시도는 없다.

원본 목록은 게시판당 15건씩 첫 페이지를 확인했고 모두 일주일 이전 글까지 도달했다. 따라서 이번 기간의 누락 없이 2건임을 확인했다. 유리리의 과거 글을 최근 글로 바꾸거나 가져오지 않았다. 기존 오버더월 카페 글은 원래 링크와 함께 보존했다.
