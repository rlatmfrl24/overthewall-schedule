## 로컬 코드 — 구현 완료, 미배포

공유 이름→ID 맵이 동명 원곡 가수·외부 참여자의 ID와 역할을 덮어쓰던 문제가 원인이다. 선택 레코드에 표시명·entityId·memberUid를 함께 보관하고, 제거·역할·생성·수정·초기화에서 ID와 순서를 유지한다. 곡 교체나 새 이름 입력에 예전 ID를 추정해 붙이지 않는다.

이전의 회원 화면 등록 ID·개인/그룹 표시 방안은 철회했다. 검색 결과·칩에는 이름을 표시하며 여러 정확 일치 결과를 Enter로 임의 선택하지 않는다. 기존 서로 다른 ID의 결과를 표시명이 같다는 이유로 합치지 않는다.

공통 외부 가수 조회가 기존 정규화 함수로 이름과 별칭을 비교한다. 멤버 UID가 있는 내부 주체는 기존 별도 경로를 유지한다.

- 직접 등록·이름 변경은 유형과 무관한 충돌을 거절하고 기존 선택을 안내한다. 자기 자신은 제외한다.
- 곡 원곡 가수/가창자 인라인 생성·통합 등록/제안 승인·수집 후보 Ready는 일치하는 활성 외부 ID가 정확히 하나면 재사용한다.
- 보관 가수는 재등록하지 않는다. 여러 기존 ID가 일치하면 확인을 요구하며 임의 선택·병합하지 않는다. 실제 동명이인은 구분되는 이름을 사용한다.
- 중복 조회 전에 catalog revision을 읽고 같은 쓰기 batch의 CAS로 보호한다. Ready의 재사용만 하는 경로도 같은 배치에서 revision을 확인하고, 불필요한 revision 증가나 가짜 catalog 변경 응답은 만들지 않는다.
- 관리자 검증 오류는 기존 특수 오류 안내를 유지하면서 서버의 구체적 안내를 표시한다.

API·DTO·검색 SQL·스키마는 변경하지 않았다. 인증·소유권·보관·idempotency·수정 버전 충돌 계약과 Play/AI 자동화 중지를 유지했다.

작성만 하고 미실행한 테스트는 없다. 선별 전체 검증 후 변경한 것은 마지막 동시 등록 회귀 한 건뿐이며 해당 파일 전체를 다시 실행했다. 명령과 출력은 `.tmp/sul-43-final-tests.log`, `sul-43-ready-final.log`, 각 red/green 로그에 보존했다. 전체 preflight는 병합·배포 범위가 아니어서 실행하지 않았다.

실제 인증된 로컬 정상 관리자 화면에서 그룹 이름을 ` 요루시카! `로 저장하면 ‘이미 등록된 가수입니다. 기존 가수를 선택해 주세요.’로 거절됐다. D1에서 두 기존 ID/이름/version0이 그대로임을 확인했다. 구분되는 `요루시카 (로컬 검증용)`으로 저장하면 기존 그룹 ID/version1로 반영됐고 개인 ID/version0과 기존 제안의 두 원곡 가수 ID/순서·그룹 코러스가 보존됐다. 인증 우회나 응답 mock은 사용하지 않았다.

이전 ID 보존 단계에서는 같은 개발 계정으로 정상 회원 화면 → 실제 YouTube 정보 조회 → 두 기존 ID 선택 → 제안 생성 → 내 제안 상세 → 수정 → 메모만 변경 → 저장을 수행했다. 로컬 제안 `94542a66-2003-4092-b2ab-1c04bcb0a645`의 version0→1, 같은 두 ID/순서·코러스 역할을 실제 저장 행으로 확인했다. 운영에 시험 제안은 만들지 않았다.

로컬 환경은 기존 DB의 일관된 읽기 전용 백업을 격리 작업 트리에 복제하고0157/0158을 로컬 적용했다. 초기 빈 DB의 기존0030 backfill 실패는 해결하거나 전체 migration 성공으로 간주하지 않았다. 원본 작업 공간 DB는 그대로다. 브라우저의 일부 캡처/탭 요청은 시간 초과됐지만 정상 UI 최종 상태와 D1 readback은 확인했다.

## 남은 한계·경계

새 중복 방지 코드는 배포하지 않아 운영 효과를 확인하지 않았다. 운영 데이터 한 건 정리 완료와 로컬 패치 검증을 구분한다. 모든 수정 경로의 실제 브라우저 조합을 실행한 것은 아니며 승인·Ready 등은 실제 D1 통합 테스트로 검증했다. 최초 중복 발생 화면의 과거 상태와 두 행의 등록 경위는 미확정이다.

커밋·푸시·PR·병합·배포·원격 migration·새곡 승인 절차 재설계·다른 가수 정리·Play/AI 자동화 재개는 하지 않았다.
