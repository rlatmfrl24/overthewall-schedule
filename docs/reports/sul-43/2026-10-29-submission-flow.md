# SUL-43 제안 수정·승인 반복 확인 축소

이 문서는 구현 단계의 커밋 전 실행 기록이다. 이후 전체 리뷰·교정·PR 준비 결과는 [전체 리뷰](2026-10-29-review.md)를 따른다.

검증일: 2026-10-29 KST. 기준 HEAD: 36625f9265a8f6e097eddd4d0a67fc553000e49a. 기존 가수 선택 ID/중복 방지 미커밋 패치 위에 더한 변경이다. 이번 수정은 회원/관리자 화면 두 곳과 회귀 테스트에 한정한다. 커밋·푸시·배포·운영 데이터 변경은 없다.

## 변경 결과

- 내 제안 수정은 저장된 내용을 확인하는 마지막 단계에서 시작한다. 영상 주소·신청 유형이 그대로이면 저장된 제안의 영상 정보를 사용하므로 메모만 바꾸고 바로 저장할 수 있다. 새로 조회했다는 표시를 만들지 않고 ‘저장된 제안 영상’으로 표시한다.
- 영상 주소를 바꾸면 기존 확인 상태가 지워지고 다시 확인해야 한다. 새 제안의 영상 확인 흐름은 그대로다.
- 관리자 제안 검수를 열면 영상·채널을 자동 조회한다. 조회 중/실패·중복·부적합 채널·미확인 가창 credit은 승인을 막는다. 수동 ‘다시 확인’은 오류 복구/최신 상태 확인용으로 남는다.
- 실제 가창자 확인 체크와 ‘확인 후 승인·게시’ 버튼을 유지한다. 같은 내용을 다시 묻던 별도 승인 확인창은 제거했다. 게시된다는 안내와 버튼 의미는 명시적으로 유지한다.
- 실패 시 입력·제안 버전·재전송 키와 결과 메시지를 보존한다. 늦은 조회 응답이 떠난 제안에 반영되지 않는다. 다른 제안이나 보관/처리 완료 자료에 자동 조회를 적용하지 않는다.

## 유지한 서버 경계

이번 변경에서 API·DTO·Worker·스키마는 수정하지 않았다. 기존 회원 수정은 본인 소유/pending_review, 입력, 중복, 참조/보관 상태, expectedVersion·idempotency를 계속 검사한다.
관리자 승인은 제안/카탈로그 버전, 실제 가창자 확인, 게시 의사, 최신 YouTube 영상, 승인·활성 채널과 유형, 구간, 중복 및 원자적 저장을 계속 검증한다. UI의 추가 확인창 제거는 이 서버 검증을 생략하지 않는다. Play/AI 자동화 중지는 유지한다.

## 실패 회귀부터 수행한 검증

1. 기존 동명 ID/역할 보존 테스트를 강화해 영상 재확인이나 중간 단계 이동 없이 메모를 저장하도록 했다. 수정 전에는 메모 입력에 접근할 수 없어 실패했다.
2. 저장된 영상 URL을 바꾸면 조회 실패 상태에서 저장으로 넘어갈 수 없도록 하는 회귀를 추가했다. 수정 전에는 최종 수정 단계에서 시작하지 않아 실패했다.
3. 관리자 진입만으로 조회하고 실제 가창자 확인 후 즉시 승인 요청하는 회귀를 추가했다. 추가 확인창을 거절하는 의존성 조건에서도 정상 승인 결과를 확인한다. 수정 전에는 자동 조회가 없어 실패했다.
4. 저장된 영상을 재확인 필요로 오인시키는 문구도 실패 회귀로 확인한 뒤 수정했다.

예상한 네트워크/API 실패 테스트의 기존 stderr 진단은 남아 있다. 위 ‘통과’는 출력에 오류 로그가 전혀 없다는 뜻이 아니다. 전체 preflight/릴리스는 요청 범위가 아니다. 로컬 서버 신규 실행은 inspector9229 충돌로 두 번 종료됐다. 조사 결과 이 작업 트리에서 앞선 검토 때 실행한 서버가 살아 있어 충돌한 것이었다. 원래 서버의 HEAD200과 경로·시작 시각을 확인해 같은 서버를 재사용했다. 제품 코드나 테스트 설정을 바꾸지 않았다.

## 실제 정상 흐름과 저장 결과

기존 Clerk 개발 계정으로 인증된 정상 화면과 기존 격리 로컬 D1 표본을 사용했다. 응답 mock·인증 우회·직접 SQL 쓰기는 하지 않았다. 표본 이름/credit은 검증용이며 실제 영상의 음악 정보가 정확하다고 인증하는 작업은 아니다.

- 내 제안 → 표본 상세 → 수정에서 곧바로 ‘이 내용으로 보낼까요?’와 메모 입력이 보였다. ‘저장된 제안 영상’으로 표시됐으며 영상 확인 버튼이나 중간 단계 이동 없이 메모를 바꿔 저장했다.
- 제안94542a66-2003-4092-b2ab-1c04bcb0a645의 version1→2와 메모 반영, 같은 영상/제목·두 가수 ID/순서·멤버 UID/코러스 역할을 D1 읽기 전용 조회에서 assert했다.
- 관리자 가져오기/검수 → 사용자 제안 → 검수 열기에서 추가 클릭 없이 실제 YouTube 영상·채널 조회가 완료됐다. 미등록 채널은 기존대로 소유자 확인을 요구했고, 로컬 표본의 주체를 명시적으로 연결했다.
- 가창자 확인 체크 → ‘확인 후 승인·게시’ 버튼 한 번으로 별도 확인창 없이 처리됐다. 대기 목록에서 빠지고 카탈로그에 ‘게시됨1’이 표시됐다.
- 제안status=approved/version3, 가창83f1e9dd-00d5-4315-ab70-7451e1b9924a/publication_status=published, 곡c3e8c20c-f1ff-47b8-8daa-8d1a2c0a3d5e와 기존 가수 ID/순서·가창자/역할을 읽기 검증했다. catalog/read-model revision은 둘 다3이다.

증거는 .tmp/sul-43-flow-local-before.json, sul-43-flow-local-memo.json, sul-43-flow-local-approved.json과 process-review/approval-catalog.jpg에 보존했다. 메모 완료 화면의 후속 클립 캡처는 로딩 프레임으로 확인돼 증거로 사용하지 않는다. 승인 후 카탈로그 캡처는 저장 파일을 열어 실제 결과를 확인했다.

## 전달·남은 범위

이번 흐름 변경만의 증분 패치는 .tmp/sul-43-submission-flow.patch다. 앞선 가수 ID/중복 방지 변경을 함께 포함한 .tmp/sul-43-with-submission-flow.patch도 만들었고, 깨끗한 원본 master에 git apply --check로 검증했다. 실제 적용이나 커밋은 하지 않았다.

운영 배포·운영 시험 제안·운영 승인·원격 migration은 수행하지 않았다. 서버 권한·중복·CAS 등은 기존 실제 Worker/D1 테스트를 포함한 전체 테스트로 검증했고, 악의적인 입력의 모든 조합을 브라우저로 재실행하지는 않았다. 새 코드의 운영 효과는 미배포 상태여서 미확인이다. Play/AI 중지를 유지한다.
