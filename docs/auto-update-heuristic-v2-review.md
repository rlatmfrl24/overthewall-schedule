# 자동 일정 업데이트 휴리스틱 V2 분석 보고서

## 결론

자동 업데이트는 “방송 기록마다 일정 후보를 추가”하는 기능이 아니라,
기존 방송 스케줄 누적 내역에서 시간·제목이 비어 있는 부분을 보완하는
기능으로 재정의했다. 과거 데이터는 분류 기준 검증과 회귀 테스트에만
사용하며 DB 후보를 소급 생성하거나 식별자를 추정 백필하지 않는다.

## 기존 방식의 문제

- VOD마다 예정 시각 ±30분만 비교해 방송 중단·재개 조각을 서로 다른
  방송으로 오인할 수 있었다.
- 예정 시각보다 30분 이상 늦게 시작한 정상 방송을 신규 일정으로
  분류했다.
- 완성된 기존 일정이 있는 날의 짧은 테스트 방송까지 신규 후보가 될 수
  있었다.
- 제목, 결손 필드, 복수 일정의 관계를 함께 보지 않아 자동 판단의 근거와
  불확실성을 Admin에서 설명하기 어려웠다.

회귀 fixture에는 다음 형태를 고정했다.

- 종료 46초 후 재개한 VOD 두 조각은 하나의 세션
- 종료 35분 후 재개한 VOD 두 조각은 하나의 세션
- 예정 시각보다 39분 늦은 방송은 기존 일정과 시간 매칭
- 종료 후 2시간 41분이 지난 실제 복수 방송은 독립 세션
- 7분 방송은 같은 날 완성 일정이 있을 때 `short_suppressed`

fixture는 원본 운영 데이터의 식별자를 복제하지 않고 시간 간격과 분류
형태만 보존한다.

## V2 판정 순서

1. `vod_id`로 관측을 멱등 저장한다.
2. 같은 멤버의 인접 VOD 간 공백이 60분 이하면 방송 세션으로 병합한다.
3. 같은 멤버·세션 시작일의 `방송`, `미정`, `게릴라` 일정을 대상으로
   일대일 매칭한다.
4. 60분 이내의 유일한 최단 시간 차이를 우선한다.
5. 시간 매칭이 없으면 제목 완전 일치·포함·bigram Dice 0.6 이상인
   유일한 일정을 선택한다.
6. 시간·제목이 모두 없는 일정과 남은 세션이 각각 하나일 때만 fallback
   연결한다.
7. 복수 제목 후보나 최상위 시간 점수 동률은 `ambiguous`로 남긴다.
8. 완성 일정은 후보를 만들지 않고, 불완전 일정은 빈 필드만 보완하며,
   매칭되지 않은 독립 세션만 새 일정 후보로 만든다.
9. 휴방일과 조건에 해당하는 10분 미만 세션을 억제한다.

## 운영 확인 지표

- `segmentCount`: 판단에 사용한 VOD 조각 수
- `sessionCount`: 병합 후 방송 세션 수
- `resumeMergedCount`: 세션 병합으로 줄어든 조각 수
- `shortSuppressedCount`, `holidaySuppressedCount`: 휴리스틱 억제 효과
- `ambiguousCount`: 관리자 대상 선택이 필요한 후보
- `obsoletePendingCount`: 승인 전 상태 변화로 정리한 stale 후보
- `rejectedSuppressedCount`, `duplicatePendingCount`: 영구 제외와 반복 수집
  방어 효과

## 한계와 운영 원칙

- 60분은 운영 사례를 반영한 고정 경계이며, 실제 독립 방송이 60분 이내
  재개되면 같은 세션으로 합쳐질 수 있다. 운영 지표와 거부 사유를
  주기적으로 검토해 기준 변경 여부를 판단한다.
- 제목 유사도는 보조 기준이다. 복수 후보가 있으면 점수가 더 높더라도
  자동 확정하지 않는다.
- 세션 시작일에 `휴방`이 있으면 해당 날짜의 모든 세션을 억제한다.
- 기존 거부 로그에 정확한 VOD 식별자가 없으면 추정 연결하지 않는다.
