# SUL-11: 폰트 일관성 개선 결과

작성일: 2026-09-14. 기존 Inter 유지, 한글 Pretendard 추가, 자체 제공 및 시스템 폰트 저장 대체를 구현했다. 제품 기준은 `Design.md`, 자산의 버전·출처·해시·라이선스는 `public/fonts/README.md`에서 관리한다.

## 적용한 정책

- 일반 화면의 공통 순서는 `Inter, "Pretendard Variable", system-ui, sans-serif`다. Google Fonts 요청을 제거했다.
- Inter 4.1과 Pretendard 1.3.9의 전체 가변 WOFF2를 제공한다. 설치된 폰트를 우선하지 않으며 `font-display: swap`을 유지한다. 두 폰트 모두 400–900 요청을 실제 가변 축으로 지원한다.
- 버전별 자산 경로에 1년 immutable 캐시를 지정했다. 폰트 업데이트는 새 버전 경로로 배포한다. 기존 URL의 파일을 덮어쓰지 않는다.
- 일반 화면은 폰트 로드 중·실패 시에도 시스템 폰트로 읽을 수 있다. 사용자 확대·접근성 설정을 제한하지 않는다.
- 이미지 저장·복사는 폰트 준비 실패 시 시스템 폰트로 계속 제공한다. 대체 사용 사실은 기존 완료 안내에 표시한다. 이는 사용자가 선택한 정책이다.

## 스냅샷의 실제 흐름

홈의 다운로드/복사 메뉴 → 기존 동일 출처 스냅샷 iframe → 일정 데이터 렌더링 및 폰트 준비 → 텍스트 재측정 → 준비 신호 → PNG 생성 → 다운로드/클립보드 쓰기 순서를 유지했다.

`prepareSnapshotFonts`는 두 파일을 읽고 FontFace로 디코딩하며 PNG에 포함할 동일 바이트의 CSS를 준비한다. 이 작업 전체에 3초 제한을 적용한다. 이미지·데이터 등 다른 준비 시간을 포함한 전체 저장 시간이 3초라는 뜻은 아니다.

준비된 폰트는 스냅샷 전용 패밀리 이름으로 등록한다. 정상 경로는 이 폰트로 레이아웃을 계산하고 동일 바이트를 `fontEmbedCSS`로 전달한다. 라이브러리의 기본 폰트 다운로드가 오류를 삼키는 동작에 성공 판정을 맡기지 않는다.

HTTP 실패, 폰트 디코딩 실패, 시간 초과 시 시스템 폰트로 고정한다. 정상 PNG 생성이 실패하면 시스템 폰트로 전환해 재측정한 뒤 한 번 더 생성한다. 두 번째 생성도 실패하면 기존 저장 실패 안내를 사용한다. 나중에 도착한 웹폰트가 시스템 폰트로 결정된 스냅샷의 배치를 바꾸지 않는다.

폰트 상태 변경은 텍스트 자동 맞춤의 재측정을 유발한다. 데이터·보기·테마·폰트 상태에 대응하는 렌더가 반영되고 두 animation frame이 지난 후 준비 신호를 제공한다. 언마운트 시 다운로드를 취소하고 타이머·이벤트 구독·등록 폰트를 정리한다.

공개 API·DB·인증·스냅샷 URL 쿼리 계약은 변경하지 않았다. 폰트 상태와 포함용 CSS 전달은 동일 출처 iframe의 내부 이벤트로 처리한다.

## 자산 검증

| 파일 | 실제 바이트 수 | 폰트 메타데이터 |
| --- | ---: | --- |
| InterVariable.woff2 | 352,240 | 가변 굵기 100–900, 광학 크기 14–32 |
| PretendardVariable.woff2 | 2,057,688 | 가변 굵기 45–930, 완성형 한글 11,172자 포함 |
| 합계 | 2,409,928 | 폰트별 파일 하나, 사용자 입력에 맞춘 임의 축소 없음 |

파일의 SHA-256과 WOFF2 문자 매핑·가변 축을 직접 확인했다. Pretendard의 `가`, `힣`, 호환 자모 `ㄱ`과 영문·숫자 샘플이 포함된다. 조합용 자모 `ᄀ`처럼 포함되지 않은 문자는 시스템 대체 대상이다. 모든 유니코드·이모지 또는 OS별 픽셀 렌더링까지 통일하는 변경은 아니다.

## 실제 사용자 흐름 결과

Windows의 Codex 브라우저에서 `http://localhost:5181/`을 사용했다. 기존 로컬 D1을 전용 작업 폴더로 복사해 검증했고 운영 데이터는 변경하지 않았다. UI 날짜 이동으로 기존 일정이 있는 2026-09-10을 선택했다. 아래 시간은 메뉴 선택 직전부터 완료 안내를 관찰할 때까지의 벽시계 시간이며, 브라우저 제어 지연도 포함한다.

404 조건은 전용 작업 폴더의 두 폰트를 잠시 이동해 실제 HTTP 404를 확인한 뒤 같은 홈 메뉴를 사용해 만들었다. 검증 후 두 파일을 복원했고 HTTP 200과 최종 빌드 포함을 다시 확인했다. 정상·시스템 그리드/타임라인 PNG 사본은 로컬 `.tmp/sul11-evidence/`에 보존했다. PNG에서 시스템 대체 시 줄바꿈이 달라지는 것을 확인했고 해당 텍스트는 출력되었다.

폰트 HTTP 다운로드를 캐시 없는 별도 curl 요청 두 건으로 측정했다. Inter는 352,240 bytes/0.003383초, Pretendard는 2,057,688 bytes/0.008557초였다. 이는 로컬 서버 전송량이며 운영 네트워크나 브라우저 콜드 캐시의 전체 페이지 성능 측정은 아니다. 브라우저 Resource Timing은 현재 제어 인터페이스에서 접근할 수 없어 실제 콜드 캐시 요청 수·전송량은 미측정이다.

## 화면 확인과 남은 제한

- Codex 브라우저 1280px 데스크톱 라이트/다크, 390×844 모바일 다크에서 홈을 확인했다. 모바일 주간 일정·VOD, 데스크톱 프로필과 저장 완료 다이얼로그도 확인했다. 주간 일정의 기존 가로 스크롤은 유지된다.
- Windows Chrome 1920px 홈에서도 공통 폰트와 웹폰트 2개 로드 상태를 확인했다. Codex 브라우저에서는 Inter와 Pretendard의 900 굵기 로드 확인도 성공했다. 글리프별 DevTools Rendered Fonts 이름은 수집하지 못했으므로 CSS 계산값만으로 모든 글자의 실제 폰트를 확인했다고 주장하지 않는다.
- 관리자 화면은 Chrome 로그인 계정의 서버 권한 검사에서 접근이 거부되었다. OTW Play는 관리자 미리보기만 허용하는 로컬 설정이므로 내부 화면을 검증하지 못했다. 권한 검사는 변경하지 않았다.
- 200% 확대 키 입력은 두 브라우저 제어 인터페이스에서 실제 배율 변화로 이어지지 않았다. 따라서 200% 확대는 미검증이다. macOS/iOS Safari, Android Chrome 및 Edge 실기기도 미검증이다.
- 클립보드 쓰기 성공 안내는 확인했지만 브라우저 도구의 클립보드 읽기는 빈 목록을 반환했다. 외부 앱에 붙여넣은 결과까지 확인한 것은 아니다.
- VOD 화면의 Shorts 요청에는 별도 로컬 API 오류가 보였다. 폰트 적용·일반 동영상 표시는 확인했으며 이 데이터 오류를 폰트 작업에 포함하지 않았다.
- 느린 네트워크의 실제 브라우저 재현은 하지 않았다. 3초 제한·취소·지연 후 재측정은 회귀 테스트로 검증했다.

현재 변경은 로컬 구현과 검증까지다. 커밋·푸시·배포하지 않았다. 기존 SUL-8 작업 폴더의 미커밋 변경을 보존했으며 테스트나 대체 경로를 정상 웹폰트 동작의 증거로 사용하지 않았다. 초기 전체 폰트 용량 약 2.41MB는 남는 비용이며 향후 최적화는 한글 범위와 이미지 포함 계약을 유지해야 한다.
