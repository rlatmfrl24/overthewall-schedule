# AI 검수 요청 분석과 최적화 — 2026-09-22

## 결론

기본 모델은 `gemini-3.8-flash`, 추론은 `low`, 영상 처리는 전체 요청 구간 `static / 1fps`를 유지한다. 저비용 모델 전환이나 영상 축소보다 기존 결과 재사용을 안정화하고 중복 요청 지시를 제거한다. 운영 배포는 포함하지 않는다.

## 기존 요청 관찰

운영 D1의 `music_ai_reviews`와 `music_ai_review_attempts`를 읽기 전용으로 조회했다. 조회 메타데이터의 `rows_written=0`, `changed_db=false`를 확인했다. 로컬 기록과 운영 기록은 합쳐서 성공률을 계산하지 않는다.

| 구분 | 관찰 |
|---|---|
| 운영 | v4 / 3.8 Flash 16작업, 16시도 모두 succeeded |
| 운영 평균 토큰 | 입력 20,830.25 / 출력 907.5 |
| 운영 시도 소요 시간 | 최소 8.992초 / 중앙값 11.128초 / 최대 88.355초 |
| 로컬 변경 전 | 18작업: 성공 15, 실패 3. 실패 3건에 7시도(연결·할당량·선불 크레딧 문제) |
| 품질 제한 | succeeded는 호출 완료이며 정확도 판정이 아니다. 운영에는 곡 정보 또는 분류 근거가 검증에서 제외된 결과도 있다. |

원문 제공자 응답·정답 라벨·관리자 최종 수정과의 대응표는 저장되어 있지 않다. 따라서 과거 결과만으로 모델별 정확도나 오류율을 확정하지 않는다. 입력 대부분은 영상이며 프롬프트 축약만으로 큰 비용 절감을 기대하기 어렵다.

## 실제 모델 비교

공개 영상 `mB4qjzLqnw0`(한국어 방송 클립), `lk4XWoTHiwM`(한·일 병기 방송 클립), `390Dz8q6C_g`(공식 커버)에 동일한 기존 프롬프트, 전체 영상, 1fps, low, 응답 스키마를 사용했다. 각 모델·영상 조합을 한 번 호출했다. 실제 Gemini 호출이며 테스트 대역이 아니다. 비교 호출은 DB에 작업을 만들거나 카탈로그를 수정하지 않았다.

| 모델 | 3건 입력 합계 | 출력 합계 | 소요 시간(영상 순서) | 관찰 |
|---|---:|---:|---|---|
| 3.8 Flash | 60,377 | 2,421 | 10.488 / 8.295 / 7.602초 | 모두 곡 제안 보존, 필드 제외 경고 없음 |

Flash-Lite가 모든 영상에서 빠르지는 않았고, 공식 커버의 원곡 가수는 3.8의 HoneyWorks와 다른 `가루루`로 반환했다. 어느 결과도 정답 라벨을 대체하지 않는다. 이 표본으로 저비용 모델을 기본값으로 채택할 근거는 부족하다. 메들리·듀엣·장시간 영상은 비교하지 않았다.

[공식 가격표](https://ai.google.dev/gemini-api/docs/pricing)의 현재 1M 토큰 단가는 3.8 Flash 입력 $0.75/출력 $3.75, 3.5 Flash-Lite 입력 $0.30/출력 $2.50다. 3.8 가격은 2026년 말까지의 도입 가격이므로 이후 재확인이 필요하다. [3.8 모델 안내](https://ai.google.dev/gemini-api/docs/latest-model)는 지연이 중요한 작업의 low 추론을 지원한다. [영상 처리 안내](https://ai.google.dev/gemini-api/docs/video-understanding)에 따라 짧은 클립의 전체 구간 관찰과 시간 정보 보존을 위해 static을 유지한다. 선택적 agentic 처리나 fps 축소는 이번에 적용하지 않는다.

## 최종 변경과 검증

- 프롬프트의 반복 시간·제목 설명만 제거했다. 크게 축약한 별도 실험에서는 공식 커버 곡 정보가 제외되어 채택하지 않았다.
- 구간·완곡 여부의 관찰 근거는 이미 values에 필수로 들어간다. 응답 스키마에서 동일 근거를 evidence에도 중복 생성할 슬롯을 제거했다. 근거 검증·요청 범위·원본 방송 확인 규칙은 유지한다.
- 프롬프트에 보낼 데이터와 캐시 키를 같은 함수에서 구성한다. 썸네일·내부 상태는 캐시 키에서 제외하고 태그·별칭 순서를 정규화한다. 실제 제목·설명·구간·모델·프롬프트가 바뀌면 새 요청이며, 공개 여부 확인은 캐시 재사용 전에도 수행한다. 강제 재분석과 24시간 재사용 기한은 유지한다.
- 새 요청은 v5로 구분한다. 동일 결과 계약의 v4는 계속 조회·적용할 수 있으며 오래된 v1~v3는 계속 차단한다. 기존 완료 결과를 읽는 행위로 유료 분석을 다시 실행하지 않는다.

동일 3건으로 최종 3.8 요청을 다시 호출한 결과 입력 합계는 **60,377 → 60,176(-0.33%)**, 출력은 **2,421 → 2,461**, 중앙값은 **8.295 → 7.796초**였다. 모든 곡 제안과 구간·완곡 필드를 보존했고 필드 제외 경고가 없었다. 출력 변동까지 포함한 추정 비용은 두 경우 모두 약 **$0.05436**으로 사실상 같았다. 각 조건 1회이므로 지연 개선·품질 동등성을 통계적으로 입증한 결과는 아니다. 주요 기대 효과는 분석 무관 정보 변경으로 발생할 불필요한 재호출 방지다.

회귀 테스트는 실제 D1 저장소를 통해 완료 결과 재사용, 설명 변경 시 새 작업, 비공개 영상 거부, 강제 재분석과 v4 결과 호환을 확인한다. 모델 응답을 흉내 낸 테스트로 실제 모델 품질을 주장하지 않는다.

로컬 관리자 검수 화면의 `재분석`으로 `4LscuFk79iA`를 실행했다. 작업 `3dcc3822-462b-4053-97b7-7a6cc5b87d90`은 v5 / 3.8 Flash로 1시도, 16.352초에 succeeded가 되었으며 입력 26,791 / 출력 971토큰을 기록했다. 화면과 저장 결과 모두 기존 곡 `34c00358-5b34-4382-99a8-4cf4eb8c3e43` 연결을 제안했다. 이어 같은 화면의 `AI로 자동 채우기`를 다시 실행하자 동일 작업이 재사용되었고 작업에 연결된 요청만 2건이 되었다. 전체 호출 시도 수는 23으로 유지되었다. 검수 저장·게시·운영 배포는 수행하지 않았다.
