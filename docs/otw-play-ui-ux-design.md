# OTW Play UI/UX 계약

기준: 2026-09-17. 공통 색상·타이포그래피·반응형 치수·접근성의 기준은
[Design.md](../Design.md)다. 이 문서는 사용자 동선과 상태 계약을 정리한다.
[과거 화면 설계](archive/otw-play-ui-ux-design-before-2026-09-17.md)의 폐기 시안·관리자 전용
preview 단계·익명 공개 계획을 현재 화면으로 복원하지 않는다.

## 진입과 탐색

로그인 회원은 발견·곡 검색·플레이리스트를 이용한다. 비로그인은 로그인 안내,
회원 열람 비활성은 활성화 대기 안내, 관리자 권한 확인 실패는 재시도 가능한 상태로 표시한다.
관리자는 서버 권한을 확인한 preview와 노래 클립 탭을 사용한다.
회원 제안은 같은 Play 브랜드 안에서 별도 인증 shell로 이동한다.

발견은 hero, 멤버 탐색, 기본 플레이리스트 요약과 곡 탐색 동선을 제공한다.
hero는 7초 순환하고 hover·keyboard focus·숨겨진 탭에서 정지한다.
reduced-motion은 수동 전환만 사용한다. 키보드·터치·직접 선택을 유지한다.
멤버 선택은 독립 노래책이 아닌 member UID로 필터한 곡 검색으로 이동한다.
프로필의 Play 링크와 기존 멤버 URL도 같은 검색 흐름을 사용한다.

곡 검색은 URL 필터와 카드·표·그리드 보기 전환을 제공한다. 보기를 바꾸어도 검색 결과,
추가 페이지와 재생 상태를 보존한다. 추가 페이지 오류는 기존 결과를 지우지 않고 재시도를 제공한다.
곡 상세는 원곡·가창 버전·역할별 참여자·source attribution을 구분한다.
공식 목록과 관리자 클립 탐색을 혼합하지 않는다.

## 재생과 목록

데스크톱은 우측 player/queue, 좁은 화면은 Now Playing과 해당 폭의 visible player 정책을
사용한다. 동일 Play shell 내 탐색에서 재생 문맥을 보존한다. 보이지 않는 iframe 재생이나
두 번째 iframe을 만들지 않으며 닫기·이탈 시 pause/stop 경계를 유지한다.
조작 버튼에는 접근성 이름을 제공하고 source 재생 불가와 다음 행동을 안내한다.

queue는 같은 가창을 한 번만 보유한다. `재생`, `다음에 재생`, `마지막에 추가`를 구분하고,
전체 삭제는 현재 재생도 정지하며 저장 상태를 초기화한다. 복원 뒤 자동 재생하지 않는다.
플레이리스트 카드는 상세로 이동하고 전체 대기열 추가는 명시적 버튼에서 수행한다.
상세의 추가 완료 뒤 해당 목록의 첫 재생 가능한 곡을 처음부터 재생한다.
전체 페이지를 같은 revision으로 모으고 실패·취소·충돌 때 일부만 추가하지 않는다.
개인 목록은 독립 사본 또는 빈 목록에서 시작해 명시적으로 저장한다.
권한 오류·version 충돌·저장 실패를 성공 안내로 바꾸지 않는다.

## 회원 제안

영상 확인 → 곡 연결/새 곡 → 참여자/선택 metadata → 제출 확인 흐름을 사용한다.
공식 커버와 편집된 한 곡의 노래 클립을 구분하며 원본 전체 방송 구간은 신청 대상이 아니다.
metadata 확인과 곡 검색을 분리하고 업로더·업로드일로 가창자·방송일을 추정하지 않는다.
오류 후 입력·단계·idempotency key를 유지하고 이탈 시 입력 손실을 확인한다.
성공 후 권위 제출 결과와 다음 행동을 보여주고 새 양식은 명시적으로 시작한다.
내 제안에서 pending_review만 수정/철회하며 검수 충돌 시 최신 상태를 다시 안내한다.
내부 검수 note와 반려 code를 회원에게 노출하지 않는다.

## 관리자 등록과 검수

관리자는 영상 등록 작업 중심으로 곡·가창·채널을 연결한다. 일반 오리지널/커버 입력,
순차 메들리의 독립 곡 입력, 노래방송의 singing_clip 입력을 구분한다.
채널 관리의 상세 동선과 통합 console은 [관리자 흐름](otw-play-admin-workflow-integration.md)을 따른다.

가져오기 검수는 행별 입력과 실제 저장값 미리보기를 제공한다. Ready 저장한 곡/외부 identity는
다음 행에서 검색·재사용할 수 있어야 한다. Ready·draft 변환·게시를 다른 상태로 표시한다.
자동 metadata 갱신으로 관리자 검수값을 덮어쓰지 않으며 충돌은 재조회·수정 가능하게 표시한다.

노래 클립은 구간·가창자·방송일/근거·원본 URL·완곡 여부를 확인한다.
같은 영상의 다음 곡 입력에서 재사용값을 보존하되 곡과 완곡 여부는 초기화한다.
승인 clip 채널이 없으면 채널 관리로 이동할 수 있어야 한다.
구간 미리보기는 실제 YouTube iframe의 시작·일시정지·재개·끝 5초 전 확인을 제공하고
구간 끝에서 멈춘다. 대상·구간 변경, 닫기와 unmount에서 player를 정리한다.
미리보기로 저장·게시·AI 실행을 일으키지 않는다.

Gemini 자동 입력은 실행 상태·예산/실패·적용할 결과를 보여주고 수동값 덮어쓰기를 방지한다.
AI 결과를 확인 없이 게시하지 않는다. [AI 검수](otw-play-ai-review.md)의 실제 검증 범위를 따른다.

## 상태와 접근성 수용 기준

정상 0건, 로딩, 추가 페이지 실패, 전체 조회 실패, 인증 실패, 비활성화와 재생 불가를
각각 구분한다. 이전 데이터가 남아 있는 갱신 실패로 성공한 저장 자체를 실패 표시하지 않는다.
키보드 탐색·명확한 focus·터치 영역·긴 한국어 제목·모바일 내부 스크롤·reduced-motion을 유지한다.
실사용 완료는 실제 진입점에서 저장/게시/재조회/재생과 다음 행동이 가능해야 한다.
시안·fixture·테스트 성공을 운영 실기 검증으로 대신하지 않는다.
잔여 검증은 [개발 상태](development-status.md)에 기록한다.
