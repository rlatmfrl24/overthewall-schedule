# 공개 페이지 AEO (SUL-14)

## 제공 범위

오늘·주간 일정, 멤버 프로필, 공지, 공개 피드, VOD, 권리 안내는 직접 방문한
HTML에 읽을 수 있는 공개 본문과 JSON-LD를 포함한다. 앱 실행 시 기존 React
화면이 서버 본문을 대체하며 별도 요약 패널이나 오류·재시도 UI는 추가하지 않는다.
화면 요소를 만들지 않는 `SiteContentMetadata`가 초기 데이터를 재사용하고,
내부 이동 시 `GET /api/site-content?path=...`로 메타데이터·JSON-LD를 갱신한다.
일일·주간 이동은 `date=YYYY-MM-DD`로 선택한 날짜를 전달한다.
멀티뷰·관리자·스냅샷은 대상이 아니다.

JavaScript를 실행하지 않는 사용자도 서버 본문을 읽을 수 있으며 브라우저와
크롤러에 같은 HTML을 제공한다. 앱에서는 기존 화면 구성과 스크롤을 유지한다. 제목, 원문
링크, 일정 상태는 저장된 자료에서 가져온다. `방송`은 편성 상태이며 실제
생방송 중이라는 주장을 하지 않는다. 일정은 한국 시간과 월요일 시작 주를
사용한다. 조회 시각과 자료 갱신 시각은 구분한다.

일반 접속에서는 초기 문서의 짧은 스크립트가 저장된 테마를 적용하고
`불러오는 중…`을 표시한다. 라우터의 최초 화면이 준비되면 즉시 기존 UI로
전환하며 최소 대기 시간이나 추가 데이터 요청은 없다. 서버 본문은 React 루트
밖에 보존되어 JavaScript 미실행·번들 로드 실패·15초 초기화 지연에도 읽을 수 있다.
정상 전환 시 서버 본문과 로딩 요소만 제거하고 초기 데이터·JSON-LD·메타데이터와
캐시 정책은 그대로 사용한다. 크롤러의 User-Agent에 따른 분기는 하지 않는다.

## 데이터와 캐시

- `worker/features/seo`가 메타데이터와 요약을 구성한다. 데이터 접근은 각
  capability의 공개 읽기 인터페이스를 composition root에서 연결한다.
- 일정은 기존 schedule-board reader를 사용한다. Cache API에 최대 300초
  보관하며 한국 시간 자정에 만료한다. 응답의 남은 수명만 전달하므로 HTML과
  API를 거쳐도 최초 생성 시각부터 5분을 초과하지 않는다.
- 피드는 요청마다 소스별 공개 정책을 확인하고 `no-store`로 제공한다.
  숨김·삭제된 게시글과 회원/비공개 소스는 초기 데이터에도 포함하지 않는다.
- 영상은 기존 YouTube 수집 저장소와 CHZZK 저장 캐시만 읽는다. 페이지 방문은
  수집·원문 보강·외부 API 요청·D1 쓰기를 만들지 않는다. 저장 데이터가 없으면
  수집된 자료를 확인할 수 없다고 표시하며 빈 카탈로그라고 단정하지 않는다.
- 핵심 조회 실패는 503, `no-store`, `noindex`로 반환한다. 부가 소스별 실패는
  나머지 소스와 분리한다. 공개 설정이 조회 도중 바뀌면 결과를 반환하지 않는다.
- 공개 피드 소스가 모두 실패하면 빈 목록으로 처리하지 않고 핵심 조회 실패로
  전파한다. 일부 소스만 실패하면 성공한 소스의 결과와 실패 상태를 함께 제공한다.
- 클라이언트 조회 실패 뒤에는 60초 후 재조회하며, 성공하면 원래 만료 시각에
  맞춘 주기로 돌아간다. SEO 정보는 갱신 주체별로 관리하여 AEO 실패가 정상
  프로필·피드 화면의 메타데이터를 삭제하지 않게 한다.
- 로컬 개발 서버도 Worker 문서 경로를 보존한다. 주간·프로필 등의 직접 방문을
  홈 경로로 바꾸지 않으며, Worker가 공통 HTML 자산에 해당 페이지 데이터를 넣는다.

## OTW Play 공개 전환

현재 `contracts/otw-play-access.ts`의 제품 정책은 `members`다. 인증, 클라이언트
접근과 SEO가 이 정책을 사용한다. `publicReadEnabled`는 이용 활성화이며
`navigationVisible`은 메뉴 노출이므로 두 값만으로 익명 공개를 허용하지 않는다.

향후 익명 공개가 승인되면 이 공통 정책을 `public`으로 변경하여 배포하고,
홈과 게시된 곡 상세의 실제 익명 접근을 검증한다. 준비된 콘텐츠 어댑터가
곡·참여자·공식 영상 링크를 제공한다. 검색 화면은 `noindex`이며 플레이리스트,
회원 제안, 관리자 전용 노래 클립의 인증은 별도 계약대로 유지한다.
Play 요약은 `no-store`로 제공하고 접근 정책·catalog revision을 다시 확인한다.
Play HTML과 동적 사이트맵도 `no-store`로 제공하여 공개 철회가 공유 캐시에 남지 않게 한다.
정책이 불명확하면 공개하지 않는다.

## 검증과 관찰

테스트는 날짜·주 경계, 캐시 만료, 공개 범위, 정책 변경, 안전한 HTML/JSON
직렬화, 화면 이동 및 실제 D1 스키마의 SELECT-only 조회를 다룬다. 최종 검증은
`pnpm preflight`와 실제 Worker HTML/API 및 브라우저 readback으로 수행한다.

배포 후에는 배포 커밋을 확인하고 대표 URL의 초기 본문·canonical·robots·JSON-LD와
사이트맵을 다시 확인한다. Search Console의 실제 수집·색인 상태와 검색 유입은
별도 관찰한다. AI 답변 채택과 노출 증가는 기술 검증만으로 달성했다고 판단하지 않는다.
`llms.txt`, 학습용 봇 정책 변경과 AI 생성 요약은 추가하지 않는다.

근거: [Google AI features and your website](https://developers.google.com/search/docs/appearance/ai-features).

### 로컬 구현 검증 (2026-09-22)

- Node 24.20에서 `pnpm preflight` 전체 통과: 311개 파일·2,385개 테스트,
  타입 검사·lint·아키텍처·빌드·D1 진단·규칙 동기화 검사.
- 빌드된 Worker와 기존 로컬 D1으로 8개 경로의 초기 HTML·API·JSON-LD 내용 일치,
  일반 요청과 Googlebot 요청의 공개 내용 일치, HEAD·301·404·400 응답 확인.
- 저장된 2026-09-14 일정 7건의 방송·휴방·게릴라 상태와 편집 시각을 기존
  `/api/schedule-board` 응답과 대조. 피드 10건, VOD 5개 분류별 5건 확인.
- UI 복원 후 브라우저에서 추가 요약 패널이 없는 오늘·주간 화면, 주간 이동 시
  JSON-LD 날짜 변경, 프로필의 Person 데이터 유지를 확인했다. 390px 모바일
  프로필에서도 기존 레이아웃과 스크롤이 유지되며 가로 넘침이 없다.
- React 화면에는 AEO 목록·오류·재시도 요소를 렌더링하지 않는다. 초기 HTML에는
  기존 공개 본문과 JSON-LD가 유지되며 실제 API 응답과 내용이 일치한다.
- 로딩 문서는 저장된 라이트·다크·시스템 테마, JavaScript 미실행, 실행 실패,
  시간 초과와 늦은 완료를 포함한 10개 테스트로 확인했다. 실제 앱 번들 응답을
  지연시킨 브라우저에서 양 테마의 로딩 문구와 기존 UI 전환을 확인했고, 같은
  Worker HTML의 스크립트 실행을 차단한 브라우저에서 서버 본문 표시를 확인했다.
- 공개 요약 API 8건의 로컬 추적: D1 읽기 18회, D1 쓰기 없음. 저장 콘텐츠
  통합 테스트에서도 SELECT-only와 외부 수집 호출 없음을 확인.
- 현재 Play 카탈로그 익명 요청은 401이며 HTML 초기 데이터의 곡 목록·JSON-LD와
  사이트맵에서 제외된다. 미래 공개 정책은 테스트로 검증했으며 실제 공개 전환
  이후 익명 브라우저 경로 검증은 별도로 필요하다. 운영 배포는 수행하지 않았다.
- 회귀 조치 후 만료·조회 실패의 1초 반복 요청 차단과 복구 후 정상 주기 복귀,
  AEO 실패 시 정상 프로필 메타데이터 유지, 피드 전체/부분 소스 실패를 검증했다.
  개발 서버 8개 경로의 HTML과 API 내용이 일치하며, 브라우저 주간 새로고침도
  다크 로딩 화면에서 기존 일정표로 전환하고 JSON-LD·색인 정책을 유지한다.
