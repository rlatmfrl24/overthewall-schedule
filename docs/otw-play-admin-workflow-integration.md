일반 방송 클립(VOD) 채널은 수집 관리에 유지한다. Play와 저장소·승인·수집 설정을 공유하지 않는다. 채널 화면에 있던 외부 인물·그룹 관리는 카탈로그의 인물·그룹 화면으로 이동했다.

## 가져오기부터 등록까지

카탈로그의 `새 영상 등록 → 노래방송`도 노래 클립 직접 등록을 사용한다. 승인된 활성 Play 노래 클립 채널의 영상을 곡·가창자·방송 정보와 연결해 비공개 저장하며, 등록 후 노래 클립 필터에서 결과를 확인한다. 여러 곡이 담긴 영상은 구간을 지정해 한 곡씩 저장한 뒤 `같은 영상의 다음 곡 추가`로 이어서 입력한다. 각 구간은 별도의 가창이며 방송 전체의 setlist나 자동 곡 분할을 생성하지 않는다.

1. 가져오기/검수 → 새 가져오기·이력에서 공식 곡 또는 노래 클립을 선택한다.
2. 플레이리스트 URL과 전체·최근·범위 수집 설정을 사전 확인하고 시작한다. 최대 5,000개 제한은 유지한다.
3. 검수 목록에서 가져오기 이력을 선택하고, 해당 이력의 `검수 열기`로 전용 화면에 진입한다. 영상 옆에서 곡·가창자·재생 구간을 검수하고, 노래 클립은 방송일·원본 링크·완곡 여부를 함께 저장한다. 자동 수집과 사용자 제안은 출처를 전환해 확인한다.
4. 채널 승인이 필요하면 채널 탭의 해당 채널 편집 페이지로 이동한다. 저장 후 `작성 중인 검수로 돌아가기`를 선택하면 이력·후보·필터와 검수 입력을 이어간다. 채널 정보 갱신으로 작성 중인 검수 입력을 초기화하지 않는다.
5. 검수를 저장한 후보를 선택해 일괄 임시 등록한다. 성공한 항목은 선택에서 제외하고 실패한 항목은 사유와 선택을 유지한다.
6. 카탈로그에서 결과를 확인한 뒤 별도로 게시한다. 사용자 제안의 기존 명시적 승인·게시 동작은 유지한다.

자동 수집을 켜지 않아도 직접 등록과 플레이리스트 가져오기는 가능하다. 플레이리스트 소유자가 아니라 개별 영상 업로드 채널의 Play 승인을 확인한다. 원본·방송일 미확인 허용, 완곡/일부 구분, 사용자 공개 화면과 플레이리스트 저장 제한은 기존 확정 정책을 유지한다.

## 계약과 저장

- 사전 확인·가져오기 생성 및 작업 조회에 `candidateKind`를 추가했다. 값은 `official_video` 또는 `singing_clip`; 기존 요청 생략값은 공식 영상이다.
- `0090_demonic_sugar_man.sql`은 `music_ingestion_jobs.candidate_kind`를 기본값 `official_video`로 추가한다. 기존 작업·후보를 삭제하거나 재분류하지 않는다.
- 작업 재시도는 저장된 종류를 따른다. 이전 가져오기 탐색과 멱등 요청 비교도 종류를 구분한다.
- `GET /api/play/admin/review-items`는 관리자 인증과 no-store를 적용한다. 종류·출처·처리 상태를 필터링하며, 50개 단위 커서에 필터와 정렬 위치를 포함한다.
- `jobId`를 지정하면 해당 가져오기 작업의 후보 출처를 기준으로 목록을 제한한다. 페이지 커서는 작업 ID도 검증하며, 서로 다른 이력의 커서를 재사용할 수 없다. 생략한 API 요청은 기존 조회 범위를 유지한다.
- 후보 하나가 여러 플레이리스트·자동 수집 경로에서 발견되어도 후보는 재사용한다. 이미 등록된 영상은 중복 생성하지 않는다.
- 후보 PATCH의 `change_kind`는 버전 검사와 감사 기록을 남기며 미등록 후보의 종류만 정정한다. 이전 검수 원문은 감사 기록에 보존하고 등록 준비 상태를 해제하여 재검수한다.
- 이력 삭제는 감사 이벤트를 사용하는 논리 삭제다. 카탈로그와 검수 후보를 보존하고 수집·재시도 대기 작업을 차단한다.
- 기존 관리자 `clips`, `clip-channels`, `review`, `automatic-review`, `play-monitor`, `source-health` 진입은 통합 작업 화면으로 연결한다.

## 검증과 전달 상태

### 가져오기 화면 후속 정리

- 가져오기 화면의 중복 후보 목록·행별 편집기·일괄 등록 UI를 제거했다. 후보 검수와 임시 등록은 통합 검수 목록에서 진행한다.
- 선택한 이력의 수집 상태·오류·재시도는 이력 영역 안에서 확인한다. `검수 목록으로 이동`은 해당 영상 종류와 플레이리스트 출처 필터를 적용한다.
- 가져오기 전용 후보 조회·편집 상태도 제거했다. 기존 후보와 검수 데이터는 변경하지 않는다.
- 후속 UI 관련 4개 파일의 테스트 59개, 타입 검사와 아키텍처 검사를 통과했다. 기존 편집기 전용 테스트는 제거하고 통합 검수 목록·공통 검수 대화상자 테스트 및 가져오기→검수 이동을 확인했다. 브라우저 직접 확인은 제어 도구의 로컬 경로 오류로 미검증이다.

### 검수 전용 화면

- 통합 목록에서 여는 검수는 팝업 대신 `view=review&selected=<후보 ID>`로 표시한다. 영상 확인과 곡·가창·방송 정보 편집을 넓은 화면에서 진행하며 모바일에서는 세로로 배치한다.
- 목록 필터와 선택은 유지한다. 열어 본 후보의 입력은 관리 화면이 유지되는 동안 후보별로 보관하고, 목록 복귀·재진입·채널 설정 확인 시 복원한다. 새로고침 후에는 서버에 저장한 검수를 불러온다.
- 저장 실패 시 입력을 유지하고, 저장 성공 시 목록으로 돌아가 일괄 임시 등록을 이어간다. 하단 저장 버튼은 스크롤 중에도 접근할 수 있다. 다른 관리자가 수정한 후보에 대한 버전 검사는 유지한다.
- 직접 주소 진입 시 기존 목록 API의 다음 페이지를 조회해 선택 항목을 찾는다. 조회 오류와 현재 필터에서 찾을 수 없는 항목은 명시적으로 안내한다.
- 관련 3개 테스트 파일의 고유 테스트 53개 통과(최종 검수 컴포넌트·목록 11개 재확인). 타입·전체 린트·아키텍처·빌드 검사 통과. 실제 관리자 브라우저 조작은 제어 도구의 `failed to write kernel assets` 오류로 미검증이다.

### 채널 편집 페이지 후속 정리

- 검수의 채널 설정 팝업을 제거했다. `tab=channels&view=channel-edit&channel=<YouTube 채널 ID>`에서 대상 채널을 바로 편집한다. 목록·필터를 위에 반복하지 않으며 채널 ID는 편집 영역 전체 너비를 사용한다.
- URL에 원래 이력·후보와 돌아갈 화면을 유지한다. 저장 후 같은 채널의 최신 버전을 다시 읽어 승인·수집 설정을 계속 편집할 수 있다. 신규 채널도 등록 후 해당 채널 편집을 이어간다.
- 검수 입력은 왕복 중 마운트된 폼에 유지한다. 이 이동만 미저장 확인에서 제외하며, 다른 페이지 이탈·새로고침 및 저장하지 않은 채널 편집의 보호는 유지한다.
- 관련 고유 테스트 48개 통과: 기존 관리자 동작 42개, 채널 페이지 저장·검수 복귀 1개, 실제 라우터의 미저장 보호 3개, 경로·URL 검증 2개. 타입·린트·아키텍처·빌드 검사 통과. 실제 브라우저 조작은 `failed to write kernel assets` 오류로 미검증이다.
