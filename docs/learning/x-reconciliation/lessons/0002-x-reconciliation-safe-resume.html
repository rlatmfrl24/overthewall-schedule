공식 X 대조가 멈췄을 때

2분 읽기. 아래 세 가지에서 이전 동작과 새 동작을 한 줄씩 비교해 보세요.

동일 작성자의 인용 20건을 처리한 로컬 표본에서 큐 실행 42회 → 33회, 한 번의 실행에서 D1 최대 48회였습니다.

무엇을 고쳤나요?

상황이전현재 로컬기대 효과와 근거
1. 이전 메시지가 늦게 도착 작업을 맡을 수 있는 시간이 끝나 새 실행이 시작돼도, 두 메시지의 회차가 같았습니다. 복구할 때 회차를 올립니다. 예를 들어 새 실행이 2회차라면 뒤늦게 온 1회차 실패 메시지는 건너뜁니다. 새 실행이 계속 진행됩니다. 임대 만료 검증
2. X 응답을 받은 뒤 저장 실패 인용 원문이나 작성자 정보를 저장하다 실패하면, 재시도에서 X에 같은 정보를 다시 요청할 수 있었습니다. 호출 전에 요청 ID를 저장합니다. 재개하면 같은 ID로 정산된 응답을 찾아 로컬 저장을 마칩니다. 신규 호출 예산을 0으로 설정한 로컬 검증에서도 두 종류의 응답을 재사용했습니다. 저장 실패 검증
3. 작성자 정보가 이미 캐시에 있음 이미 저장된 작성자 정보를 붙일 때도 인용을 한 건씩 처리했습니다. 작성자 정보가 캐시에 있는 인용만 두 건씩 적용합니다. 새로 조회해야 하는 인용은 한 건씩 처리합니다. 동일 작성자 표본에서 큐 실행이 9회 줄었습니다. D1은 한 번의 실행에서 50회 이내였습니다. 20건 검증

큐 실행 수는 작업을 시작한 횟수입니다. X 요청 수는 X에 실제로 조회한 횟수입니다. 용어와 단위 빠른 참조

30초 확인

답을 먼저 떠올린 뒤 각 줄을 눌러 확인하세요.

2회차 작업이 진행 중인데 1회차 실패 메시지가 도착했습니다. 무엇을 할까요?

1회차 메시지를 건너뜁니다. 회차가 일치하는 메시지만 현재 작업의 상태를 바꿀 수 있습니다.

인용 응답은 정산됐고 로컬 저장만 실패했습니다. 무엇을 다시 실행할까요?

같은 요청 ID로 정산된 응답을 읽고, 로컬 저장을 다시 실행합니다.

12시간 정기 주기, 진행 중인 구간의 즉시 재개, 저장 글 재조회 방지를 확인했습니다. 과거 보완 글도 4건 모두 로컬에서 찾았습니다. 운영 설정과 배포는 보류 중이며 신규 유료 X 호출은 0회입니다. 과거 보완 검증
